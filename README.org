* clawtilla

Run a *fleet* of [[file:deps/libreclaw/README.org][libreclaw]] agents instead of one.

One libreclaw process is one agent.  clawtilla is the thing above it: a
daemon that owns the fleet, gives each agent its own persona, model,
credentials, integrations and computer, and lets the agents talk to each
other so one of them can divide work among the rest.

Agents are managed the way chats are.  Each has a durable mailbox, so you
can message an agent that is switched off and it picks the message up when
it starts.  Give a chief-of-staff agent an instruction and watch it delegate.

Past a handful of agents it wants a shape, so agents can belong to
*teams*.  A team has a lead who assigns work inside it and members who
talk to anybody and assign to nobody; the chief of staff sits above all
of them and hands work to the leads, choosing a team by reading what each
one says it handles.  Teams are optional -- a fleet that declares none
behaves exactly as it did before there were any.

*Library first.*  Everything lives in =libclawt=; the daemon, the CLI, the
GTK client and the web client are all thin things on top.  An in-process
host -- GNU Emacs, most immediately -- gets the identical daemon by calling
=clawt_daemon_new()= and owning the main loop itself, with no socket and no
second process in the way.

** Status

Complete and working.  The daemon, both agent runtimes, all four computer
backends, mailboxes, rooms, teams, tasks, the orchestration tools, the
plugin system, the integrations, the AI agent designer, the CLI, the GTK
client and the web client are all built and tested.

The two graphical clients are held to the same feature set by ~make
parity~, which compares the parts of the daemon each one reaches *and*
the slash commands each answers, failing when a capability exists in only
one of them.  Two clients drifting
apart is otherwise invisible until somebody reaches for the half that was
not built.

** What an agent gets

| Thing | Options |
|-------+---------|
| Persona | inline system prompt, or =SOUL.org= / =IDENTITY.org= / … identity files |
| Model | any provider libreclaw supports, with effort, routing profile and fallbacks |
| Runtime | a supervised =libreclaw= process (default), or embedded in the daemon |
| Computer | =none=, =host=, =container= (podman), =distrobox= (a container wired into your session), or =vm= (libvirt or plain QEMU) |
| Desktop | optional gowl or GNOME control, alongside any computer type |
| Mounts | host paths shared into the container or VM, plus a shared exchange directory |
| Mailbox | durable queue with priority, TTL, leases, retry and a dead-letter view |
| Integrations | matrix, email, webhook, local, cmacs, mcp, notify, connector |
| Credentials | per-agent, by reference -- never literal secrets in the config |
| Team | optional, with a role: a lead assigns inside it, a member assigns to nobody |
| Tools | per-agent allow/deny over the orchestration tools |
| Spending | per-agent and fleet cost, from the figure each provider reported |

** Quick start

#+begin_src bash
git clone --recurse-submodules <url> clawtilla
cd clawtilla
make
#+end_src

#+begin_src bash
./build/release/clawtilla --generate-config > ~/.clawtilla/config.yaml
./build/release/clawtillad --foreground
#+end_src

Then, in another terminal:

#+begin_src bash
clawtilla agent create --id researcher --model sonnet --computer container
clawtilla chat researcher
#+end_src

=create= starts what it made, because an agent's computer is built at its
first start and one created and left alone is a configuration file and no
machine.  =--no-start= declines.

See [[file:docs/getting-started.org][docs/getting-started.org]] for the longer version, including the Fedora
packages to layer in.

** Giving an agent your actual computer

An agent's computer can be the machine clawtilla is running on.  This is the
most useful and the most dangerous option, so it is deliberately awkward to
enable by accident:

#+begin_src yaml
computer:
  type: host
  host:
    confine: bwrap                  # none | workspace | allowlist | bwrap
    allow_paths: ["~/src"]
    deny_paths:  ["~/.ssh", "~/.gnupg"]
    allow_sudo: false
    confirm_host_control: true      # required; the daemon refuses without it
#+end_src

=confine: none= additionally requires =daemon.allow_unconfined_host=, so
handing over the whole machine takes two deliberate acts rather than one
typo.  What each mode actually prevents -- and what none of them prevent --
is spelled out in [[file:docs/security.org][docs/security.org]].

** Clients

- =clawtilla= -- the CLI.  Agents, rooms, mailboxes, tasks, computers, config.
- =clawtillad= -- the daemon.  Everything above is a client of this.
- =clawtilla-gtk= -- a full GTK4 + libadwaita client.
- =clawtilla-web= -- the same client over HTTP, built with htmx-glib.
  Listens on the loopback and this machine's tailnet address, so a laptop
  reaches the fleet without a tunnel set up by hand.

** Building

#+begin_src bash
make                  # release, to build/release/
make DEBUG=1          # debug, to build/debug/
make test             # hermetic suite: no network, no podman, no libvirt
make test-integration # the rest
make clean            # this build type only, leaving the deps built
make clean-all        # the deps too, so the next build starts from nothing
make help             # every target
#+end_src

~make clean~ stays inside clawtilla, because the dependency tree below
it takes minutes to rebuild and almost never needs to be.  ~make
clean-all~ is the one that reaches all fifteen vendored projects --
libreclaw brings five, podomation brings six of its own, ai-glib brings
one -- in *both* build types, and it finds them by walking the tree
rather than from a list, because the list it replaced named the first
level only and left nine dep build trees standing.

Zero warnings is a rule, not an aspiration.  See [[file:CLAUDE.md][CLAUDE.md]] for the full
build environment and the rules that are not optional.
