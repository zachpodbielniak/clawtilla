* Development

** Building

#+begin_src bash
make                    # build/release
make DEBUG=1            # build/debug, -O0 -g3
make clean all
make tests              # build every test binary and stop
make test               # build them and run them
make test-verbose
make test-integration   # needs real podman / libvirt / gowl
make config-files       # regenerate data/*.yaml and the docs table
make docs-check         # undocumented public API, stale doc references
make parity             # the two graphical clients cover the same daemon
make help               # every target, with a line each
#+end_src

~make tests~ builds the suite without running it, which is what the
zero-warnings check wants: ~make clean tests~ compiles every test binary
and says nothing else.  It is worth knowing that this target did not
exist for a long time -- make answered *"Nothing to be done for
'tests'"* and exited 0, so a documented check for warnings compiled
nothing and passed.  Run a build command from the docs and read what it
built, not what it exited with.

~make help~ is the full list.  Everything below is the part of it that
needs more than a line: ~install~, ~uninstall~, ~clean~, ~clean-deps~,
~clean-all~, ~distclean~, ~version~ and the per-artefact targets
(~shared~, ~static~, ~daemon~, ~cli~, ~gtk~, ~web~, ~mcp-server~,
~plugins~, ~pod-modules~, ~gir~) do what their names say.

~make parity~ compares ~clawtilla-gtk~ and ~clawtilla-web~ across *five*
layers, not one: the IPC frame kinds each sends, the slash commands each
answers, the choice enumerations each walks (a ~_count()~/~_nth()~ pair
in the public API is the library saying "here is a set"), values a client
spells out that the library already enumerates, and declared affordances
-- capabilities that are pure interface and touch no shared symbol at
all.  Adding a capability to one client and not the other is a build
failure, because two clients drifting apart is otherwise invisible until
somebody reaches for the half that was not built.

The layer count is the lesson rather than a detail.  The check was
frame-kinds only and reported OK while thirteen slash commands were
missing; it grew a command layer and reported OK through two more gaps, a
palette selectable in one client and an unread marker built for one
transcript, because neither sends a frame or answers a command.  *A check
finds the layer it looks at.*  The fifth layer needs declaring by hand
and says so -- better to have it and state the limit than to pretend the
check is complete.

Deliberate asymmetries live in an exception map in
~tools/clawt-client-parity.sh~ with a reason each.  An entry there is a
decision, not a to-do.

~make docs-check~ runs parity too, and ~tests/test-web-render.c~ invokes
the script from ~make test~ -- skipping when it is absent.

The web client's routing needs a running client to check, because unit
tests cannot see it -- a route registered after ~/a/:id/:view~ is
unreachable, and an unrecognised view falls back to chat, so a swallowed
route renders the chat page and answers 200:

#+begin_src bash
make web-smoke WEB_SMOKE_URL=http://127.0.0.1:8790 WEB_SMOKE_AGENT=chief
#+end_src

Both build types coexist.  ~DEBUG=1~ tests link against debug binaries,
so ~make DEBUG=1 test~ exercises what you just built rather than a stale
release tree.

Sanitisers:

#+begin_src bash
make DEBUG=1 ASAN=1 clean all && make DEBUG=1 ASAN=1 test
make DEBUG=1 UBSAN=1 clean all && make DEBUG=1 UBSAN=1 test
#+end_src

GIR is auto-disabled under a sanitiser: ~g-ir-scanner~ runs a dump binary
linked against the library, and with a sanitizer compiled in but its
runtime not preloaded that binary aborts, failing the whole build at the
~.gir~ step.  ~GIR=1~ forces it anyway, and forcing it does more than
override the switch -- ~config.mk~ then sets ~LD_PRELOAD~ to the ASan
runtime and turns leak detection off for the scanner, so the dump binary
survives rather than being asked to.  The skip is announced, not silent.

The sanitiser targets are also the reason the ~deps~ target pins three
knobs and not one.  make passes a command-line variable down to every
sub-make, so ~make DEBUG=1 ASAN=1~ once built *libreclaw's release tree*
with ASan linked in -- which is the one tree ~LIBRECLAW_OUTDIR~ points at
unconditionally.  The next ordinary ~make~ then failed inside libreclaw's
own GIR scanner with "ASan runtime does not come first in initial library
list": a message naming no sanitiser, no previous build and no dep, on a
target several layers from anything the person had changed.  ~deps~ now
pins ~DEBUG=0 ASAN=0 UBSAN=0~.  Pinning one of three reads as "we pin the
build type" and is not.

** The three-file build system

Same shape as libreclaw, deliberately.

| File | What is in it |
|------+---------------|
| ~config.mk~ | versions, paths, ~PKG_DEPS~, dep blocks, build-type selection |
| ~rules.mk~ | pattern rules, the test rule, clean targets, ~help~, the ~.d~ include |
| ~Makefile~ | source lists, phases, every client and test target, install |

Some details worth knowing:

- object directories are created by *one* stamp target.  Concurrent
  per-object ~mkdir -p~ under ~make -j~ races on shared parents and
  intermittently fails with "can't create …o: No such file or directory".
  The stamp depends on ~Makefile~ and ~config.mk~ so a new source
  subdirectory re-runs it.
- test binaries depend on ~libclawt-1.0.a~ and ~liblc-1.0.a~, not just
  link against them.  Without that, a fix in a dep rebuilt its archive
  but never relinked the tests, and the suite kept exercising the old
  code -- which looks exactly like the fix not working.

  The other five bundled archives -- ai-glib, yaml-glib, podomation,
  mcp-glib, htmx-glib -- are link *arguments* and not prerequisites, so
  that failure is still reachable for a fix landed in one of them.  A
  libreclaw sub-make usually touches ~liblc-1.0.a~ as well, which masks
  it; do not rely on that when checking a dep fix by hand.
- every object and every test binary is compiled with ~-MMD -MP~, and
  the resulting ~.d~ files are included at the bottom of ~rules.mk~.
  That is what makes editing a *header* rebuild the things that include
  it.  Without it make saw no changed source and did nothing, so
  ~make test~ after changing a declaration compiled nothing and passed
  --- indistinguishable from a change that worked.

  Worse than a stale binary in one target, because it reaches every
  source in the tree and it silently defeats the habit below of proving
  a test fails without its fix: the sabotage never reaches the binary,
  so the "proof" is a pass.  That is exactly how it was found.
- a test that ~#include~s a *source* file needs that source naming as a
  prerequisite, by hand.  The generic test rule lists only the test's own
  ~.c~, so editing ~clients/web/web-ui.c~ left ~test-web-render~
  untouched and passing.  The Makefile names the five included files
  after ~include rules.mk~, because the specific prerequisite has to come
  after the pattern rule exists.

  This one cost a double false pass: reverting the fix to prove the test
  caught it produced a pass, twice, because the binary was never rebuilt.
  Anything in ~clients/~ that a test reaches into needs the same
  treatment.

*** make test does not relink the daemon

~test~, ~tests~, ~test-verbose~ and ~test-integration~ all depend on the
test binaries, the bundled plugins and the test plugins -- and on nothing
in ~build/<type>/clawtillad~.  So a change can be built, tested and
passing while the daemon binary is the previous one, and checking a fix
by hand against a running daemon then checks the old code.

Run plain ~make~ before restarting the daemon.  Two rounds of "the fix
did not work" came from this, with the library provably correct from a
standalone probe and the running daemon minutes old.

** Code style

- C, ~gnu89~, GCC
- symbol prefix ~clawt_~ / ~Clawt~ / ~CLAWT_~
- ~/* */~ comments only
- four-space indentation, tabs in Makefiles
- ~UPPERCASE_SNAKE~ for macros, ~PascalCase~ for types,
  ~lowercase_snake~ for everything else; never ~camelCase~
- SPDX ~AGPL-3.0-or-later~ on every file
- GObject Introspection annotations on every public symbol

*** Zero warnings

Builds are warning-free on every target.  Fix warnings in the code, never
by lowering GCC's verbosity.  A warning is a latent bug.

*** Comments explain why

The code says what it does.  A comment that repeats it earns nothing.
Comment the decision: why this order, why this bound, what breaks if it
changes.  Several of the comments in this codebase are there because the
alternative was tried and produced a bug.

** GObject conventions

- ~G_DECLARE_FINAL_TYPE~ unless it is genuinely meant to be subclassed
- ~G_DECLARE_DERIVABLE_TYPE~ with a padded vtable for extension points
- ~G_DEFINE_BOXED_TYPE~ + ~G_DEFINE_AUTOPTR_CLEANUP_FUNC~ for value types
- ~G_DECLARE_INTERFACE~ for capabilities plugins implement
- ~g_autoptr~ / ~g_autofree~ everywhere; ~g_steal_pointer~ on return

*** Enum registration is longhand

Eighteen enums, each written out.  A macro looks tidier and does not
work: braces do not protect commas in the C preprocessor, so the value
table arrives as fourteen separate arguments.

*** Main contexts

~g_timeout_add_seconds()~ and ~g_idle_add()~ attach to the *default*
context, not the thread-default one.  In an embedded daemon -- one whose
host runs its own loop on its own context -- that means the source never
runs at all.  Use ~clawt_timeout_add_seconds()~, which exists for exactly
this and returns the source so it can be destroyed to cancel; for an idle
or a one-shot, the longhand:

#+begin_src c
GSource *source = g_idle_source_new();

g_source_set_callback(source, on_ready, self, NULL);
g_source_attach(source, context);
g_source_unref(source);
#+end_src

Three real bugs came from getting this wrong: two timers that silently
never fired for an embedded daemon -- a keepalive and a restart policy --
and an idle that never delivered a single event to an embedded client.

It is not only the source constructors.  ~g_task_new()~ captures
~g_main_context_ref_thread_default()~, and *dispatching a source does not
make its context thread-default* -- GLib pushes nothing on the way in.
So a ~GTask~ created inside a callback takes the process default and
completes on a loop the daemon may never run.  Push the context around
the ~g_task_new()~ call.

And anything that *waits* has to wait on the context the answer will
arrive on rather than on whatever is thread-default where the wait
happens.  ~ClawtProcessRuntime~ holds the context its child's exit will
be delivered to, because it once asked for the ambient one in ~stop()~
while ~g_subprocess_wait_async()~ had captured a different one at start:
every clean shutdown then waited out the full grace period and SIGKILLed
a child that had already gone.

The general rule, and it will keep coming up: *anything that captures
"the current context" is a bug in an embedded daemon unless it was told
which one.*

** Adding a configuration option

1. Add an entry to the table in ~src/config/clawt-config-schema.c~: key,
   type, flags, default, enum type, documentation, ~Since:~.
2. If it carries ~PER_AGENT~, add its agent-relative spelling to
   ~clawt_config_schema_agent_keys()~ in the same file.
3. ~make config-files~.
4. Read it with ~clawt_config_get_*()~ or ~clawt_agent_config_get_*()~.
5. Mention it wherever in ~docs/~ it belongs.

Step 2 is the one that gets skipped.  What an agent calls a fleet option
is not derivable -- ~orchestration.mailbox.max_depth~ becomes
~mailbox.max_depth~ inside an agent block while ~memories.enabled~ keeps
its whole name -- and that relationship used to live in two private
tables, which is how nine settings came to work when typed into the file
and be unreachable from every client.  It is schema, because it says
where an option may be written, so it belongs beside the schema.
~tests/test-config-schema.c~ fails on a ~PER_AGENT~ key with no entry.

Put a new top-level *section* after every key belonging to the one before
it.  ~clawt-genconfig~ walks the table in order and opens a YAML section
when it meets one, so a section inserted in the middle of another's keys
emits the rest of them under the new heading and then reopens the old --
a duplicate top-level key, which YAML resolves by silently discarding the
first.

Do not hand-edit ~data/*.yaml~ or ~docs/configuration-options.org~.
~tests/test-config-schema.c~ fails when they have drifted, which is what
makes this rule enforceable rather than merely written down.

** Adding an IPC frame kind

The daemon's client surface is one file per verb family in ~src/core/~:
~daemon-agent.c~ answers ~agent.*~ and ~memory.*~, ~daemon-computer.c~
answers ~computer.*~, and so on, with ~daemon-misc.c~ for the handful
that belong to no family of their own.  A new verb goes in the file for
its family; a new *family* is a new ~daemon-<name>.c~, an entry in
~LIB_SOURCES~, a prototype in ~src/core/clawt-daemon-private.h~ and a
line in ~family_handlers[]~ in ~src/core/clawt-daemon.c~.

Each family exports one function:

#+begin_src c
JsonNode *
clawt_daemon_handle_agent(
    ClawtDaemon  *self,
    const gchar  *kind,
    JsonNode     *request,
    JsonObject   *payload,
    gboolean     *handled
);
#+end_src

~handled~ is separate from the return value on purpose.  A handler that
defers -- ~clawt_ipc_server_defer()~ then ~clawt_ipc_pending_respond()~
when the work finishes -- returns ~NULL~ *now*, and eleven of them do.
Reading that ~NULL~ as "not mine" would hand the frame to the next family
and then to the unknown-kind error, so the client would be answered
twice: once with an error and once with the real reply.  Set ~*handled~
before returning anything, including ~NULL~.

This was a single chain of about a hundred ~if (g_strcmp0(kind, ...))~
blocks inside ~clawt_daemon_handle_request()~.  Splitting it is why two
branches adding two verbs no longer conflict.

Then: document the kind in [[file:ipc-protocol.org][ipc-protocol.org]] -- ~make docs-check~ fails on
one that is handled and absent -- and reach it from *both* graphical
clients, or add it to the exception map in
~tools/clawt-client-parity.sh~ with a reason.  Both checks read the
family files by glob, so a kind is compared from the moment it exists.

** Adding a connector to the catalogue

Two ways, and the second is usually right.

For something only you use, a file in ~connectors.dir~ needs no rebuild
and survives upgrades -- see [[file:connectors.org][connectors.org]].  These are somebody
else's endpoints, and a copy of them in C goes stale silently.

For something worth shipping, add a row to the table in
~src/integration/clawt-connector.c~.  A row must carry a
~credential_name~ (nothing else says what to call it) and, if it uses
OAuth, both endpoints.  It must *not* carry a client id: clawtilla has no
application of its own to lend, and borrowing another project's would
mean every clawtilla identifying itself as something it is not.  Put
where to register one in ~client_id_help~ instead.

Set ~default_instance~ only for a service people self-host.  It changes
how every URL in the row is read -- absolute without it, a path joined
onto the configured instance with it -- so a row that mixes the two
authenticates against the wrong server.

** Adding a distribution for guest desktops

~src/computer/clawt-guest-desktop.c~ holds one ~FlavourSpec~ per family.
A new one needs a ~ClawtGuestFlavour~ member, a row in the table, a
~flavour~ on whichever ~ClawtVmImageSource~ entries belong to it, and a
marker in ~flavour_markers~ so an image somebody downloaded is placed by
its filename.

Choose that marker carefully.  It is matched anywhere in the path, so a
short one that is a common English fragment will place unrelated images:
matching Arch on ~arch~ would claim ~~/archived-vms/debian.qcow2~ and
~/home/me/research/disk.qcow2~.  ~arch-linux~ and ~archlinux~ are the
markers for that reason, and there is a test naming both of those paths.

What a row has to get right is more than package names: the display
manager's unit, whether PyGObject is ~python3-gobject~ or ~python3-gi~ or
~python-gobject~, and whether ~glib-compile-schemas~, ~python -m venv~
and the ~dconf~ binary are present at all.  Every one of those fails
*inside the guest*, in a cloud-init log, long after the config line that
caused it -- so assert the rendered seed rather than trusting the table
to read correctly.

** Adding a test

~tests/test-*.c~, picked up by wildcard.  GTest.

#+begin_src c
g_test_add_func("/subsystem/what-it-checks", test_function);
#+end_src

Available at build time, all absolute, so nothing has to guess at the
cwd:

| Define | What it names |
|--------+---------------|
| ~CLAWT_TEST_SRCDIR~ | the repo root |
| ~CLAWT_TEST_FIXTURES~ | ~tests/fixtures~ |
| ~BUILD_OUTDIR~ | the build tree matching this test's own build type |
| ~CLAWT_TEST_POD_MODULE_DIR~ | libreclaw's built podomation modules |

The last one comes with an obligation: a test that needs a real pod
module must *skip* when the directory is absent rather than carry on.
Without it the container backend refuses before it opens a socket, so
start is fast for a reason unrelated to whatever is being tested -- which
is precisely what the first draft of the mute-socket test did.  It passed
against a deliberately broken daemon.

*** Raise the floor

~tools/clawt-test-floor.sh~ fails the suite when suspiciously few test
binaries ran, because a green run that built almost nothing still looks
green.  ~TEST_FLOOR~ is a number in that script and adding a test file is
the moment to raise it.  It is run from ~make test~ only.

*** Clean up with ~clawt_test_remove_tree()~, never ~g_rmdir()~

A fixture that made a temporary directory has to remove the *tree*.
~g_rmdir()~ does nothing at all to a directory that is not empty, and
~g_unlink()~ on the file a test wrote leaves the directory above it ---
so a fixture that ends with either looks tidy and is not.  Three did:
~test-attachment~ freed the path in its teardown without touching the
directory, and ~test-appearance~ and ~test-connection~ each unlinked a
file two levels down.  2710 directories had built up in ~/tmp~ over six
days before anybody counted them, and every one of those runs was green.

~clawt_test_remove_tree()~ in ~tests/clawt-test-util.h~ is the one
spelling.  A directory that belongs to the whole binary --- an
~XDG_CONFIG_HOME~ set before ~g_test_init()~ --- is removed after
~g_test_run()~ returns, not by any one test, because nothing before that
may take it away.

~tools/clawt-test-litter.sh~ enforces this: ~make test~ lists the
temporary directories before the run and again after, and a *green* run
that added any fails, naming each one.  It compares the same run against
itself rather than asking whether the temporary directory is empty,
because a previous *failing* run leaves its directories behind on
purpose --- they are the evidence, and GTest aborts on a failed
assertion, so no teardown of any kind runs on that path.  That is also
why moving cleanup into a ~g_test_add()~ teardown fixes nothing: the
teardown does not run either.

What the check cannot see: a fixture whose ~g_dir_make_tmp()~ template is
not a string literal in ~tests/test-*.c~.  The prefixes are read from
those literals, so the check grows with the suite instead of being a
hand-written list that drifts --- but a template built at runtime is
invisible to it.

*** Tests stay hermetic

No network, no podman, no libvirt, no gowl.  Anything needing real
infrastructure goes behind ~CLAWT_TEST_INTEGRATION=1~ and
~make test-integration~.

A fixture also has to keep three things inside its temporary directory,
and the third is the one that gets forgotten: the socket, the state
directory, and ~defaults.workspace_root~ -- which defaults to
~~/.clawtilla/agents~, so a test that creates an agent scaffolds it into
the developer's real fleet on every ~make test~.  That went unnoticed for
a long time, because the leftovers are indistinguishable afterwards from
agents somebody meant to keep.

*** Prove the test fails without its fix

Reverting the change and watching the test go red is the only thing that
tells you the test is testing the fix.  Two traps make that proof
worthless without saying so:

- hiding the build behind ~>/dev/null 2>&1~.  If the sabotage did not
  compile, the old binary runs and the "proof" is a pass.  Read the build
  output, or at minimum grep it for ~error~ -- and note that a filter
  matching ~file:line:col: error~ misses *linker* errors entirely.
- ~git checkout <file>~ to undo the sabotage.  During a change the file
  has uncommitted work in it, and that throws the work away.  Copy the
  file aside and copy it back.

*** GTest makes g_warning fatal

When a warning is the *correct* behaviour, expect it rather than
weakening it:

#+begin_src c
g_test_expect_message("Clawtilla", G_LOG_LEVEL_WARNING, "*unknown *");
/* … */
g_test_assert_expected_messages();
#+end_src

*** Test names say what is being asserted

~/mailbox/lease-expiry-returns-to-pending~ tells you what broke from the
failure line alone.  ~/mailbox/test3~ does not.

** Debugging

#+begin_src bash
G_MESSAGES_DEBUG=Clawtilla ./build/debug/clawtillad --foreground
gdb --args ./build/debug/clawtillad --foreground -c /tmp/config.yaml
G_DEBUG=fatal-warnings gdb --args ./build/debug/tests/test-mailbox
#+end_src

For a leak or an overflow, ASAN first:

#+begin_src bash
make DEBUG=1 ASAN=1 clean all
ASAN_OPTIONS=detect_leaks=1 ./build/debug/tests/test-daemon
#+end_src

** Upgrading libreclaw

#+begin_src bash
git -C deps/libreclaw pull --ff-only
make clean all && make test
git add deps/libreclaw && git commit
#+end_src

~make check-submodules~ is a prerequisite of ~all~, so it runs on every
build rather than when somebody remembers it.  It *errors* when
~deps/libreclaw~ is not checked out at all, naming the ~git submodule
update~ to run; it *warns* when the checkout is behind the recorded
gitlink -- the failure that prevents is building against one version and
shipping a gitlink to another.  Being ahead is silent, because that is
what upgrading looks like from inside.

** Commits

Conventional Commits.  ~feat~, ~fix~, ~docs~, ~refactor~, ~perf~,
~test~, ~chore~, ~ci~, ~build~; ~!~ after the type for a breaking change.

Docs ship in the same commit as the code they describe.  A doc written
"later" is a doc written never.
