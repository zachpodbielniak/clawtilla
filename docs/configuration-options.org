** =daemon=

The daemon itself: where it listens, where it keeps state, how loud it is.

clawtillad owns every agent process, every credential and every socket.
Clients hold no transports of their own -- they send typed commands and
fold one event stream. That is what lets the CLI, the GTK app, the web
client and an in-process cmacs embed all be the same program.

*** =daemon.socket=

- Type :: path
- Default :: =$XDG_RUNTIME_DIR/clawtilla/daemon.sock=
- Since :: 0.1.0

Unix socket the clients connect to.

Created with mode 0600 inside a 0700 directory, which is the whole of
the access control: the daemon does not check the peer's uid, so
anything that can open the file is trusted completely.

A unix socket is used rather than a loopback HTTP port because the
filesystem can express that at all, and because any web page the user
visits can reach a loopback port through DNS rebinding.

*** =daemon.git=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Make the state directory a git repository on first start.

The workspaces, the org files and this configuration are worth having
a history of. What makes this safe rather than alarming is the
.gitignore written beside it: the same directory holds credentials,
link tokens, mailboxes and memory databases, and the moment to keep
those out of a history is before there is anything in it.

clawtilla never commits. It creates the repository and the ignore
rules; what goes into a commit stays your decision.

Turning this off stops the repository being created. The ignore file
is still written, because a state directory somebody put in git by
hand needs it more, not less.

*** =daemon.state_dir=

- Type :: path
- Default :: =~/.clawtilla=
- Since :: 0.1.0

Where agent workspaces, mailboxes, transcripts and credentials live.

Created 0700. Never mounted into any agent's computer, whatever the
mount configuration says -- an agent that could read this directory
could read every other agent's credentials.

*** =daemon.pod_module_dir=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Where podomation's loadable modules are, if they are not found for you.

The container and vm computers do their work through podomation's
'container' and 'vm_virtmanager' modules, which libreclaw builds. They
are looked for next to the running binary and then in the install
location, so a normal build and a normal install both work without
setting this.

Set it when the modules live somewhere else -- a system podomation, or
a build tree you are testing against. Naming a directory here means
that directory and no other, so a wrong path fails loudly instead of
being papered over by a stale set found elsewhere.

*** =daemon.log_level=

- Type :: enum
- Values :: error, warning, info, debug
- Default :: =info=
- Since :: 0.1.0

How much the daemon says: error, warning, info, debug.

Everything at or above the level reaches the log and nothing below.
GLib already drops debug messages unless G_MESSAGES_DEBUG names the
domain, so debug is what turns clawtilla's own on; warning and error
are what quieten a daemon that is working.

Read by clawtillad only. A host embedding ClawtDaemon owns its own
logging, for the same reason it owns its own signal handling.

It said `debug logs every frame on every link` until 0.2.0, and did
not: nothing read this key at all, and there is no per-frame logging
to enable. Turning it up changed nothing and warned about nothing,
because it is not flagged inert either.

*** =daemon.tcp_enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Also listen on TCP, so clients on other machines can connect.

Off by default. The unix socket is authenticated by the kernel; a TCP
listener is authenticated by whatever you configure below, so turning
this on without TLS and a token puts the whole fleet on the network.

*** =daemon.tailscale=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Also listen on this machine's tailnet address, when there is one.

On by default, and the one network where that is defensible: a peer on
a tailnet is a device you enrolled and WireGuard authenticated, and
nothing outside it can route to a 100.64/10 address at all. It is what
lets the client on a laptop reach the fleet on a workstation with no
tunnel set up by hand.

A token is still required, and generated into <state_dir>/tcp-token if
token_file names nothing -- so the listener is never open, only
reachable. Print it with `clawtilla daemon token`.

Nothing happens when Tailscale is absent, down, or in
userspace-networking mode, since there is then no address to bind.

*** =daemon.token_file=

- Type :: path
- Default :: unset
- Since :: 0.1.0

File holding the bearer token remote clients must present.

Ignored for unix socket connections, which the kernel already vouches

cannot leave the daemon open by omission.

*** =daemon.device_idle_days=

- Type :: integer
- Default :: =90=
- Since :: 0.15.0

Days a paired device may go unseen before its token stops working.
0 means never.

A device is seen when it connects and, once a minute, for as long as
it stays connected -- so a laptop left open on the fleet never lapses
while somebody is looking at it. An expired device is removed exactly
as `clawtilla device revoke` would remove it, live connections and
all; pair it again with a fresh code. The daemon's own token
(token_file) is the owner credential and never expires.

*** =daemon.event_log_days=

- Type :: integer
- Default :: =30=
- Since :: 0.1.0

How many days of per-room event logs to keep. 0 disables the sweep.

The event log is the file you paste into a bug report. Secrets are
scrubbed as it is written, not as it is displayed -- a transcript gets
replayed into every context rebuild, so a leaked key in one would be
permanent.

*** =daemon.allow_unconfined_host=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.1.0

Permit agents to use computer.host.confine: none.

An unconfined host computer means the agent runs commands as you, with
your files, your keys and your network. That needs to be two deliberate
acts rather than one typo, so it requires this AND confirm_host_control
on the agent itself.

*** =daemon.automation_dir=

- Type :: path
- Default :: =~/.clawtilla/pods=
- Since :: 0.2.0

Where podomation pods that watch the fleet live.

Every `*.pod` in here is loaded at start. clawtilla registers itself
into podomation as a module, so a pod can bind to what the fleet does
and act on it in the same file:

  pod researcher = clawtilla->new("researcher");

  researcher->on_agent_state where event->state == "error" =>
      clawtilla->restart_agent(agent: "researcher");

  researcher->on_agent_state where event->state == "error" =>
      clawtilla->notify(title: "researcher fell over; restarted it");

An event name cannot carry a dot -- podomation's lexer stops at it --
so it is on_agent_state rather than agent.state.

The constructor's arguments are the scope, and it applies both ways:
a pod named for one agent neither hears about the others nor can act
on them. With no arguments, the whole fleet.

A file that does not parse disables that file and warns; the rest are
loaded.

*** =daemon.webhook_enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether to accept inbound trigger deliveries.

Off by default. A fleet nothing calls into needs no listener, and a
port opened because a feature exists rather than because somebody
asked for it is a port nobody is watching.

The receiver is its own server on its own port and serves only
/health and the secret /hooks/... paths -- never the IPC surface --
so putting it behind a tunnel exposes nothing else.

*** =daemon.webhook_port=

- Type :: integer
- Default :: =8788=
- Since :: 0.2.0

Port the trigger receiver listens on.

It binds loopback and the tailnet address when there is one, and
loopback alone when there is not -- the same rule the web client
follows, and for the same reason: a listener is never widened
because an address was missing.

*** =daemon.update_check=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether to ask, on a timer, if a newer clawtilla exists.

Off by default, because it is the only thing in the daemon that
reaches the network without somebody asking it to.

It checks and reports; it does not install anything. An unattended
update must not restart the daemon under running turns, so applying
one waits on a hold that can drain first.

The result reaches every client through control.status, including
when the check itself failed -- a check that has been quietly
erroring for a month is worse than none, because nothing to draw
reads as up to date.

*** =daemon.update_url=

- Type :: string
- Default :: =https://gitlab.com/api/v4/projects/zachpodbielniak%2Fclawtilla/releases=
- Since :: 0.2.0

Where daemon.update_check asks.

Three answer shapes are understood, because three are real and none
of them is ours: a bare version as text or as a JSON string, an
object carrying version, tag_name or name, and an array of those --
which is what Forgejo, Gitea and GitLab all return from a releases
endpoint. Point it at a self-hosted forge or a file you publish;
nothing here is tied to a particular host.

*** =daemon.update_interval_hours=

- Type :: integer
- Default :: =24=
- Since :: 0.2.0

How often to ask, in hours. Clamped to at least one.

Nothing is asked at daemon start: the first check happens one
interval in. Starting a daemon must not reach the network, or every
test fixture that builds one does too.

** =defaults.mounts=

Host paths shared into *every* agent's computer.

  defaults:
    mounts:
      - source: "~/source"
        target: "/work/source"
        mode: rw

The directory you want every agent to see -- your projects tree,
your notes -- written once instead of copied into every agent block
and then forgotten on the next agent you create.

Applied to container, distrobox and VM agents. Not to host agents:
there a mount is the confinement allowlist rather than a kernel
mount, and quietly widening what a host agent may reach is not
something a convenience should do.

An agent's own computer.mounts wins on a matching target, so one
agent can point the same path somewhere else without turning the
default off. agents.computer.default_mounts: false declines them all.

bind, volume, virtiofs, 9p or tmpfs. Chosen from the backend when

*** =defaults.mounts.relabel=

- Since :: 0.1.0

SELinux relabelling: none, shared (:z) or private (:Z).

*** =defaults.mounts.scope=

- Type :: enum
- Values :: none, selected, all
- Default :: =all=
- Since :: 0.1.0

Who gets this folder: all, selected or none.

`all` includes agents created later, which is the point of a default.
`selected` uses the `agents:` and `teams:` lists below. `none` keeps
the entry without giving it to anybody, which is how you park one
without losing what it said.

Naming agents or teams without saying `scope` means `selected` --
writing a list and having it ignored would be a rule that reads
correctly and does the opposite.

A scope that is written and cannot be read reaches nobody, the same
way an unrecognised integration scope does: handing somebody's home
directory to the whole fleet by typo is far worse than handing it to
nothing and saying so.

An id that names no agent is ignored rather than refused: an agent

*** =defaults.mounts.teams=

*** =defaults.stream_steps=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether agents report what they are doing while a turn runs.

With this on, the tools an agent reaches for and the prose it writes
between them appear in the conversation as they happen, so a turn
that takes ten minutes is something to watch rather than a typing
dot. With it off, a turn shows the indicator and then its answer.

A step is not a message. It is never delivered, never queued, never
written to the transcript and never answered -- so an agent watching
a peer work does not take a turn over it, which is the failure the
old five-minute progress notes had.

Tool arguments are previewed, one line each, with secrets redacted.
Turn it off for a fleet where even a redacted command line should
not reach whoever can open the chat.

*** =defaults.confine=

- Type :: enum
- Values :: none, bwrap
- Default :: =none=
- Since :: 0.14.0

Whether agents' own CLIs run inside a bubblewrap sandbox: none or

The fleet-wide answer for agents.runtime.confine, which an agent may

Set to bwrap, every process-runtime agent that says nothing itself is

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Resolved together with the team's list and the agent's own through

** =defaults.policy=

What agents may do without asking. See agents.policy.

*** =defaults.policy.rules=

- Type :: list of strings
- Default :: unset
- Since :: 0.3.0

Action rules every agent follows unless it has its own list.

Each is MATCH=MODE. MATCH is an action class -- read, write, delete,
message, exec, external, desktop_input, fleet_admin -- or a tool-name
glob such as clawtilla_create_* or Bash. MODE is allow, review, ask,
hand_back or deny. The first rule that matches decides; a call no
rule matches is allowed. An agent's own agents.policy.rules replaces
this list rather than adding to it, so the order of one list is the
whole answer.

*** =defaults.policy.ask_timeout_seconds=

- Type :: integer
- Default :: =600=
- Since :: 0.3.0

How long an `ask` waits for a person before it is refused. The
decision is then settled as defaulted, so the inbox says nobody
chose rather than that somebody said no.

*** =defaults.policy.reviewer=

- Type :: string
- Default :: unset
- Since :: 0.3.0

The decision model `review` asks: typesafe, ollama or laya (ai-glib's
deciders). Unset, `review` behaves as `ask`. A reviewer that is
unsure, or that fails, also becomes `ask` -- never `allow`.

** =secrets=

How secret references in this file are resolved.

There is deliberately no way to write a literal secret here. Credentials
are always a reference:

  api_key: {file: ~/.clawtilla/secrets/anthropic}
  api_key: {env: ANTHROPIC_API_KEY}
  api_key: {command: "pass show clawtilla/anthropic"}

Resolved values are written to per-agent credential files at mode 0600
and injected into that agent's environment. They never appear in an IPC
response, a log line or a transcript.

** =egress=

Where an agent with runtime.network: gated may connect.

A gated agent's sandbox has no network of its own. Its one way out is
clawtilla's egress gate, an HTTP proxy in the daemon that resolves
names itself and connects only to public addresses: never this
machine, the LAN (RFC 1918), link-local, CGNAT and tailnets
(100.64.0.0/10), IPv6 unique-local, multicast or a cloud metadata
service. It judges the address, after resolution, so a public name
pointed at 127.0.0.1 is refused too.

*** =egress.allow=

- Type :: list of strings
- Default :: unset
- Since :: 0.17.0

Private addresses gated agents may reach anyway.

Each entry is an address (100.101.102.103), a network
(192.168.1.0/24, fd7a:115c:a1e0::/48) or a host name
(nas.example.ts.net), optionally with a port (10.0.0.5:8080,
[fd00::1]:443). A name matches the name the agent asked for and never
opens loopback; loopback needs an address. Cloud metadata, multicast,
the unspecified address and reserved space cannot be opened, and an
entry naming one is refused. One bad entry refuses the whole list, at
load and where it is added.

** =orchestration=

How agents talk to each other, and what stops them doing it forever.

Bot-to-bot messaging is the point of clawtilla and also the thing most
able to run away: two agents that each reply politely will do so until
something stops them. Every limit here is that something.

*** =orchestration.max_hops=

- Type :: integer
- Default :: =8=
- Since :: 0.1.0

How far a message may travel agent-to-agent before it is refused.

Every message carries the depth it was sent at. A chief-of-staff
delegating to a worker that asks a specialist is three hops; anything
much beyond that is usually a loop rather than a plan.

*** =orchestration.rate_limit_per_minute=

*** =orchestration.cycle_window=

- Type :: integer
- Default :: =10=
- Since :: 0.1.0

How many recent messages per room are remembered for loop detection.

A message repeating one already in the window is refused. This catches

This bounds the memory. How far back the check looks in time is
orchestration.cycle_seconds.

*** =orchestration.cycle_seconds=

- Type :: integer
- Default :: =300=
- Since :: 0.1.0

How long a repeated message counts as a loop. 0 disables the check.

Without this the cycle window was a count alone, so how far back it
looked was however long the room's last cycle_window messages had
taken -- ten messages in a quiet room is hours. An agent that hit a
spawn failure and reported the same error string every turn had its
first report delivered and every one after it refused, so a wedged
agent was indistinguishable from an idle one for ten hours.

The default suits the runaway this check exists for -- two agents
alternating the same two replies with nothing pacing them, where a
turn is seconds. Raise it for a fleet whose turns are minutes; a
repeat is only caught if it lands inside the window.

*** =orchestration.ack_check_model=

- Type :: string
- Default :: ==
- Since :: 0.17.0

A small model that decides whether an answer only acknowledges, as
provider/model -- claude/claude-haiku-4-5-20251001, ollama/llama3.2.
Empty turns the check off.

An answer to a deliberate message wakes the agent that sent it, and
that turn costs as much for "Thanks, noted." as for a page of
findings. With a model set, an answer is put to it only when the
answering turn made no tool calls (so ran no commands, changed no
files and sent nothing), its steps were streamed so that is known,
the answer is at most 600 characters, and the message it answers was
not a task. The model is asked one question, ACK or NEEDS, with both
texts fenced as data, and has 8 seconds.

Only a plain ACK skips the wake. NEEDS, a failure, a timeout or any
other reply wakes the sender as before. An acknowledged answer is
still recorded in the room, marked "acknowledged (no wake)", and
the sender's next turn opens with a one-line note of it, so nothing
is dropped.

A provider ai-glib reaches over HTTP, with its key configured the way
ai_assist's is. A command-line provider would spend the 8 seconds
starting. A message sent with reply: none never wakes its sender,
with or without this.

*** =orchestration.tree_message_budget=

- Type :: integer
- Default :: =60=
- Since :: 0.20.0

How many requests one task tree may send between settlements.
0 disables the budget.

A tree is a root task and everything delegated from it. max_hops
bounds how deep a chain goes and says nothing about how wide: a chief
that hands work to ten agents, each of which asks two more, is three
hops deep and can still talk all night. This counts the deliberate
messages sent from inside one tree -- clawtilla_message_agent,
clawtilla_ask_agent, clawtilla_delegate, clawtilla_handoff,
clawtilla_post_room and an @mention in a room -- one per call, however
many teammates the call reaches.

Answers are not counted and never refused, and neither is the
follow-up turn a delegator is owed when its work settles. The count
starts again whenever any task in the tree settles, because a
settlement is progress and chatter is not.

At the limit the messaging tools are withheld from that tree's turns,
exactly as max_hops withholds them, and one alert names the tree.

*** =orchestration.pair_message_budget=

- Type :: integer
- Default :: =12=
- Since :: 0.34.0

How many rounds of requests two agents may send each other with no
person in between. 0 disables the budget.

Every other limit here can be started again by the agents
themselves. The hop count begins at zero on a notice of the daemon's
(a task settling, a wait ending), and the tree budget renews when a
task settles -- so two agents trading one job at a time, or asking
each other something after every notice, could do it for as long as
both were willing and nothing was ever refused. This is the count
nothing an agent does renews.

A round is every request one agent sends the other from one turn --
clawtilla_message_agent, clawtilla_ask_agent, clawtilla_delegate, a
handoff -- so a chief handing a worker ten jobs at once has used one
round, and a pair passing one job back and forth has used a round
each time. Answers are not counted and never refused. Group rooms
are not counted: rounds and rooms.max_chain bound those.

The count starts again when a person, a routine or a trigger writes
to either agent, or when the two have sent each other nothing for
orchestration.pair_quiet_minutes. At the limit a request between
the two is refused, saying so, and one alert names the pair.

*** =orchestration.pair_quiet_minutes=

- Type :: integer
- Default :: =30=
- Since :: 0.34.0

How long two agents must send each other nothing before their pair
budget starts again. 0 means only a person renews it.

A fleet driven from somewhere the daemon does not see -- a Matrix
room, a webhook -- never shows it a person, so without this two
agents that had ever done pair_message_budget rounds of honest work
could not ask each other anything again until somebody opened a
chat. A loop is never quiet, so it does not earn this; once it has
been stopped nothing is left running to start it again.

*** =orchestration.answer_in_request_room=

- Type :: boolean
- Default :: =true=
- Since :: 0.34.0

Hand an agent's answer to the asker in the conversation it asked
from, rather than in the room the two agents share.

An agent that asks a teammate something from your chat, or from a
group, is woken with the answer there: it has the conversation
behind it, what it writes at the end of that turn reaches you as any
reply does, and anything more it wants from the teammate is a tool
call. The answer itself stays on the record in the two agents' own
room, where Flow shows the exchange.

Off, the answer wakes the asker in the two agents' room -- a
separate session that holds none of your conversation -- as it did
before 0.34.0. A request made while answering somewhere the daemon
does not see (a Matrix room) is always answered that way.

*** =orchestration.crosstalk_summary=

- Type :: enum
- Values :: chief, on, off
- Default :: =chief=
- Since :: 0.30.0

Tell you about agent-to-agent conversations: chief, on or off.

When an exchange between agents ends -- a message and its answer, a
delegated task settling, a Grok bot reaching out and being answered,
a group room's round -- a short summary of it is posted into your own
conversation with the agent that took part: who reached out, what
they asked, what the agent did (tool calls by kind, tasks it handed
on, decisions it raised) and how it ended, with a link that opens the
exchange in Flow. Without it, that conversation is only in Flow, and
you have to go and look.

chief, the default: only the chief of staff's conversation with you
gets them. on: every agent's. off: none. Set per agent as
`crosstalk_summary` to turn one agent on or off whatever this says.

The summary is the daemon's note, built from the record and costing
no model call: it is never delivered to the agent, never starts a
turn, invites no reply and counts towards no hop, budget or incident.
An exchange ends when nobody in it has a turn running or a message
waiting there, no task it carries is still running, and it has been
quiet for 15 seconds; exchanges ending within a few seconds of each
other are posted as one note. Work a trigger or routine started is
not cross-talk and is never summarised.

*** =orchestration.crosstalk_summary_to=

- Type :: enum
- Values :: source, chat
- Default :: =source=
- Since :: 0.33.0

Where a cross-talk summary is posted: source or chat.

source, the default: back where the request came from. An agent that
reached out to another agent or a Grok bot while answering somebody in
a Matrix room has the summary posted in that room, from its own Matrix
account, so the person who asked hears how it went. Asked in a
clawtilla room you are in -- a group -- it is recorded there. Anything
else comes to your chat with the agent, as does a Matrix post that
fails (with a line saying why).

chat: always your chat with the agent.

Only the agent whose turn began the exchange posts it at the source;
another agent in it that is told (`crosstalk_summary`) is told in your
chat with it. An exchange picked up again after a daemon restart has
lost where it came from and comes to your chat. Set per agent as
`crosstalk_summary_to`.

*** =orchestration.crosstalk_summary_model=

- Type :: string
- Default :: ==
- Since :: 0.30.0

A small model that rewrites each cross-talk summary as one friendly
paragraph, as provider/model -- the same spelling as
orchestration.ack_check_model. Empty, the default, posts the summary
built from the record and asks no model anything.

The model is given the record-built summary, fenced as data, and 10
seconds. Nothing waits on it: the note is posted when it answers. A
failure, a timeout, an empty reply or one longer than 1200
characters posts the record-built summary instead, so turning this on
can delay a note and never lose one.

** =orchestration.mailbox=

Defaults for every agent's mailbox.

Each agent has a durable queue, so a message to a stopped agent waits

- Type :: integer

- Since :: 0.1.0

How many undelivered items a mailbox holds before overflow applies.

*** =orchestration.mailbox.overflow=

What a full mailbox does: reject, drop-oldest or block-sender.

*** =orchestration.mailbox.max_attempts=

Delivery attempts before an item is dead-lettered rather than retried.

*** =orchestration.chief_of_staff=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Id of the agent that receives work addressed to the fleet.

At most one agent may hold this. Setting it here is equivalent to

*** =orchestration.repeat_thresholds=

- Type :: list of strings
- Default :: =5,10,20=
- Since :: 0.2.0

Repeat counts worth reporting when an agent keeps making the same
call.

A count lands on a threshold exactly once, so the fifth identical
call reports and the sixth does not. Reporting every repeat past a
floor turns a signal into noise, and noise is what gets skipped.

This one observes rather than intervenes. clawtilla does not own the
model's own tool-call loop, so it cannot steer a turn that is already
running: it counts the calls it serves, writes a note into the
thread, and at the highest threshold interrupts the turn.

An empty list turns the counting off.

*** =orchestration.repeat_max_keys=

- Type :: integer
- Default :: =256=
- Since :: 0.2.0

How many distinct calls one turn remembers while watching for
repeats.

Bounded on purpose: an unlimited set of unique arguments lets one
pathological turn grow the daemon for as long as it runs. The least
recently seen call is dropped first, and a dropped one starts
counting again from one.

*** =orchestration.handoff_max_per_turn=

- Type :: integer
- Default :: =4=
- Since :: 0.2.0

How many handoffs one turn may queue.

Small deliberately. A blocking ask gets backpressure for free
because the caller waits; an asynchronous handoff does not, so this
is the only thing standing between a confused chief of staff and a
fan-out of real turns that each cost money.

Counted as handoffs still *waiting*, not as a tally reset each turn.
Usually the same number, because a queue drains when the turn that
filled it ends -- and deliberately not the same when it does not: a
transfer still waiting for a busy recipient goes on counting, so an
agent with three stuck cannot queue four more on top of them.

The refusal says how many are waiting and suggests doing the piece
rather than queueing another. 0 removes the limit.

*** =orchestration.handoff_busy_retries=

- Type :: integer
- Default :: =3=
- Since :: 0.2.0

How many times a handoff waits for a busy assignee before giving up
and saying so.

Giving up is its own outcome rather than a failure: 'nobody was
free' and 'it went wrong' need different answers from whoever reads
the receipt.

These are tries, not seconds. A queued handoff is looked at every
time any turn in the fleet ends, so three tries means three turn
boundaries went by with the recipient still mid-turn. 0 waits
indefinitely, which is only sensible in a fleet where every turn
ends.

*** =orchestration.handoff_receipt_days=

- Type :: integer
- Default :: =2=
- Since :: 0.2.0

How long a finished handoff's receipt is kept.

A receipt says how one handoff went: queued, delivered, refused. The
task itself is kept for orchestration.task_retention_days; this is
the record of the move.

A count bounds the file as well as this age, because a fleet that
passes work around all day fills two days faster than a quiet one
fills two years. A handoff that has not run yet is never pruned
however old it is: it is undrained rather than finished. 0 keeps
receipts until the count alone drops them.

*** =orchestration.review_rounds=

- Type :: integer
- Default :: =3=
- Since :: 0.38.0

How many times a reviewer may send a task back for changes before the
operator decides.

Reviewed work goes back and forth between its assignee and its
reviewer (agents.review_by); past this many rounds of changes the task
stays in review and the verdict becomes the operator's, as a decision
in the inbox, rather than the two going round again. 0 removes the
limit.

*** =orchestration.checkout_keep_days=

- Type :: integer
- Default :: =14=
- Since :: 0.39.0

How long a finished task's checkout is kept, in days.

A task given a repository (`repo` on clawtilla_delegate or a new task)
works in a checkout of its own under its assignee's workspace, at
tasks/<task>, on the branch clawtilla/<task>. Once the task has been
finished this long the checkout is removed and its branch kept: a
worktree's branch is in the repository already, and a clone's is
fetched back into it first. A checkout with uncommitted changes is
never removed this way -- that is the operator's call, from the
task's Changes. 0 keeps every checkout.

*** =orchestration.task_retention_days=

- Type :: integer
- Default :: =180=
- Since :: 0.35.0

How long a finished task is kept, in days.

Every task is written to tasks.db in the state directory as it
changes, with a journal of what happened to it, so a daemon restart
keeps the list, a delegator can still ask what became of its work,
and a parent still knows its children. A task that has finished is
removed once it is older than this, with its journal; one that has
not finished is never removed however old it is, because somebody
may still be waiting on it. The clients' Tasks lists show the tasks
that have not finished and those that finished in the last day; the
rest are in the history (task.list with history: true, or
`clawtilla task list --history`). 0 keeps every task.

*** =orchestration.max_waits_per_agent=

- Type :: integer
- Default :: =10=
- Since :: 0.15.0

How many pending waits one agent may have.

A wait (clawtilla_wait_until) is a condition clawtilla checks by code
-- a URL, a file, a task, the agent's computer, a command -- so the
model is woken once when it holds rather than on every look. A pending
wait costs no turns, but each one is a probe: a URL fetched once a
minute, a command run on the agent's computer. This bounds how many
of those one agent can leave running, and the refusal names its
pending waits so it can fold a new one into an old one.

Override with max_waits on an agent. 0 removes the limit.

** =orchestration.incidents=

Reports of runs that broke, sent to whoever leads the team.

A delegated task that failed or stalled, an agent that would not start
with work waiting for it, and a routine run that did not happen each
open an incident: one per run (the same task failing again updates it),
filed in a room per team called "Problems to look at", and delivered
as a report the recipient can act on with clawtilla_task_retry. A
recipient that is mid-turn has its report held until the turn ends.
See docs/orchestration.org, "Incidents".

*** =orchestration.incidents.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.17.0

Whether broken runs open incidents at all.

Off, nothing is filed and nobody is told; tasks still fail and stall
exactly as before, and their delegators still get the settle notice.
Retrying a failed task works either way.

*** =orchestration.incidents.to=

- Type :: enum
- Values :: lead, chief, none
- Default :: =lead=
- Since :: 0.17.0

Who an incident report goes to: lead, chief or none.

lead is the failing agent's team lead, or the chief of staff when the
team has none (or two). chief is always the chief of staff. none spends
nobody's turn: the report is recorded in the room for you to read.
Never the agent whose run broke, and never the agent that delegated
the task -- it already has the settle notice.

** =memories=

What an agent remembers between conversations.

Not agents.memory, which is the MEMORY.md size budget and a different
thing entirely. This is the searchable store.

Each agent gets its own SQLite database beside its mailbox, holding
what it chose to write down: decisions, preferences, things that
turned out to be true. It searches its own with clawtilla_memory_*.

One database per agent rather than one table with an agent column, so
isolation is a property of the filesystem: a query that forgot to
filter still cannot reach another agent's memories, because they are
not in the file being read.

*** =memories.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether agents get a memory store at all.

Off means the clawtilla_memory_* tools are not offered, rather than
offered and failing. An agent that can see a tool will try it.

*** =memories.max_results=

- Type :: integer
- Default :: =20=
- Since :: 0.1.0

How many memories one search or listing returns at most.

This lands in the agent's context on every call, so the limit is a
budget rather than a formality.

*** =memories.readers=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Comma-separated ids of agents allowed to read this agent's memories.

Empty by default, which is the whole point: an agent's memories are
its own unless somebody says otherwise. Reading only -- there is no
setting that lets one agent write into another's memory, because a
memory you did not form is not a memory.

A comma-separated string, not a YAML list: `readers: chief, deputy`.
Written as `readers: [chief]` it reads back as unset and grants
nothing, so the loader warns about that spelling rather than leaving
a permission somebody granted silently denied.

*** =memories.scope=

- Type :: enum
- Values :: agent, team, fleet
- Default :: =agent=
- Since :: 0.2.0

Where this agent's own memories are written: agent, team or fleet.

Reading always fans out across every scope the agent is entitled to;
this says only where a new memory lands. A fact the whole fleet
needs is worth writing once rather than being relearned by each
agent in turn.

Each scope is a separate database, so what an agent may read is
decided by which file is opened rather than by a WHERE clause. A
permission that is structural cannot be lost to a missing
condition.

`team` needs the agent to be on one. An agent with no `team:` that
asks for team scope is refused rather than quietly written to its own
database -- a memory whose whole purpose was to reach the team is worse
in the wrong place than not written at all.

*** =memories.recall=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether the agent may search past conversations.

Separate from `memories.enabled`, which is about facts the agent
chose to record. This is about the transcript itself, which it never
chose and which is much larger.

Off means `clawtilla_recall` is not offered, rather than offered and
refused. Only rooms the agent is a member of are ever searched, so this
is about the agent reading its own past rather than anybody else's.

*** =memories.summarise=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether finished work is summarised into memories automatically.

Off by default because it is a model call nobody asked for, billed
to whoever set it. On, a completed task or a closed routine run is
distilled into memories tagged with the transcript they came from.

It uses the `ai_assist` provider, so that has to be configured too,
and the memories land in whichever scope `memories.scope` names. A
summary that produced nothing is the common answer and not a failure.

*** =memories.nudge_turns=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

The cadence the reminder to record what was learned asks for. 0 is
off.

The reminder rides the per-agent prompt suffix rather than being a
mechanism of its own, so it is visible in the same place as every
other per-turn instruction -- `clawtilla config render` shows it
beside the computer directive.

A prompt suffix reaches every turn, so this number is what the
reminder asks the agent for rather than something clawtilla counts.
Counting turns from the daemon would need a per-turn channel to the
agent, and the only one there is is the delivery preamble -- which not
every turn has.

*** =memories.journal_keep=

- Type :: integer
- Default :: =1000=
- Since :: 0.26.0

How many changes each memory database's journal keeps. 0 keeps every
one.

Every remember, forget, pin and unpin is written to a journal beside
the memories it changed, with who made it, and the Memory review page
in each client lists it with an Undo per row. The oldest rows go first
once there are more than this, and a change whose row has gone can no
longer be undone -- the page says so rather than offering a button
that cannot work. One journal per database: an agent's own, each
team's and the fleet's.

*** =memories.operator_profile=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether the fleet keeps a profile of the person it works for.

A fleet-scope memory a newly created agent inherits, so it starts
knowing how you work instead of learning it again. Plain text and
editable: a model of a person that the person cannot read is not
something to build.

Two halves: `<state_dir>/OPERATOR.org`, which you write, and
fleet-scope memories in the `operator` category, which agents record.
Both are written into a marked region of every agent's USER.org, so a
change reaches the whole fleet rather than only agents made afterwards.
Off removes the region again.

** =memories.review=

A periodic review of each agent's memories by a small model, which
proposes merges, forgets and pins for a person to accept one at a
time. Off unless a model is named.

*** =memories.review.model=

- Type :: string
- Default :: ==
- Since :: 0.29.0

The model that reviews memories, as provider/model --
claude/claude-haiku-4-5-20251001, ollama/llama3.2. Empty turns the
review off, which is the default.

Off by default because every pass is a model call nobody asked for,
billed to whoever set this. On, each agent's own memories are read
by the model at most once per interval, fenced as data, and what it
proposes -- merge two memories into one, forget one, pin or unpin

anything, through the same journaled store as every other change, so
an accepted proposal can be undone like any other.

ai_assist's is. The model has a hard limit of 60 seconds per pass; a
timeout, a failure and a reply that cannot be read propose nothing.

*** =memories.review.interval_hours=

- Default :: =24=
- Since :: 0.29.0

How often each agent's memories are reviewed, in hours (1 to 720).

answered, so an unread list never grows by itself.

*** =memories.review.max_memories=

- Since :: 0.29.0

*** =sentinel.daily_spend_micros=

** =skills=

Reusable procedure, shared across the fleet.

A skill is a directory holding a SKILL.md, in the layout every
supported CLI understands. clawtilla links the ones an agent is
assigned into that agent's workspace at whichever path its provider
actually reads -- the paths differ per provider and are asked of the
library rather than written down here.

*** =skills.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether skills are scanned and linked at all.

Off means off rather than empty: nothing is scanned, no directory is
watched, and no link is written into any workspace. Existing links
clawtilla made are left where they are, so turning this off does not
quietly rewrite every agent -- turn it back on, or remove the
assignments, if that is what you meant.

*** =skills.dir=

- Type :: path
- Default :: =~/.clawtilla/skills=
- Since :: 0.2.0

Where the fleet's skills live.

One directory per skill, each holding a SKILL.md whose front matter
names it and says when to use it. The directory name and the `name`
must agree, because that name is the traversal gate: no dots, no
slashes, and no way to call a skill `..`.

A skill lives here once and is linked into whichever workspaces need
it, at whatever path that agent's own CLI reads -- which differs per
provider and is asked of the library rather than written down. The
directory is watched, so editing a SKILL.md takes effect without a
reload. It is not created for you: a read with a side effect is how a
typo in this path leaves an empty directory to puzzle over later.

*** =skills.extra_dirs=

- Type :: list of strings
- Default :: =~/.agents/skills=
- Since :: 0.9.2

Other directories of skills to read, on the daemon's machine.

~/.agents/skills by default: the directory ai-glib's harnesses, Claude
Code and others share, so a skill installed for them is a skill the
fleet has. Read after skills.dir -- a skill of the same name there
wins -- and never written: removing one is refused, and turning one
on or off is kept under the daemon's state directory. A directory
that does not exist is skipped without a word. An empty list reads
only skills.dir.

*** =skills.teach_max_seconds=

- Type :: integer
- Default :: =900=
- Since :: 0.2.0

How long a demonstration may record before it stops itself.

A recording that has been forgotten is worse than one that ended
early, because what it captures is whatever you did next.

The deadline is armed when the recording starts and is not a
request: it fires whether or not anything is still listening, and
it is passed to the compositor as well, so a clawtilla that dies
mid-demonstration does not leave one running. Zero means the
default rather than no limit.

*** =skills.teach_max_events=

- Type :: integer
- Default :: =20000=
- Since :: 0.2.0

How many recorded steps a demonstration keeps.

Bounded, and the count of what was dropped is reported rather than
hidden: a silently truncated demonstration teaches half a task.

The earliest steps are the ones kept, because the first part of a
procedure is a usable prefix of it while a slice out of the middle
is not. Pointer motion is never counted: a drag is hundreds of
events and would spend the whole budget on the mouse travelling,
so every click and scroll carries the position it happened at
instead.

*** =skills.max_proposals_per_day=

- Type :: integer
- Default :: =3=
- Since :: 0.19.0

How many skills one agent may propose in any 24 hours.

clawtilla_skill_propose lets an agent write down a technique it
worked out -- a new skill, or a change to one that exists -- as a
draft that reaches no prompt, with a decision in your inbox to
approve, edit or reject it. Every proposal spends your attention, so
this bounds how often one agent can ask for it; a rejected proposal
still counts. 0 turns proposing off, and the tool is not offered.

** =rooms=

Standing rooms, created at startup if they do not exist.

A room is a conversation with members. Posting into one enqueues to
every member's mailbox. A direct chat is just a room with two members,
so there is one mechanism rather than two.

*** =rooms.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.1.0

Identifier used to address the room.

*** =rooms.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Display name.

*** =rooms.members=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Agent ids in the room. The human is always implicitly a member.

*** =rooms.require_mention=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Only deliver messages that name a member.

Defaults to the room's shape when it is not set: off for two members,
where everything said is for the other one, and on for three or more,
where delivering every remark to everybody costs a model turn each
and is never what anybody meant. Setting it explicitly wins either
way.

A member is named as @its-id or as a bare word; matching ignores
case, and an agent's display name counts when it is a single word.
@all reaches everybody and belongs to you -- an agent writing it
reaches nobody, because one broadcast per reply is how a room of five
turns one remark into a runaway.

A message that names nobody is still recorded and everyone can read
it. That is the ordinary way to take part, and each delivery says so.

*** =rooms.max_hops=

- Type :: integer
- Default :: unset
- Since :: 0.1.0

Overrides orchestration.max_hops for this room.

It may loosen the fleet limit as well as tighten it, which is the
whole reason it exists: in a conversation three agents each reply one
hop deeper, so an ordinary standup reaches the fleet ceiling on its
own, and the only other remedy is raising orchestration.max_hops for
every delegation chain in the fleet to fix one room.

It reaches the hop count and nothing else. The rate limit, the task
budget and the cycle detector are untouched, so a loop that costs
money still has three limits on it.

In a group room this is the backstop rather than the limit that
fires: rooms.max_chain ends a thread of replies first, and the depth
starts again at each round.

*** =rooms.max_chain=

- Type :: integer
- Default :: =3=
- Since :: 0.20.0

How many replies one thread may run to in a round of a group room.
0 removes the cap; the once-per-thread rule below still applies.

A round starts at a message from you, a routine or a trigger. Each
member that answers it starts a thread, and an @mention in a reply
carries the thread on. Within one thread a member answers once: a
mention of a member already in that thread is recorded in the room
and not delivered, with the reason shown beside it. A member that
spoke in another thread of the same round still answers.

Without this the hop count built up across a room's history, so an
ordinary standup reached max_hops by itself. The depth now starts
again at every round, and max_hops stays as the backstop.

*** =rooms.turn_timeout_seconds=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

How long one member may hold a room's turn before it is yielded.
0, the default, turns it off.

Off for the same reason as agents.runtime.turn_timeout_seconds, and
the five minutes it used to default to were worse: an agent doing
real work in the operator's own room was stopped mid-turn and the
room stalled, five minutes in, and the notice explaining it read as
though the agent had misbehaved.

Set a number for a busy shared room, where the point is that one
member must not hold the floor indefinitely. Counted in work, not
wall time: the clock holds while the turn is parked on an open
decision and resumes with what is left. Stopping a turn under a
question nobody has answered manufactures a stranded decision, which
the daemon then has to repair.

Different from the runtime's turn timeout: that one catches a wedged
worker, this one catches a wedged conversation.

Anything below 60 is raised to 60.

*** =rooms.order=

- Type :: integer
- Default :: unset
- Since :: 0.2.0

Where this room sits in the sidebar, among the agents.

The same scale as agents.order, because a client draws one list and
a room can sit beside the agents it concerns. Written by the clients
when a room is dragged or moved, numbered from one in steps of ten so
there is room to hand-place something between two.

*** =rooms.team=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Which team's group this room appears under in the sidebar.

Presentation and nothing else: it does not change who is in the room
or who a message reaches. A room with no team sits with the agents
that have none.

*** =rooms.catchup_messages=

- Type :: integer
- Default :: =20=
- Since :: 0.2.0

How much of a room a member is caught up on when it is named.

In a room that requires mentions an agent only receives the messages
that named it, so without this it has no idea what was being
discussed -- the transcript holds the conversation and the model does
not. Each delivery carries the messages since that member last heard
from the room, capped here, with a count of anything dropped.

0 turns it off. Anything older is clawtilla_room_history, which the
delivery preamble names.

** =projects=

Projects: the pieces of work the fleet is pointed at.

A task belongs to at most one project: the one its delegation or the
operator named, else its parent's, else the one whose directory its
checkout came from (by path, or by a shared git remote). Its assignee
is told the project's name and goal; the project's spend is summed
over its tasks each month, against an optional budget; and every
agent working in it finds it in PROJECTS.org. Optional: a fleet with
none works exactly as before.

*** =projects.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.40.0

Identifier used to address the project: `project` on a delegation or
a new task, and the task lists' filter.

*** =projects.name=

- Type :: string
- Default :: unset
- Since :: 0.40.0

Display name; the id when unset.

*** =projects.directory=

- Type :: path
- Default :: unset
- Since :: 0.40.0

The project's repository or directory, as a host path.

A task whose checkout is of this directory -- or of any repository
sharing one of its git remotes, compared as host/owner/repo -- belongs
to this project without being told.

*** =projects.goal=

- Type :: string
- Default :: unset
- Since :: 0.40.0

What the project is for, in a sentence or two.

Every assignment in the project starts with it, so the agent doing a
piece of work knows what the piece is for.

*** =projects.review_by=

- Type :: string
- Default :: unset
- Since :: 0.40.0

Who reviews work in this project, as agents.review_by spells it.

Between a delegation's own `review` and the assignee's
agents.review_by: the project's rule beats the agent's habit.

*** =projects.agents=

- Type :: list of strings
- Default :: unset
- Since :: 0.40.0

The agents that work in this project, by id.

Only decides whose PROJECTS.org lists it; empty lists it for every
agent. Anyone may still be given its work.

*** =projects.monthly_budget_usd=

- Type :: number
- Default :: =0=
- Since :: 0.40.0

What the project may spend in a calendar month, in US dollars.

Summed from every agent's usage ledger over the project's tasks
made this month. 0 means no budget: spend is still shown.

*** =projects.budget_warn_percent=

- Type :: integer
- Default :: =80=
- Since :: 0.40.0

At what share of monthly_budget_usd the operator is warned, once a
month.

*** =projects.budget_hard_stop=

- Type :: boolean
- Default :: =false=
- Since :: 0.40.0

Refuse new work in the project once its monthly budget is spent.

A delegation, a new task and a held task's release are refused, as
the spending caps refuse, with the reason. Work already handed over
is not stopped.

*** =projects.venture_repo_id=

- Type :: integer
- Default :: =0=
- Since :: 0.44.0

The VENTURE repository (a `forge_repo` id) this project's tasks are
mirrored against.

Only with a venture connector's `mirror_tasks` on. Without it, a
task's checkout remotes are matched against VENTURE's repositories;
with it, the project's tasks file there whatever their remotes say.
0 for none. See docs/venture.org.

*** =projects.venture_milestone_id=

- Type :: integer
- Default :: =0=
- Since :: 0.46.0

The VENTURE milestone this project's mirrored tickets are filed under.

Its name, due date and state are read once a day and shown in the
project's agents' PROJECTS.org and each task's assignment. 0 for none.
See docs/venture.org.

*** =projects.venture_goal_id=

- Type :: integer
- Default :: =0=
- Since :: 0.46.0

The VENTURE goal this project's mirrored tickets count toward.

Its name and progress (current against target) are read once a day
and shown with the milestone. 0 for none. See docs/venture.org.

** =teams=

Teams, so a fleet larger than a handful has a shape.

An agent names its team in agents.team, and its standing there in
agents.team_role. A lead may hand work to the members of its own team;

sits above all of them and hands work to the leads.

Teams are optional. A fleet that declares none behaves exactly as it
did before there were any.

*** =teams.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.1.0

Identifier used to address the team, and what agents.team names.

*** =teams.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Display name. Defaults to the id.

*** =teams.description=

- Type :: string
- Default :: unset
- Since :: 0.1.0

What this team is for, and what to send it.

Written for a chief-of-staff deciding where a piece of work goes: it
reads these to choose a team, so say what the team handles and what it
does not, rather than naming the people on it.

*** =teams.color=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Accent colour in the clients, as a hex string.

*** =teams.order=

- Type :: integer
- Default :: =0=
- Since :: 0.1.0

Where this team sits in the list, lowest first. Ties keep file order.

*** =teams.skills=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Skills every agent on this team gets.

Between the fleet default and the agent's own list, resolved by the
same function as both. The three are additive: a skill named in two
of them is one skill, and the most specific place it was asked for is
what gets reported.

*** =teams.broker_server=

- Type :: string
- Default :: unset
- Since :: 0.24.0

The broker's gateway server for this team's agents.

For anythingmcp, the id of an MCP server made in its dashboard (the
last part of the server's MCP URL); its connectors are what the
team's agents may use. For jentic, the Jentic agent the team acts
as, whose API key `clawtilla broker key team:<id>` stores. An agent
with its own agents.broker_server uses that one instead. Unused
unless broker.enabled is on.

** =computers=

Machines several agents share.

Each entry takes an id and the same keys as an agent's computer:
block -- type, container, vm, desktop, mounts, and the rest; every
one is documented under agents.computer. An agent joins one with
agents.computer.use. Agents A and B on `alpha` and C, D and E on
`beta` are two machines, not five.

Each agent keeps its own workspace, mounted at
/mnt/clawtilla/workspaces/<agent>, and its own exchange folder. The
machine stops when its last running agent stops, and is rebuilt only
when every agent on it is stopped. A desktop is one screen, driven by
one agent at a time.

*** =computers.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.5.0

Identifier, and what agents.computer.use names. The machine is called
clawt-c.<id> in podman, distrobox and libvirt -- a dot no agent id can
hold, so it never shares a name with an agent's own machine.

*** =computers.description=

- Type :: string
- Default :: unset
- Since :: 0.5.0

What this machine is for.

** =browsers=

Web browser sessions several agents share.

Each entry takes an id and the same keys as an agent's browser:

Agents on one entry share one profile -- its cookies, its logins, its

*** =browsers.id=

- Type :: string

- Since :: 0.9.0

Identifier, and what agents.browser.use names.

*** =browsers.description=

- Type :: string

What this session is for -- say which logins it holds.

** =vault=

Secrets an agent can have typed into a web page without ever seeing
them: passwords, and TOTP seeds the daemon turns into one-time codes.

  vault:
    - name: github
      secret: {command: "pass show web/github"}
      sites: [github.com]
    - name: github-2fa
      kind: totp
      secret: {file: github-totp}
      sites: [github.com]

An agent may ask only for the names its agents.browser.secrets lists.
It calls clawtilla_secret_ref for a one-use reference bound to it and
to the conversation it is in, then clawtilla_browser_fill_secret with
that reference and a field. The daemon resolves the value, types it
into the field as key input, and the agent hears only that it was
filled. Screenshots and clawtilla_browser_eval are refused on that
page until the browser navigates away. Needs a GSURF=1 build.

*** =vault.name=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.25.0

What an agent asks for, and what agents.browser.secrets lists. The
name is all an agent or a client ever sees of the entry's secret.

*** =vault.description=

- Type :: string
- Default :: unset
- Since :: 0.25.0

Whose login this is, or which field it belongs in.

*** =vault.kind=

- Type :: enum
- Values :: password, totp
- Default :: =password=
- Since :: 0.25.0

`password` types the value itself. `totp` reads the value as a TOTP
seed -- base32, or an otpauth://totp/ URI with its algorithm, digits
and period -- and types the RFC 6238 code for the current time.

*** =vault.secret=

- Type :: secret reference
- Default :: unset
- Required :: yes
- Since :: 0.25.0

A secret reference, never the value: {file: ...}, {env: ...} or
{command: ...}, resolved the way secrets: says, at the moment of the
fill and not before.

*** =vault.sites=

- Type :: list of strings
- Default :: unset
- Required :: yes
- Since :: 0.25.0

The hosts the secret may be typed into: a page on any other host is
refused, so an agent steered to a look-alike site cannot be made to
fill it there. `example.com` also matches its subdomains
(login.example.com); a page whose address cannot be read is refused.
An entry without sites is never filled.

** =accounts=

Separate logins for an agent CLI, so two agents on one machine can
spend two subscriptions.

Each account is a directory the CLI keeps its login and settings in;
an agent picks one with agents.model.account. Claude Code and the tmux
variant use CLAUDE_CONFIG_DIR, codex CODEX_HOME, grok GROK_HOME and
opencode its XDG directories. cursor and antigravity keep their login
under $HOME and cannot take an account: an agent that names one for
them is disabled with that reason rather than run on the default
login.

The directory is not created. Log in once with `clawtilla account
login ID`, which runs the CLI's own login against it.

*** =accounts.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

Identifier, and what agents.model.account names.

*** =accounts.provider=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

The agent CLI this login is for: claude-code, claude-tmux, codex-cli,
grok-build or opencode. An agent may use the account only when its own
provider is the same CLI.

*** =accounts.config_dir=

- Type :: path
- Default :: unset
- Required :: yes
- Since :: 0.2.0

The directory the CLI keeps this login in. ~ is expanded.

*** =accounts.description=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Whose login this is, or what it is for.

*** =accounts.pay_per_use=

- Type :: boolean
- Default :: =false=
- Since :: 0.16.0

This login bills each use -- an API key -- rather than drawing on a
subscription's limit.

Only agents.model.fallbacks reads it. Failing over to another sign-in
of the same subscription is refused, because rotating accounts to
get past a usage limit breaks the provider's terms; a pay-per-use
login on the same CLI pays for the work it does and is allowed.

** =integrations=

Named integrations, each handed to one agent, some agents or all of them.

An integration is a connection to something outside the fleet, kept in
one place and pointed at whichever agents should have it. That is the
difference from the per-agent `integrations:` block inside an agent,
which still works and is still the right thing for a connection only
that one agent will ever use: this one is configured once and scoped.

Which keys below apply depends on `type`. Each names the type it
belongs to; a key belonging to another type is ignored rather than
rejected, so changing a draft's type does not mean deleting fields
first.

*** =integrations.name=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

What this instance is called.

Unique across the file, and used everywhere the instance is referred
to -- the CLI, the UI, and the key it gets in an agent's .mcp.json. Two
instances with the same name is an error rather than a merge, because
the second silently winning is how a credential ends up pointing at the
wrong account.

*** =integrations.type=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

Which kind: matrix, email, webhook, local, cmacs or mcp.

An unknown type disables that instance and nothing else, with the
reason recorded -- the same treatment a shadow agent gets, and for the
same reason: a config written by a newer build must survive an older
one.

*** =integrations.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether this instance is live at all.

Independent of `scope`: this is the switch, scope is the audience.

*** =integrations.scope=

- Type :: enum
- Values :: none, selected, all
- Default :: =selected=
- Since :: 0.2.0

Who gets it: all, selected or none.

`all` includes agents created later, which is the point of it -- a tool
server the fleet shares should not need revisiting every time the fleet
grows. `selected` uses the `agents:` list below. `none` keeps the
instance and its credentials without handing it to anybody.

*** =integrations.teams=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Team ids, when `scope: selected`.

Beside `agents:` rather than instead of it, and either can match.
Naming a team is how an instance covers a group without being
rewritten every time somebody joins it.

Worth thinking about for a *channel*: two agents sharing one Matrix
account answer as the same person, so a team is rarely what you want
there. For a tools integration it is the ordinary case.

*** =integrations.agents=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Agent ids, when `scope: selected`.

An id that names no agent is a warning rather than an error: an agent
removed for the afternoon should not stop the daemon starting.

*** =integrations.per_agent=

- Type :: mapping
- Default :: unset
- Since :: 0.2.0

Per-agent overrides, keyed by agent id.

This is how one instance covers several agents that cannot share an
identity. A Matrix account is one login: two agents on the same one
both receive every message and both answer as the same user. So the
homeserver and the room list live at the top and each agent's own
user_id and access_token go here.

Any key from this section may be overridden, not only the identity
ones -- a room list that differs per agent is an ordinary thing to
want.

*** =integrations.description=

- Type :: string
- Default :: unset
- Since :: 0.2.0

What this is for, in your words.

Written into the agent's TOOLS.org beside the integration, so it is
the sentence the model reads when deciding whether this is the thing
to reach for. Worth filling in for anything whose name is not
self-explanatory.

*** =integrations.homeserver=

- Type :: string
- Default :: unset
- Since :: 0.2.0

matrix: the homeserver base URL, e.g. https://matrix.example.org.

*** =integrations.user_id=

- Type :: string
- Default :: unset
- Since :: 0.2.0

matrix: the full user id, e.g. @agent:example.org.

Must differ per agent. Put it under `per_agent` when the instance
covers more than one.

*** =integrations.access_token=

- Type :: secret reference
- Default :: unset
- Since :: 0.2.0

matrix: the access token, as a secret reference.

`clawtilla integration matrix-login` turns a password into one of
these without the password ever being written down.

*** =integrations.rooms=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

matrix: room ids to listen in.

Empty means every room the account is joined to. Bridged rooms --
Discord, Signal, anything else with a Matrix bridge -- are just rooms,
so an agent reaches them without knowing they are bridged.

*** =integrations.require_mention=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

matrix: only answer messages that name the agent.

Defaults on, unlike a clawtilla room. A Matrix room usually has people
in it talking to each other, and an agent that takes a turn on every
line of it is both expensive and unbearable.

*** =integrations.backend=

- Type :: enum
- Values :: desktop, ntfy, gotify, matrix, command, apprise
- Default :: =desktop=
- Since :: 0.2.0

notify: how the notification reaches you.

`desktop` raises one on the machine the daemon runs on, which is the
wrong answer when the daemon is on a workstation and you are not.
`ntfy` and `gotify` reach a phone. `matrix` posts into a room, which
on a bridged homeserver means it reaches you wherever you already
read messages. `command` runs a program and hands it the text.
`apprise` (since 0.22.0) hands it to the apprise CLI, which reaches a
hundred-odd services -- Telegram, Signal, email, Pushover, Gotify, SMS
-- through one URL scheme; the URL is `apprise_url`.

*** =integrations.token=

- Type :: secret reference
- Default :: unset
- Since :: 0.2.0

notify: the credential for ntfy, gotify or Matrix, as a secret
reference. libresearch: the server's token. grokbot: the routine's
webhook key (`crsr_...`), which is the whole of what lets anybody
start that bot.

Resolved once when the configuration loads rather than on every
notification: a `command` reference to a locked password manager
blocks until it times out, and doing that each time something needed
saying would make the notifier the slowest thing in the daemon.

*** =integrations.apprise_url=

- Type :: secret reference
- Default :: unset
- Since :: 0.23.0

notify: with `backend: apprise`, the Apprise URL -- or several, one per
line -- as a secret reference: `{file: ~/.config/clawtilla/apprise.url}`.

A secret because an Apprise URL nearly always carries a credential
(`tgram://BOT_TOKEN/CHAT_ID`, `mailtos://user:password@host`). It
reaches apprise in a 0600 file passed with `--config`, deleted when
apprise exits, and never on its command line, which any user on the
machine can read. `command` names the apprise binary when it is not on
PATH.

*** =integrations.room=

- Type :: string
- Default :: unset
- Since :: 0.2.0

notify: with `backend: matrix`, the room id to post into.

A room of your own with nobody else in it works well: it keeps the
fleet's noise out of a room people are talking in, and still arrives
on every device you read Matrix on.

*** =integrations.events=

- Type :: list of strings
- Default :: =question,error=
- Since :: 0.2.0

notify: what is worth interrupting you for.

`question` -- an agent said something to you and is waiting.
`done` -- a task finished.
`error` -- an agent stopped in a way nobody asked for.
`routine` -- a scheduled run failed.
`update` -- a newer clawtilla exists.
`budget` -- a daily spending cap refused work
(`orchestration.daily_fleet_budget_micros`, or an agent's
`orchestration.daily_agent_budget_micros`).

The default is question and error, which is the whole rule: blocked
on you, or broken. A notifier that fires on every turn is one people
turn off, and then it is not there for the two that mattered.

*** =integrations.priority=

- Type :: string
- Default :: =normal=
- Since :: 0.2.0

notify: low, normal, high or urgent.

Mapped onto whatever the backend understands -- ntfy's five levels,
gotify's ten, the two urgency hints a desktop has.

*** =integrations.provider=

- Type :: string
- Default :: unset
- Since :: 0.2.0

connector: which service this is an account on.

One of the ids from `clawtilla connector catalog`. The catalogue says
how to authenticate and, where there is a well-known one, which MCP
server fronts it -- so a connector integration is usually a provider,
a client id and nothing else.

*** =integrations.account=

- Type :: string
- Default :: unset
- Since :: 0.2.0

connector: which account on that service, in your own words.

Two connectors for the same provider are the ordinary case -- work
and personal, or one GitLab org and another -- and the account label
is what tells them apart everywhere they are shown.

Required, and unique per provider, for every account after the first:
adding a second one without a label, or with one another account on
that service already uses, is refused. An agent granted several
accounts on one service sees each account's tools prefixed with its
label -- `work_create_issue`, `personal_create_issue` -- and a call to
the bare name is refused rather than run as whichever account it
happened to reach.

*** =integrations.instance=

- Type :: string
- Default :: unset
- Since :: 0.2.0

connector: the host, for a service you run yourself.

Only meaningful for a self-hostable provider such as gitlab or
forgejo, where the endpoints are paths joined onto this. Left unset

*** =integrations.client_id=

connector: the OAuth application you registered with the provider.

clawtilla ships none. It has no application of its own to lend, and

Written by the daemon when the flow completes, and named here rather

*** =integrations.credential_name=

*** =integrations.tools=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

connector: the only tools the agent may use, if you want fewer.

Empty means every tool the server offers. Naming some is enforced in
the relay: the others are removed from the agent's tool list rather
than refused when called, because a tool that is advertised and then
refused is worse than one that was never there -- the agent plans
around it and has to work out from an error that it never had it.

*** =integrations.directory=

- Type :: enum
- Values :: auto, always, never
- Default :: =auto=
- Since :: 0.18.0

connector: whether its tools are listed one by one or searched.

A server with hundreds of tools puts every description into every
model call. As a directory it is three tools instead --
<name>_search_tools, <name>_describe_tool and <name>_call_tool -- and
the agent looks up what it needs. The search, the description and the
call all work from the tools this agent may use, so narrowing `tools:`
narrows what can be found as well as what can be called.

`auto` makes a directory of a server past
connectors.directory_min_tools or connectors.directory_min_chars, for
an agent whose CLI does not search tools itself; Claude Code does, so
its agents get every tool as before. `always` makes one whatever the
size or the CLI, and `never` lists every tool however many there
are. See docs/connectors.org, "Servers with many tools".

*** =integrations.max_result_bytes=

- Type :: integer
- Default :: =-1=
- Since :: 0.27.0

connector: the most of one tool result the agent is shown, in bytes.

A result bigger than this is trimmed before the agent reads it -- the
text cut on a character boundary, a JSON array cut to the records that
fit, structuredContent trimmed the same way -- with a [clawtilla] note
at the start and the end saying what was cut. The whole result is kept
under the agent's state directory and the agent reads the rest with
clawtilla_mcp_result_query. -1 (the default) means the fleet's
connectors.max_result_bytes, 0 means no budget for this connector,
and anything below 1024 is read as 1024. See docs/connectors.org,
"Results bigger than the budget".

*** =integrations.show_apps=

- Type :: boolean
- Default :: =false=
- Since :: 0.27.0

connector: show its apps in chat.

An MCP server can ship an interactive view (an MCP App, a ui://
resource) for a tool. With this on, the relay tells the server it can
show them, reads the view when the tool is called, and the call
appears in the conversation as an app: the web client draws it in a
sandboxed frame when somebody opens it, and the GTK and lrg clients
offer it in the browser. Off by default, because the view is the
server's own code running in your browser. See docs/connectors.org,
"Apps in chat".

*** =integrations.confirm_writes=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

For a connector that can stage its writes, whether it does.

A staged write becomes a decision in the operator's own inbox rather
than something to be found later in the other system's web
interface. Turning this off means the agent's writes land
immediately and unreviewed.

Read by the `venture` connector, which is the one built-in that
stages. It does not switch staging on -- `venturectl mcp` decides
that for itself and stages by default -- it decides whether
clawtilla polls the queue and raises what is waiting as a decision.
Turning it off leaves the changes in VENTURE for somebody to find in
its own web interface.

*** =integrations.apply_writes=

- Type :: enum
- Values :: off, all, low_risk
- Default :: =off=
- Since :: 0.36.1

connector (venture): whether the agent's writes wait for approval.

`off` keeps every create, update and delete the agent makes in
VENTURE staged: VENTURE holds it, and with confirm_writes on it
reaches the operator's decision inbox to approve or reject. `all`
starts `venturectl mcp --apply-writes`, so every write lands at once,
unreviewed, as the agent's own VENTURE account -- opt in only for an
account whose memberships already limit what it can reach. With one
connector per agent this is per agent.

`low_risk` (since 0.43.0) starts `venturectl mcp
--apply-writes=low-risk`: ordinary writes -- tickets, comments,
worklogs, links -- land at once, and VENTURE still stages anything
touching money, people, access or credentials, anything sent outward,
and every delete. It needs VENTURE 0.10.0 or later; against an older
venturectl it falls back to `off` with a warning, never to `all`.

Ignored when `args` is set on the integration: those are the
server's arguments, as written. See docs/venture-setup.org, step 2.

*** =integrations.mirror_tasks=

- Type :: boolean
- Default :: =false=
- Since :: 0.44.0

connector (venture): copy the covered agents' tasks into VENTURE
tickets.

A task is mirrored only when this is on for an agent it involves and
its repository matches a VENTURE `forge_repo` -- a checkout remote
that /api/v1/forge_repo/resolve knows, or its project's
`venture_repo_id`. The delegator's account creates the ticket and
the assignee's keeps it current: status, assignee, results and
comments. Nothing on an agent's path waits on VENTURE: changes are
queued in tasks.db and sent behind. Needs VENTURE 0.10.0 or later.
See docs/venture.org.

*** =integrations.service_token_file=

- Type :: path
- Default :: unset
- Since :: 0.46.0

connector (venture), with mirror_tasks on: the operator's own VENTURE
token, for the mirror's writes that no agent makes.

Files the operator's own tasks, and tasks whose delegator and assignee
have no VENTURE account, as this account. Keep it outside
secrets.dir/connectors/ so no agent's box ever mounts it. See
docs/venture.org.

*** =integrations.mirror_intake=

- Type :: boolean
- Default :: =true=
- Since :: 0.45.0

connector (venture), with mirror_tasks on: a ticket assigned to this
agent's VENTURE user starts a task for it.

Only an internal ticket still `todo` and carrying no other system's
reference, at most ten an hour per agent; its text reaches the agent
fenced, as data. Anyone who can edit tickets in that VENTURE
organization can then hand this agent work: turn it off where that is
more than you want. See docs/venture.org.

*** =integrations.poll_seconds=

- Type :: integer
- Default :: =60=
- Since :: 0.2.0

How often a connector that has something to report is asked.

Polling, because the other end is another process with its own
event loop. It runs on a timer attached to the daemon's context --
never from a request handler, which would make a client wait on
somebody else's network.

One timer covers every connector, so the shortest interval anybody
asked for is the one that runs. The first poll is one interval after
the daemon starts, never during it.

*** =integrations.push_replies=

- Type :: boolean
- Default :: =true=
- Since :: 0.11.0

grokbot: hand each agent reply to the bot as a new run of its routine.

When a Grok bot starts a conversation with an agent, the agent's
reply is POSTed to the bot's routine, so the bot answers on its own.
Each reply is a Grok run -- 200 an hour per routine, and each one
billed. Off, replies wait in clawtilla until the bot reads them with
clawtilla_grok_replies. A reply Grok refuses waits the same way.

** =connectors=

Connected accounts: how clawtilla obtains credentials and keeps them.

A connector integration gives an agent the tools of a service without
giving it the credential. The daemon runs the authorization, holds the
token, renews it, and injects it into the tool server -- so the value
is never in the agent's .mcp.json, its environment or its transcript.

What that is worth depends on where the agent runs. For a container
or VM agent the boundary is real: the token file and the relay are on
the host and the agent cannot reach either. For an unconfined host
agent it is protection against leaking a credential by accident, not
against one that goes looking -- see docs/security.org.

*** =connectors.dir=

- Type :: path
- Default :: =$XDG_CONFIG_HOME/clawtilla/connectors.d=
- Since :: 0.2.0

Directory of extra connector definitions.

Each `.yaml` file holds a `connectors:` list, and an entry whose id
matches a built-in one replaces it. These are somebody else's URLs:
a provider that moves an endpoint should be fixable here rather than
by waiting for a clawtilla release.

*** =connectors.refresh_margin_seconds=

- Type :: integer
- Default :: =300=
- Since :: 0.2.0

How long before expiry to renew a token.

An access token often lasts an hour, and one that expires while the
request carrying it is in flight fails exactly like a wrong one --
the agent sees only a refusal from a service it was using a minute
ago.

*** =connectors.redirect_port=

- Type :: integer
- Default :: =8765=
- Since :: 0.2.0

Loopback port for the authorization-code flow's redirect.

Only used by providers with no device flow. It has to be a fixed
number rather than whatever the kernel offers, because the redirect
URI is registered with the provider in advance and most match it
exactly: register `http://127.0.0.1:8765/callback`.

Bound on 127.0.0.1 only. A redirect carries an authorization code in
a URL, and a listener on every interface offers that code to whoever
on the network reaches the port first.

A client clawtilla registers for itself by dynamic client registration
is registered with this redirect, so changing the port means signing
in again.

*** =connectors.discovery=

- Type :: boolean
- Default :: =true=
- Since :: 0.20.0

Whether a remote connector finds out for itself how to sign in.

A connector reached by URL whose catalogue entry names no endpoints
asks the server: its RFC 9728 protected-resource document names an
authorization server, whose RFC 8414 metadata names the endpoints,
and RFC 7591 dynamic client registration supplies a client id when
the connector has none. Endpoints a catalogue entry names by hand
always win, and so does a configured `client_id`.

Only when somebody asks for a sign-in -- never at daemon start. No
request in it follows a redirect, and nothing it finds may be plain
http unless the server itself is on loopback. Off, such a connector
takes a pasted token only.

*** =connectors.client_name=

- Type :: string
- Default :: =clawtilla=
- Since :: 0.20.0

What clawtilla calls itself when it registers with a server.

Sent as `client_name` in a dynamic client registration, so it is what
the server's consent screen shows the person approving it -- worth
setting to something that says which machine is asking when several
fleets sign in to one service.

*** =connectors.registry_enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether the open MCP registry is imported into the catalogue.

Off by default because it reaches the network. When on, the fetch
happens on a timer into a cache on disk -- never at daemon start and
never from a request handler, so a client pressing a button waits on
this machine and not on somebody else's. `connector.registry_refresh`
asks for one sooner than the timer would.

An imported entry only ever fills a gap: it never replaces a
built-in connector or one from connectors.dir, which are both a
choice somebody already made on purpose.

*** =connectors.registry_url=

- Type :: string
- Default :: =https://registry.modelcontextprotocol.io=
- Since :: 0.2.0

Base URL of the MCP registry to import from.

Somewhere else entirely is a legitimate answer: the registry is an
ordinary HTTP service and an internal mirror serves the same
shape.

*** =connectors.registry_refresh_hours=

- Type :: integer
- Default :: =24=
- Since :: 0.2.0

How often the cached registry listing is refreshed.

Checked against the cache's own `fetched_at`, not against when the
daemon last started -- a restart must not reset this clock, or a
fleet that bounces every hour would refresh every hour regardless of
what this key says.

*** =connectors.directory_min_tools=

- Type :: integer
- Default :: =40=
- Since :: 0.18.0

More tools than this makes a connector's server a directory.

Counted after the connector's `tools:` narrowing, because that is the
list the agent would otherwise read. Forty is where a tool list starts
to cost more than it helps -- and API-model engines refuse more than
128 tools a turn across every server they have. Only read when a
connector's `directory` is `auto`.

*** =connectors.directory_min_chars=

- Type :: integer
- Default :: =100000=
- Since :: 0.18.0

More characters of tool definitions than this makes a directory too.

The names, descriptions and input schemas together, which is what the
model actually reads on every call. A server with thirty tools can
still be a hundred thousand characters when each one carries a page of
documentation; about where Claude Code starts searching its own tools
rather than listing them. Only read when a connector's `directory` is
`auto`.

*** =connectors.max_result_bytes=

- Type :: integer
- Default :: =65536=
- Since :: 0.27.0

The most of one connector tool result an agent is shown, in bytes.

For every connector that does not set max_result_bytes itself. Past
it the result is trimmed, announced at both ends, and kept whole
under the agent's state directory for clawtilla_mcp_result_query, so
one listing of a big repository does not spend the whole context. 0
turns the budget off; anything below 1024 is read as 1024. Whatever
this says, the relay holds at most 64 MiB of one message in memory --
anything longer goes to disk as it arrives.

*** =connectors.apps_web_url=

- Type :: string
- Default :: =http://127.0.0.1:8790=
- Since :: 0.27.0

Where the web client is reached, for an MCP app's Open in browser.

The GTK and lrg clients cannot draw an app's HTML, so they link to the
web client's view of it: <this>/a/<agent>/app/<app>. The address
clawtilla-web listens on by default; change it when the web client
runs elsewhere or on another port.

** =broker=

An integration broker clawtilla runs for you, in podman.

Ready-made app integrations -- hundreds of SaaS and business systems
-- behind one MCP gateway on this machine. clawtilla pulls the
pinned image, keeps the gateway's database, keys and token under
<daemon.state_dir>/broker/, starts it with the daemon and keeps it
running. Each agent or team names its own gateway server in
agents.broker_server or teams.broker_server and reaches it as a
connector, through the same relay as every other connector.

Not the provider-key broker of runtime.network: gated, which is a
different thing with a similar name. See docs/connectors.org,
"An integration broker".

*** =broker.enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.24.0

Run the broker.

Off by default, because turning it on pulls an image of several
hundred megabytes and opens ports on this machine. Started in the
background when the daemon starts or this is turned on, never in the
way of either: broker.status says starting while the image pulls.

*** =broker.type=

- Type :: enum
- Values :: anythingmcp, jentic
- Default :: =anythingmcp=
- Since :: 0.24.0

Which broker: anythingmcp or jentic.

anythingmcp is an MCP gateway (AGPL-3.0) whose adapters turn REST,
SOAP, GraphQL and SQL services into tools, with OAuth through your
own client. jentic is Jentic One (Apache-2.0, a public beta whose
schemas may change), a credential broker that checks a per-agent
rule before it injects a stored key. Jentic One's own caveat is
that an agent running as the same OS user can read its state, so it
is refused unless every agent using it has runtime.confine: bwrap.
Its telemetry and release check are always switched off.

*** =broker.image=

- Type :: string
- Default :: unset
- Since :: 0.24.0

The gateway's image, pinned to a tag.

Empty means the image this release was checked against:
docker.io/helpcodeai/anythingmcp:v0.54.0 for anythingmcp and
ghcr.io/jentic/jentic-one-app:0.44.0 for jentic. An image with no
tag, or tagged latest, is refused: an upgrade should be a change
somebody made. AnythingMCP publishes amd64 only, so an aarch64
machine names a locally built one here -- docs/connectors.org says
how.

*** =broker.database_image=

- Type :: string
- Default :: unset
- Since :: 0.24.0

The database image beside an AnythingMCP gateway, pinned to a tag.

Empty means docker.io/library/postgres:17.12-alpine. The database
publishes no port: the two containers share a unix socket under
<daemon.state_dir>/broker/run. Jentic One keeps SQLite files and
runs no database container, so this is unused for jentic.

*** =broker.bind=

- Type :: string
- Default :: =127.0.0.1=
- Since :: 0.24.0

The address the gateway's ports are published on.

Loopback by default: the relay that reaches it runs on this machine.
Anything wider puts the gateway's dashboard and MCP endpoint on that
network, and the dashboard's own sign-in is all that guards it.

*** =broker.port=

- Type :: integer
- Default :: =47400=
- Since :: 0.24.0

The host port of the gateway's MCP endpoint and API.

For jentic this is also its dashboard, which shares the port.

*** =broker.dashboard_port=

- Type :: integer
- Default :: =47300=
- Since :: 0.24.0

The host port of AnythingMCP's dashboard.

Where you register the first (admin) account, sign in to SaaS apps
with your own OAuth clients and make a gateway server for each agent
or team. Unused for jentic, whose dashboard is on broker.port.

*** =broker.connection=

- Type :: string
- Default :: unset
- Since :: 0.24.0

Which podman runs the broker, as computer.container.connection says.

Empty is this user's rootless podman. A remote podman runs the
containers there while broker.bind and the relay still dial this
machine, so a remote one also needs a tunnel to its ports.

*** =broker.restart=

- Type :: enum
- Values :: never, on-failure, always
- Default :: =always=
- Since :: 0.24.0

What to do when a broker container stops without being asked to.

always starts it again however it ended. on-failure starts it again
only when it exited non-zero or was killed for running out of
memory; a clean exit, a container that never ran and one removed
from podman are left down. never leaves it down whatever the exit.
A container left down leaves the broker failed, and broker status
says how it ended and why it was not restarted. on-failure needs
podomation 1.0.3 or later, whose inspect reports the exit code;
with an older one it cannot tell a failure and restarts nothing.
Five restarts within ten minutes stop the retries, so a gateway
that cannot start is reported rather than restarted for ever.

** =grok=

Handing work to Grok bots, and hearing back.

Each bot is a `grokbot` integration named for it -- `chief`,
`research` -- whose url is a Grok routine's webhook. A job is POSTed
there with a callback address minted for it, and the bot reports
back to the daemon's webhook listener over the tailnet, by HTTP or
by the clawtilla MCP tools. These keys are about that return path.
See docs/grok.org.

*** =grok.callback_host=

- Type :: string
- Default :: unset
- Since :: 0.10.0

The name a Grok bot uses to reach this daemon.

Empty means the machine's own tailnet name, asked of tailscaled as
soon as the daemon starts -- the FQDN `tailscale status` shows for
it -- and a job sent before it answers waits for the answer. This is
an override, for a machine whose tailscaled the daemon's user cannot
read or a name other than its MagicDNS one. Either way the listener
(daemon.webhook_enabled) has to be bound on the tailnet
(daemon.tailscale): a job is refused rather than sent with an
address nothing answers on.

*** =grok.job_ttl_minutes=

- Type :: integer
- Default :: =120=
- Since :: 0.10.0

How long a job may go unanswered before it is given up.

Longer than the half hour an unattended Grok run's approval card
waits, because a run that stalls on one is the usual reason a
report is late. When it lapses the agent is told, with Grok's run
id, and a report arriving afterwards is refused. A job may ask for
less or more; this is the default.

*** =grok.attention_days=

- Type :: integer
- Default :: =3=
- Since :: 0.52.0

Days a job that needs somebody keeps counting on the Grok badge.

A job that failed, was refused, expired or asked for input needs
somebody. It counts on the badge for this many days after it
settled, then stops asking -- it stays listed until it is removed
or grok.retention_days passes. 0 means it counts until it is
removed. Clamped to 0..365.

*** =grok.retention_days=

- Type :: integer
- Default :: =30=
- Since :: 0.52.0

Days a settled job is kept for the Grok page and `grok jobs`.

Pruned at start and then hourly. A job still open is never pruned:
it expires through grok.job_ttl_minutes first, and its agent is
told. Clamped to 1..3650.

** =routines=

Standing work: a prompt, an agent, and when to run it.

A routine is the thing you would otherwise remember to ask for every
morning. It runs as a delegated task, so it has its own result.

It does not get a session of its own. libreclaw keys a session on
channel, room and sender and deliberately ignores the thread, so a
routine lands in the operator's session and queues behind whatever
the operator is doing -- and inherits that conversation's context.
Point a routine at an agent that is not also somewhere you chat, or
give it `isolate` so it runs in a room of its own.

Routines only fire while the daemon is running. A machine that was
asleep at nine o'clock has missed nine o'clock, and the routine says
so rather than pretending otherwise -- see `catch_up`.

*** =routines.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

What this routine is called, and how it is referred to.

*** =routines.description=

- Type :: string
- Default :: unset
- Since :: 0.2.0

One line about what it is for, for a person reading the list.

*** =routines.instructions=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

What the agent is asked to do, in full.

Sent as the whole of the prompt, so it should read as an instruction
rather than a reminder: the agent has no memory of the last run and
nobody is there to answer a question about what was meant.

*** =routines.agent=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

Which agent runs it.

*** =routines.model=

- Type :: string
- Default :: unset
- Since :: 0.7.7

The model this routine's run uses, instead of the agent's own.

For that one turn only: the agent's next turn is back on its own
model. A scheduled check that reads a page and compares a number does
not need the model the agent plans with, and a run costs what its
model costs. A model name for the agent's provider, as in
`agents.model.model`; like that key it is not checked against the
catalogue, which goes stale, so a name the provider does not know
fails the run rather than the save. Empty is the agent's own model.

*** =routines.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether it runs on its schedule. A disabled routine can still be
started by hand, which is how you try one before trusting it.

*** =routines.schedule=

- Type :: enum
- Values :: manual, hourly, daily, weekdays, weekly, custom
- Default :: =daily=
- Since :: 0.2.0

manual, hourly, daily, weekdays, weekly or custom.

All of them become a cron expression, including the presets -- so
there is one answer to "when does this next run" rather than two.

*** =routines.at=

- Type :: string
- Default :: =09:00=
- Since :: 0.2.0

The time of day, for daily, weekdays and weekly.

Local time, because somebody who wrote 09:00 means nine o'clock where
they are. With `hourly` only the minute is used.

*** =routines.weekday=

- Type :: string
- Default :: =monday=
- Since :: 0.2.0

Which day, for `weekly`.

*** =routines.cron=

- Type :: string
- Default :: unset
- Since :: 0.2.0

The expression, for `custom`: minute hour day-of-month month day-of-week.

Ranges, lists and steps all work, and months and weekdays may be
named. Note the oldest oddity in cron: when *both* day fields are
restricted the match is day-of-month OR day-of-week, so `0 0 13 * 5`
is the thirteenth and every Friday, not Friday the thirteenth.

*** =routines.directory=

- Type :: path
- Default :: unset
- Since :: 0.2.0

Where to run, if not the agent's workspace.

A path on the agent's computer, which for a container or a VM is a
path inside it and not on the host.

*** =routines.worktree=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Run in a fresh checkout of `directory` rather than in it.

For a routine that changes files: it keeps a scheduled run from
landing on top of whatever you had checked out at the time. Since
0.39.0 clawtilla makes the checkout itself, for each run, in the
agent's workspace at tasks/<task> on the branch clawtilla/<task> (a
git worktree, or a local clone for a confined or containerised agent),
and tells the agent where it is; the run fails if it cannot be made.
The run's Changes show what it did, and the checkout is removed after
orchestration.checkout_keep_days with its branch kept.

*** =routines.isolate=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Give this routine a conversation of its own.

A run is sent from `user` to the agent by default, so it lands in the
operator's room from the operator's sender -- and libreclaw keys a
session on channel, room and sender. One session, one queue: Monday's
run is in Tuesday's context, a 09:00 brief starts whenever the agent
next goes idle, and both happen in the operator's transcript.

Set this and the run goes to a room of its own from a sender of its
own, which is a session of its own: no shared context, no waiting
behind a conversation. The cost is that the prompt and the answer are
no longer in the operator's chat -- they are in the task result and on
the Flow tab, which is where a delegated task's output already lives.

Off by default because moving somebody's output is not a thing to do
to them silently. Pointing the routine at an agent nobody talks to
solves the same problem and needs no setting.

*** =routines.read_only=

- Type :: boolean
- Default :: =false=
- Since :: 0.4.0

Run with read-only tools: the agent may look at anything it can reach
and change nothing -- no messages, no writes, no commands, no screen.

The run gets a room of its own (as routines.isolate does) and every
turn in that room is offered only clawtilla's read tools; its own
tools are refused through the PreToolUse hook. That hook exists only
for claude-code and claude-tmux, so a read-only routine on any other
backend is refused rather than run with its own tools unchecked.
What it finds it reports with clawtilla_ask_decision.

*** =routines.proactive=

- Type :: boolean
- Default :: =false=
- Since :: 0.4.0

Look for ways to help, unasked, and report them without acting.

Implies read_only. With no instructions, the agent is told to go
through what it is connected to -- its integrations and connectors --
for anything that needs attention, and to file each finding as a
decision for the operator rather than acting on it.

*** =routines.catch_up=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Run once at startup when its time passed while the daemon was down.

Off by default, and worth leaving off for anything that talks to
somebody: a laptop opened after a long weekend would otherwise deliver
a stack of good mornings at once. Only ever one run, however many
were missed.

*** =routines.jitter_seconds=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

Delay each run by up to this many seconds, chosen at random.

Zero here, unlike a hosted scheduler, because there is no shared
server to spread load across: this is your machine, and a routine set
for 09:00 should run at 09:00. Worth setting only when several
routines share one rate-limited service.

Only a scheduled run is delayed. `clawtilla routine run` starts at
once, because somebody waiting at a terminal is not load to spread;
so does a catch-up, because a run that was already missed does not
need to be later still.

*** =routines.max_start_failures=

- Type :: integer
- Default :: =3=
- Since :: 0.13.0

Turn the routine off after this many runs in a row whose computer
did not start. 0 never turns it off.

A dead VM or a missing image otherwise fails the routine on every
tick, and nobody hears about it. At the limit the routine is turned
off -- `enabled: false`, so it shows as off everywhere and is turned
back on the same way -- and an alert names the routine and the
computer's error. The count is run state, kept beside the config and
never in it. Any run whose computer starts sets it back to zero, and
so does editing the routine; a run that began before the edit is not
counted. A negative value reads as the default.

*** =routines.locked=

- Type :: boolean
- Default :: =false=
- Since :: 0.7.1

Keep the agent from changing or removing this routine.

An agent with tools.schedule may adjust the routines that run on it --
move a check, split one, drop one it no longer needs. Lock the ones
that are yours to decide: it can still read a locked routine, and it
is told why a change was refused rather than left guessing. Only a
client or the config can set or clear this; an agent cannot.

** =triggers=

Work started by something happening elsewhere.

A routine is a clock; a trigger is an event. Both end in the same
queued run against the same agent, so a trigger inherits the
routine's ordering behind a busy agent and its durable receipts
rather than growing a second set.

*** =triggers.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

How the trigger is named on the command line and in the clients.

Not the address it is called on: that is a separate unguessable
endpoint, so renaming a trigger does not tell anybody where it
lives.

*** =triggers.description=

- Type :: string
- Default :: unset
- Since :: 0.2.0

What this trigger is for, in a line.

*** =triggers.agent=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

Primary agent to run when it fires.

*** =triggers.agents=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Additional recipients for the same delivery. The primary agent runs first;
duplicates are removed in order. Every recipient has a separate durable
task and outcome. A batch must fit the trigger's max_pending slots in
full.

*** =triggers.room=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Where the run reports, if not the agent's own conversation.

*** =triggers.mode=

- Type :: enum
- Values :: run, post
- Default :: =run=
- Since :: 0.15.0

What a delivery that passed every filter turns into: run or post.

run starts the agent with the expanded instructions, which costs a
turn. post writes the instructions and the event into `room` as a
system message and runs nothing -- for the deploy that finished or
the monitor that fired, which somebody wants to see and no agent
needs to act on. A post wakes nobody and costs nothing.

post needs `room`: a trigger set to post with no room is refused at
load, and refuses every delivery until one is named.

*** =triggers.max_pending=

- Type :: integer
- Default :: =4=
- Since :: 0.15.0

How many runs this trigger may have unfinished at once, 1 to 50.

A push that fires a five-minute run, twenty times while the first is
still going, is twenty agents on one machine. A delivery past the cap
is answered 429, so the sender retries it later, and recorded as
dropped in the trigger's deliveries -- never silently. Every recipient
of a fan-out takes a slot. A value outside 1 to 50 written by hand is
read as the default, with a warning at load.

*** =triggers.provider=

- Type :: enum
- Values :: generic, forgejo, gitea, github, gitlab, venture
- Default :: =generic=
- Since :: 0.2.0

Who is calling: forgejo, gitea, github, gitlab, venture or generic.

This decides how the delivery is authenticated, and the four forges
genuinely disagree. Forgejo and Gitea sign the body with HMAC-SHA256
and send the hex bare; GitHub sends the same digest behind a
`sha256=` prefix; GitLab sends the secret itself, verbatim, and
signs nothing.

Naming it matters because Forgejo also sends GitHub- and
Gitea-shaped headers for compatibility. Sniffing is a fallback for
when nobody said, and it can never widen what a configured trigger
accepts.

venture is VENTURE's own webhook: the same `sha256=` HMAC as GitHub
under X-Venture-Signature, so the webhook must be created with this
trigger's secret as its signing secret. Its record type fills
{{kind}}, the record's label {{title}}, its id {{number}} and the
user who made the change {{actor}}.

*** =triggers.secret=

- Type :: secret reference
- Default :: unset
- Since :: 0.2.0

The shared secret the caller proves it knows.

Shown once, when it is created or rotated, and never again -- not in
a listing, a log line, an event or a transcript. Rotating it stops
the old one working immediately.

*** =triggers.events=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Which event names are acted on. Empty means all of them.

An event outside the list is answered normally and recorded as
ignored, because a caller that gets an error for a delivery you
simply did not want will keep retrying it.

*** =triggers.repo=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Only act when the delivery names this repository.

*** =triggers.branch=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Only act when the delivery names this branch.

*** =triggers.header=

- Type :: string
- Default :: unset
- Since :: 0.2.0

For `provider: generic`, the header carrying the event name.

*** =triggers.ignore_actors=

- Type :: list of strings
- Default :: unset
- Since :: 0.9.3

Changes made by these users are recorded as ignored, not run.

The loop guard. An agent that writes what its own trigger watches --
a VENTURE ticket it updates, a branch it pushes -- is called back by
its own write, and the sender cannot tell: to it every write is an
ordinary user's change. Name the account the agent's credential
belongs to. Matched against {{actor}}, ignoring case.

** =triggers.match=

Fields the delivery's JSON body must contain, or it is ignored.

  match:
    - path: pull_request.title
      value: release
    - path: labels.name
      value: deploy

Up to 10 pairs, and all of them must match. The path is dotted; a
number indexes an array (`commits.0.message`), and a name on an array
looks in every element (`labels.name`). The value must be contained in
what the path holds, ignoring case. Checked before anything is queued:
a miss is recorded in the deliveries as ignored, naming the pair that
failed, and starts no run. Empty, or null, means no filter.

*** =triggers.match.path=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.15.0

Where in the JSON body to look, dotted, such as `repository.name`.
No spaces, no `=` and no empty part; a bad path is refused at load.

*** =triggers.match.value=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.15.0

Text the field must contain, ignoring case. An object or array is
searched as its JSON text.

*** =triggers.replay_connector=

- Type :: string
- Default :: unset
- Since :: 0.9.3

venture: the connector whose credential reads the business-event
feed, so deliveries missed while the daemon was down are caught up.

The name of a `venture` connector integration bound to this
trigger's agent. Its token must belong to an owner or administrator
of the organization, which is who VENTURE lets read the feed. The
feed is read every poll interval and replayed through the same
deduplication as a pushed delivery, on the event's stable id, so a
delivery that arrives both ways runs once.

The first read only finds where the feed ends: replaying an
organization's whole history into an agent is never what somebody
turning this on meant. Only the durable lane (`business_events` on
the VENTURE webhook) has a feed; ordinary record webhooks are never
retried by VENTURE and cannot be caught up.

*** =triggers.organization_id=

- Type :: integer
- Default :: =0=
- Since :: 0.9.3

venture: which organization's business events to replay.

The `organization_id` VENTURE scopes every request by. 0 sends none,
which VENTURE answers for the token's default organization.

*** =triggers.instructions=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

What the agent is asked to do, with the event fenced beneath it.

Placeholders -- {{event}}, {{repo}}, {{ref}}, {{actor}}, {{title}},
{{url}}, {{number}}, {{kind}} -- are expanded by hand rather than by a format
function, because this string comes out of a configuration file and
a stray percent sign must be a percent sign.

The payload arrives marked as untrusted, and the agent is told to
read it as data: a webhook body is somebody else's text.

*** =triggers.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether it fires.

A new trigger starts unverified: the first authenticated delivery is
captured and shown to you rather than run, so you can see what the
caller actually sends before an agent acts on it.

*** =triggers.directory=

- Type :: path
- Default :: unset
- Since :: 0.2.0

Where the run should work, if somewhere particular.

*** =triggers.worktree=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Run in a fresh checkout of `directory` rather than in it.

Since 0.39.0 clawtilla makes the checkout for each run, as for
routines.worktree: in the agent's workspace at tasks/<task>, on the
branch clawtilla/<task>, and tells the agent where it is above the
trigger's payload. The run fails if it cannot be made.

*** =triggers.isolate=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Give the run a conversation of its own rather than the agent's.

** =agents=

The fleet.

Each entry is one libreclaw agent: its persona, its model, its
credentials, its integrations and its computer. This file is the source
of truth -- the daemon renders each agent's libreclaw config.yaml into
its workspace from what is here, and regenerates it when this changes.

An agent whose block cannot be understood becomes a shadow: it is
listed, it says why, and it refuses to run. That is what lets a config
written by a newer clawtilla round-trip through an older one without
losing anything.

*** =agents.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.1.0

Identifier used everywhere else to address this agent. Must be unique.

*** =agents.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Display name shown in the clients and used as the agent's own name.

*** =agents.description=

- Type :: string
- Default :: unset
- Since :: 0.1.0

One line about what this agent is for.

Other agents see it when they list the fleet, so it is how a
chief-of-staff decides who to delegate to. Worth writing properly.

*** =agents.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether this agent may run at all.

*** =agents.chief_of_staff=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Marks the agent that receives work addressed to the fleet.
At most one agent may hold this.

*** =agents.color=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Accent colour in the clients, as a hex string.

*** =agents.order=

- Type :: integer
- Default :: =0=
- Since :: 0.1.0

Where this agent sits in the list, lowest first.

Set by dragging a row in the clients rather than written by hand,
though there is nothing wrong with writing it. Agents sharing a
number keep the order they appear in this file, so leaving them all
at 0 changes nothing.

*** =agents.review_by=

- Type :: string
- Default :: unset
- Since :: 0.38.0

Who checks this agent's work before it counts as done.

`lead` (its team's lead, or the chief of staff when the team has
none), `delegator` (whoever handed it the task), `operator` (you,
from the decision inbox or any client's task page), an agent id, or
empty for no review. When the agent finishes a task it goes to
`review` with the result instead of `completed`, and only an accept
completes it; asking for changes sends it back with the notes, and
after orchestration.review_rounds of that the operator decides. A
delegation's own `review:` and an operator task's `review` override
this. The reviewer is never the agent itself: a setting that would
make it so means no review.

*** =agents.team=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Which team this agent belongs to, by teams.id.

Unset means no team: the agent still messages and is messaged, it is
simply not grouped and no team lead may assign to it.

*** =agents.broker_server=

- Type :: string
- Default :: unset
- Since :: 0.24.0

This agent's own gateway server on the broker.

For anythingmcp, the id of an MCP server made in its dashboard (the
last part of the server's MCP URL); the connectors assigned to that
server are this agent's permission, and clawtilla reaches it as the
connector broker-agent-<id>. For jentic, the Jentic agent this one
acts as, whose API key `clawtilla broker key <id>` stores. Unset
means the team's teams.broker_server, or no broker at all. An agent
with runtime.network gated or none cannot reach the gateway on
loopback and is not given it.

*** =agents.team_role=

- Type :: enum
- Values :: member, lead
- Default :: =member=
- Since :: 0.1.0

Standing within that team.

A lead may hand work to the members of its own team and to nobody
else. A member may message, ask and share a room with anyone --
handing something over in conversation is not assigning it -- but may
not delegate at all.

At most one lead per team; a second is refused rather than picked
between. The chief of staff outranks every lead and needs no team.

*** =agents.avatar=

- Type :: path
- Default :: unset
- Since :: 0.1.0

The agent's profile picture. Optional, and usually unnecessary.

A file called profile-picture.png, .jpg, .jpeg or .webp in the
agent's own directory is found without being configured, which is
the expected way to set one: drop the file in and it appears. This
key is for pointing somewhere else, and is resolved against the
workspace when it is relative.

A path named here that does not exist warns and falls back to the
initials, rather than falling back silently -- a mistyped path and
no picture at all otherwise look identical.

The picture reaches a client as bytes, never as a path, because a
client may be running on another machine.

*** =agents.skills=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Skills this agent gets, on top of its team's and the fleet's.

Named, not paths: a skill lives once under `skills.dir` and is
linked into the workspace at whatever path this agent's provider
reads. A selector naming a skill that does not exist warns rather
than silently reaching nobody.

An imported skill arrives disabled and stays that way until somebody
has read it, so assigning one is not the same as the agent having it.
Both states are reported.

*** =agents.workspace=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Workspace directory. Defaults to defaults.workspace_root/<id>.
Scaffolded on first start if it does not exist.

** =agents.persona=

Who the agent is.

*** =agents.persona.system_prompt=

- Type :: string
- Default :: unset
- Since :: 0.1.0

System prompt, inline. Mutually exclusive with identity_files.

*** =agents.persona.identity_files=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Files in the workspace concatenated into the system prompt, in order.

Leave it unset to get the standard set, which is what every workspace
is scaffolded with: SOUL.org for character, IDENTITY.org for role,
USER.org for who you are, AGENTS.org for how to work, TOOLS.org for

Set it to take control of the list: to reorder, to drop one, or to add
a file of your own. An inline system_prompt replaces the lot.

*** =agents.prompt_suffix=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Text appended to every turn this agent runs.

For a rule that has to hold on turn 200 as much as turn 1. A resumed
session never re-receives the system prompt, and a long conversation
drifts away from anything said only once at the start.

clawtilla already adds one of its own for an agent with a computer,
naming the container or VM and telling it to run commands there
rather than on the host. Yours is appended to that, not instead of
it.

Costs tokens on every turn, so keep it to rules that genuinely have
to be repeated -- anything else belongs in the agent's org files.

** =agents.model=

*** =agents.model.model=

Model name. Defaults to defaults.model.

*** =agents.model.effort=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Reasoning effort: low, medium, high, xhigh or max, when the model has one.

*** =agents.model.command=

- Type :: string
- Default :: unset
- Since :: 0.28.0

The command line an acp agent is started from, e.g.
"gemini --experimental-acp". Only read when model.provider is acp.

acp runs any program that speaks the Agent Client Protocol (v1,
JSON-RPC over stdio) as the agent's engine, so which program is this

fails saying so.

(or its command line) chooses.

*** =agents.model.routing_profile=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Reserved. Not implemented in this build: nothing reads it, and
nothing will until it can mean something here.

libreclaw's smart routing (off, eco, auto, premium, free) picks a
model per message by scoring the prompt against a price table of

so there is nothing for a profile to choose between -- rendering it
would switch on a router with a single candidate. Moving off a
backend that refuses is model.fallbacks; a cheaper model for one
scheduled job is routines.model.

** =agents.model.fallbacks=

Where this agent's conversations continue, in order, when its own
backend refuses a turn: a usage limit, a rate limit, a sign-out or
an outage.

  fallbacks:
    - provider: codex-cli
      model: gpt-5.5
    - provider: claude-code
      model: sonnet

libreclaw does the failing over: the next turn runs on the first
entry nothing is holding, and the agent returns to its own backend
at the reset the provider named, or after a backoff when it named
none. A move to another CLI or another login starts a fresh
conversation there; the agent's own conversation resumes when it
comes back. Each switch raises an agent.failover event and alert,
and agent status shows the fallback until the agent is back.

Another sign-in to the same subscription is refused: an entry on
this agent's CLI (claude-code and claude-tmux are one Claude login)
with a different account, unless that account has pay_per_use set.
Rotating accounts to get past a usage limit breaks the provider's
terms. The agent is a shadow with the reason until the list is
fixed, and agent set refuses such a list where it arrives.

On the command line the list is one string:
`clawtilla agent set ID model.fallbacks "codex-cli:gpt-5.5,
claude-code:sonnet@backup"` -- provider:model, then @account.

*** =agents.model.fallbacks.provider=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.16.0

The agent CLI: one of the providers model.provider takes.

*** =agents.model.fallbacks.model=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.16.0

The model that CLI is asked for.

*** =agents.model.fallbacks.account=

- Type :: string
- Default :: unset
- Since :: 0.16.0

Which entry of accounts this fallback's CLI logs in as. Unset is the
CLI's default login. The account's provider must be this entry's
provider.

*** =agents.steer=

- Type :: enum
- Values :: never, delegator, peers, all
- Default :: =delegator=
- Since :: 0.28.0

Which messages may be handed to the turn this agent is already
running, instead of waiting to become a turn of their own.

Without steering, a message for a busy agent waits and becomes its
next turn: a correction ("stop, use the staging DB") arrives after
the work it was meant to change has finished, and a follow-up costs a
whole extra turn that rereads everything. A steered message reaches
the running turn at the next point its engine accepts input -- before
the next model call -- and the turn's closing answer answers it too.
Nothing is killed or restarted.

never: nothing steers. delegator, the default: a message steers when
its sender handed out the work the running turn is on -- the agent
that turn is answering, or the delegator of the task it is working.
peers: as delegator, and any other agent's message in the same room.
all: as peers, and your own message in your conversation with this
agent (otherwise held and sent when the turn ends).

No level lifts these: a message never steers into another room's
turn; never into a consultation unless the consulting agent is asking
again, and a consultation never steers into a turn that can act; a
result held for the end of a turn, a message naming another task or
a model of its own, and anything in a group room take turns of their
own. A steered message is still a hop and still passes the loop guard
when it is sent.

Only some engines can be steered: Claude Code, claude-tmux and codex
on libreclaw's ai.codex.transport app-server. On any other the agent
says no and the message waits as before. Needs libreclaw 0.30.0 or
later; an older agent is never asked.

** =agents.session=

How this agent's conversations map to AI sessions.

*** =agents.session.routing_mode=

- Type :: enum
- Values :: sender-room, room, agent
- Default :: =sender-room=
- Since :: 0.2.0

How many context windows this agent is.

sender-room, the default, gives every (room, sender) pair a session
of its own: the conversation with the operator, the conversation
with each peer, each a separate AI context that shares nothing with
the others. room drops the sender, so everybody in one room shares
a session. agent is one session for everything -- every room, every
sender, one conversation.

The default suits an agent that serves several people and should
keep them apart. It is the wrong shape for an orchestrator: a chief
of staff told "only use oryx" in the operator's room has never
heard that constraint when a peer's reply wakes the sibling session,
and what looks like one agent contradicting itself is three contexts
that have never met. Give such an agent agent mode. The cost is
concurrency -- one session runs one turn at a time, so three busy
rooms take turns -- and the mode changes every session key, so each
conversation starts a fresh context once when it is switched.

The values are libreclaw's own (its session.routing_mode); the
daemon renders this straight through.

The default is role-dependent: an agent marked chief_of_staff --
on the agent or through orchestration.chief_of_staff -- or given
team_role: lead defaults to agent mode, because an orchestrator's
job assumes the shape. An explicit value here always wins, and
dropping the role restores the ordinary default; toggling a role
never writes this key on your behalf.

A member of a room with more than two members defaults to room
mode instead, and sender-room is refused for one. That mode gives
an agent a session per speaker in the same room, and every piece
of the daemon's per-room turn state is keyed on the room alone --
the typing indicator carries the room and not the session, so two
such turns cannot be told apart: the second to start would run
holding the first one's depth and origin, and the first to finish
would settle both. It is reported and replaced with room rather
than refused, because refusing would take the agent out of the
fleet over a setting.

*** =agents.session.timeout_minutes=

- Type :: integer
- Default :: =30=
- Since :: 0.7.5

Minutes of inactivity before libreclaw drops this agent's session.

The next message after the timeout starts a fresh context rather
than continuing the old one. -1 means never expire: the session
lives as long as the agent does, and the tradeoff is one context
that only ever grows until the provider compacts it or somebody
runs /reset. 0 and anything below -1 are meaningless to libreclaw's
own session manager, which takes only a positive number of minutes
or -1: `clawtilla config validate` rejects such a value, and if one
reaches the daemon anyway it is reported with a warning and
replaced with 30 in the rendered config.

This is libreclaw's own value (its session.timeout_minutes); the
daemon renders this straight through.

** =agents.runtime=

How this agent's libreclaw instance is hosted.

*** =agents.runtime.type=

- Type :: enum
- Values :: process, embedded
- Default :: =process=
- Since :: 0.1.0

process or embedded.

process supervises a real libreclaw child: crashes stay contained, the
environment and credentials are genuinely separate, and the agent can
live inside its own container. embedded runs it inside the daemon,
which is cheaper and is what an in-process host such as cmacs wants, at
the cost of sharing a fate with every other embedded agent.

*** =agents.runtime.confine=

- Type :: enum
- Values :: none, bwrap
- Default :: unset
- Since :: 0.14.0

Run this agent's own CLI inside a bubblewrap sandbox: none or bwrap.
Defaults to defaults.confine.

computer.host.confine governs clawtilla_computer_exec and nothing
else. The agent's own Bash, Read and Write belong to the AI CLI that
libreclaw spawns, and without this they reach the whole filesystem as
the daemon's user. bwrap wraps the libreclaw child -- and so the CLI,
every command it runs and its MCP servers -- in one sandbox that
binds the workspace and the agent's state directory read-write, the
CLI's login directory read-write (it refreshes its OAuth tokens there),
the agent's mounts as declared, the programs its .mcp.json names
read-only, and the daemon's sockets. /usr and /etc are read-only, /tmp
and $HOME are private and empty apart from those binds, and TMPDIR,
HOME and XDG_* are set by the sandbox -- an agent's env: cannot point
them somewhere else. The network is left alone.

Only runtime.type: process can be confined; bwrap with embedded
disables the agent. bubblewrap missing disables it too, with the
reason, and it is never started unconfined instead. Takes effect at
the agent's next start.

*** =agents.runtime.confine_paths=

- Type :: list of strings
- Default :: unset
- Since :: 0.14.0

More paths to bind read-only into a confined agent's sandbox.

The sandbox finds libreclaw, the AI CLI and the programs in .mcp.json
for itself. A CLI installed somewhere it cannot follow -- a node
under ~/.nvm, a tool a skill shells out to -- is named here. Read-only
on purpose: something the agent should write is a mount, which says
so in its mode. Ignored unless runtime.confine is bwrap.

*** =agents.runtime.network=

- Type :: enum
- Values :: open, gated, none
- Default :: =open=
- Since :: 0.17.0

Where this agent's own process may connect: open, gated or none.

open shares the machine's network, LAN and tailnet included. gated
gives the sandbox no network of its own: its only route is
clawtilla's egress gate, an HTTP proxy reaching public addresses only
(plus egress.allow), handed to the CLI as HTTPS_PROXY and HTTP_PROXY.
none gives it no route at all.

Under gated or none, provider keys whose CLI can be pointed elsewhere
(ANTHROPIC_API_KEY for Claude Code, OPENAI_API_KEY for Codex) are
brokered: the agent holds a token for its own process, and the daemon
swaps it for the real key on the way to a fixed upstream. Others are
passed as before and listed as unbrokered. An OAuth login is
unaffected.

Anything but open needs runtime.confine: bwrap -- outside the sandbox
a process can ignore a proxy -- and without it the agent is disabled
with that reason, never run on an open network instead. Takes effect
at the agent's next start.

*** =agents.runtime.autostart=

- Type :: boolean
- Default :: unset
- Since :: 0.1.0

Start with the daemon. Defaults to defaults.autostart.

*** =agents.runtime.restart=

- Type :: enum
- Values :: never, on-failure, always
- Default :: unset
- Since :: 0.1.0

never, on-failure or always. Defaults to defaults.restart.

*** =agents.runtime.backoff_seconds=

- Type :: integer
- Default :: =5=
- Since :: 0.1.0

Base delay before a restart, doubling on each consecutive failure.

*** =agents.runtime.max_restarts=

- Type :: integer
- Default :: =10=
- Since :: 0.1.0

Consecutive failures before the agent is left in error rather than
restarted again. 0 means never give up.

*** =agents.runtime.stream_steps=

- Type :: boolean
- Default :: unset
- Since :: 0.2.0

Report this agent's steps while its turn runs. Defaults to
defaults.stream_steps.

*** =agents.runtime.process_timeout_ms=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

Maximum elapsed milliseconds for one AI CLI subprocess, including
streaming turns. 0, the default, disables the limit so an agent can
work for several hours. Set a positive integer to opt into a deadline.
Rendered explicitly as libreclaw ai.process_timeout_ms for every agent.
The tmux provider uses its own command and inactivity bounds instead.
This is a duration limit; runtime.turn_timeout_seconds separately
controls the turn watchdog. Values must be between 0 and 2147483647.

*** =agents.runtime.idle_stop_hours=

- Type :: integer
- Default :: =0=
- Since :: 0.8.0

Stop this agent after this many hours without a turn. 0 never does.

An idle agent still holds its process, its ports and its computer.
Stopped this way it is woken again by the next message queued for
it -- from you, a routine, a trigger or another agent -- so sleeping
loses no conversation; the message waits in its mailbox while it
starts. An agent that has never taken a turn is measured from when
it started. Stopping it by hand is not this: it stays stopped.

*** =agents.runtime.turn_timeout_seconds=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

How long a turn may go without producing anything before it is
cancelled. 0, the default, disables it.

Off by default because the number was always a guess, and the guess
was wrong in the expensive direction: a twenty-minute ceiling killed
real work -- a long refactor, a slow test suite -- and reported it
as a wedged turn. Every step an agent takes now counts as activity,
so a turn that is working says so continuously and a person can see
a stalled one rather than having a timer guess for them.

Set a number to bring the watchdog back. It counts activity, not
duration: a turn may legitimately run for an hour while steps keep
arriving, and one that has produced nothing at all for this long is
wedged. A turn parked on a decision is exempt, because waiting for a
person is not a stall.

Watched in two places, on purpose. The daemon watches activity and
publishes turn.timed_out; the same number is rendered into the
agent's own session.watchdog_timeout_seconds. That inner watchdog
measures total duration, even while output arrives or a decision is
pending; a positive value therefore also caps the whole turn -- at
this number plus runtime.busy_max_seconds while the busy check
(runtime.busy_cpu_percent) is on, and not at all when that ceiling
is 0.

*** =agents.runtime.first_reply_seconds=

- Type :: integer
- Default :: =20=
- Since :: 0.26.0

How long a turn may show nothing at all -- no step, no thought, no
reply -- before the clients offer to stop it or to run the same
message on another model. 0 never offers.

Nothing is stopped by this; it is an offer, shown beside the
conversation and withdrawn the moment the turn shows anything. It
needs runtime.stream_steps, since a turn whose steps are not
streamed is silent until it answers whether or not it is working.

Silence here is what the daemon can see, which is less than what the
CLI is doing: libreclaw does not forward the CLI's own status lines,
and holds prose until a tool call or the end of the turn. So the
offer says the turn has shown nothing, never that it is stuck. The
models offered are the model.fallbacks entries on the agent's own
CLI and login, since one turn's model is a name on the CLI it is
already running.

*** =agents.runtime.busy_cpu_percent=

- Type :: integer
- Default :: =5=
- Since :: 0.26.0

How much CPU the agent's processes must use, in percent of one core,
for a silent turn to count as working. 0 turns the check off.

A turn running one long command -- a test suite, a build -- reports
nothing between the tool starting and the tool finishing, so
runtime.turn_timeout_seconds would read forty minutes of compiling as
a wedged turn. Each watchdog sweep (every five seconds) reads the CPU
time of the agent's process tree from /proc; a tree that used at
least this much since the last sweep counts as a sign of life. A
command waiting on the network uses none and is still stopped.

Only for runtime.type: process. An embedded agent shares the daemon's
process, so its tree cannot be told apart from the fleet's and the
check does nothing there. Nothing is read while
runtime.turn_timeout_seconds is 0.

*** =agents.runtime.busy_max_seconds=

- Type :: integer
- Default :: =7200=
- Since :: 0.26.0

The longest a busy process tree may keep a silent turn alive, in
seconds since the turn last reported anything. 0 is no ceiling.

A command stuck in a loop uses CPU too, and without a ceiling it would
hold its turn for ever. Past this many seconds with no step, message
or tool call the CPU stops counting and runtime.turn_timeout_seconds
applies as it would to any silent turn.

*** =agents.computer.use=

- Type :: string

Share a machine declared under computers: instead of having one of

*** =agents.computer.type=

- Type :: enum

- Default :: unset
- Since :: 0.1.0

Which kind of computer this agent gets. Defaults to

*** =agents.computer.start=

- Type :: enum
- Values :: on_agent_start, on_first_use
- Default :: =on_agent_start=
- Since :: 0.19.0

When the machine is started: with the agent, or the first time
something runs in it.

on_agent_start brings the computer up before the agent's first turn,
so a broken image or a dead libvirtd stops the agent at once, with the
reason, instead of a turn later. That is the default, and what every
agent did before this key existed.

on_first_use leaves it down until the first clawtilla_computer_exec,
`computer exec`, wait condition or desktop call. The agent's own bash,
read and write run on the host either way, so an agent that mostly
talks, plans or delegates never pays for a VM it does not touch.
Callers that arrive while it is coming up share the one start, and
the time it takes is not counted against the command's timeout.

is a local check and always starts with the agent. A computer stopped
by hand under a running agent is started again by its next use.

An agent with a VM desktop is the exception in practice: its MCP
client asks for the desktop when the agent starts, and that request
is a use.

*** =agents.computer.exchange=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether the shared exchange directory is visible to this agent.

On by default, because otherwise every pair of agents that wants to

*** =agents.computer.workspace=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether the agent's own workspace is mounted into its computer at
/mnt/clawtilla/workspace.

On by default. The workspace holds the agent's persona, its notes and
its MEMORY.md, and without this it exists only on the host -- so the
agent reads the files that describe it with one set of tools and
works in a machine that cannot see them, and anything it writes there
from inside goes somewhere the host never looks.

Turn it off for an agent whose computer should hold nothing of
clawtilla's.

*** =agents.computer.default_mounts=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether this agent gets the fleet's shared folders from
defaults.mounts.

On by default -- that is what makes them defaults. Turn it off for an
agent that should see only what it declares itself, which is the
point of giving one a container in the first place.

Declining all of them is different from replacing one: an agent that
declares its own mount at the same target already wins there, with
no need to turn the rest off.

** =agents.computer.mounts=

*** =agents.computer.mounts.type=

- Type :: enum
- Values :: none, shared, private
- Default :: =shared=
- Since :: 0.1.0

*** =agents.computer.host.confine=

- Type :: enum
- Values :: none, workspace, allowlist, bwrap
- Default :: =workspace=
- Since :: 0.1.0

How much of the machine the agent may touch.

  workspace  cwd pinned to root; every path in the command line is
             canonicalised and rejected if it escapes
  allowlist  root plus allow_paths, minus deny_paths
  bwrap      a real kernel sandbox via bubblewrap
  none       no restriction at all

running it, which closes '..' and symlink escapes together. They do not
stop a program that opens paths itself once it is running. Only bwrap
does, because only bwrap involves the kernel.

All of it applies to clawtilla_computer_exec. The agent's own bash,
read and write tools are its CLI's, and that CLI is not wrapped: they
reach the whole filesystem as the user running the daemon whatever
this is set to. That is true of every computer type -- only exec
enters the computer -- but host is the type where the setting reads
like a boundary around the agent rather than around one tool.

If bwrap is asked for and not installed, the agent becomes a shadow with
that as its reason. It is never silently downgraded.

*** =agents.computer.display.allow_spawn=

- Type :: boolean
- Default :: =true=
- Since :: 0.51.0

Whether the agent may start apps on its display with display_launch.

Off leaves it the apps in computer.display.startup and whatever it
starts through clawtilla_computer_exec, which is its own setting.

*** =agents.computer.display.gowl_binary=

- Type :: path
- Default :: unset
- Since :: 0.51.0

A gowl to run instead of searching /usr/bin, /usr/sbin and PATH.

For when the first gowl found is not the one wanted -- an old build in
/usr/local/bin that cannot load its wlroots, say. It must answer
--version or it is not used.

** =agents.computer.container=

Settings for computer.type: container.

*** =agents.computer.container.image=

- Type :: string
- Default :: =registry.fedoraproject.org/fedora:45=
- Since :: 0.1.0

Image the container is created from.

Any reference podman can pull. Unset means defaults.container_image.

Name the registry: a bare 'fedora:45' is resolved through podman's
unqualified-search list, which is per-machine, so the same config can
pull a different image on two hosts.

*** =agents.computer.container.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Container name. Defaults to clawt-<agent-id>.

*** =agents.computer.container.connection=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Podman connection: a socket path, ssh://user@host/socket, tcp://host:port,
or a named connection. Defaults to the user's podman socket.

*** =agents.computer.container.command=

- Type :: string
- Default :: =sleep infinity=
- Since :: 0.1.0

What the container runs.

The default keeps the container alive, because a container computer
exists to be exec'd into: a plain base image's entrypoint exits the
moment it starts, and an agent whose container has already gone is an
agent whose every command fails for no visible reason.

Set it when the image has an entrypoint worth running. A JSON array is
used as-is; anything else is split on spaces.

*** =agents.computer.container.network=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Network to attach to. Leave unset for podman's default.

Not implemented in this build. The value reaches the container object
through clawt_container_computer_set_network() and stops there: the
podman create request is built without it, so the container is always
on podman's default network however this is set.

*** =agents.computer.container.keep=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Keep the container when the agent stops, instead of removing it.

Stopping an agent stops its machine, and with this off the container
is removed as well: everything the agent installed goes with it and
the next start builds a fresh one from the image.

On by default. It reads as the smaller of the two settings and it is
not -- a bare image has no toolchain, so the first thing an agent does
in a new container is install one, and discarding that on every stop
means paying for it again on every start. The distrobox backend has
defaulted to keeping for exactly this reason since it was written.

Turned off, `computer stop` and `computer restart` refuse without
`--remove`, and both graphical clients ask first: the contents are
gone rather than offline, which is not what the word stop suggests.

*** =agents.computer.container.pids_limit=

- Type :: integer
- Default :: =0=
- Since :: 0.19.0

Most processes and threads the machine may hold at once.

What stops a fork bomb, or a build with -j0, taking the host down with
it. 0 leaves podman's own default (2048 on Fedora, from
containers.conf); -1 removes the limit. Anything else is the limit.

Read by the distrobox backend too, which is a podman container
underneath: computer.container.* limits reach either. Passed to podman
when the machine is created; a changed value is applied to the
existing one with `podman update` at the next start, without a
rebuild and without losing what the agent installed.

*** =agents.computer.container.memory=

- Type :: string
- Default :: unset
- Since :: 0.19.0

Most memory the machine may use, e.g. 512m or 4g.

A whole number with an optional unit -- b, k, m or g, in powers of
1024 -- and at least 6m, which is podman's floor. Unset means no limit
beyond the host's. Past it the kernel's OOM killer picks a process
inside the machine, which is the point: the agent's container dies
rather than your desktop.

Applies to container and distrobox computers, at creation and then
with `podman update` whenever it changes.

*** =agents.computer.container.memory_swap=

- Type :: string
- Default :: unset
- Since :: 0.19.0

Memory and swap together, e.g. 8g; -1 for unlimited swap.

podman's own meaning, and easy to misread: this is the total, not the
swap alone, so memory: 4g with memory_swap: 6g allows 2g of swap. Equal
to memory means no swap at all. Unset lets podman allow as much swap
again as memory. It needs memory to be set and must not be smaller
than it; both are refused when they arrive rather than when podman
reads them.

** =agents.computer.ssh=

A machine reached over ssh.

The only backend clawtilla does not own. A container, a distrobox and
a VM are things it creates and can destroy; this one was running
before the fleet existed. So clawtilla will not start, stop or take
apart an ssh computer, and both clients leave those buttons out
rather than offering them and failing.

Nothing is mounted into it either -- there is no mount to make across
an ssh connection. That means the agent does NOT get the workspace at
/mnt/clawtilla/workspace or the shared exchange, which every other
backend does get, and fleet-wide shared folders do not apply. What
the mount list does instead is described under workspace below.

*** =agents.computer.ssh.host=

- Type :: string
- Default :: unset
- Since :: 0.2.0

The ssh config alias to connect to.

An alias from ~/.ssh/config, not a hostname -- so the identity file,
the jump host, the port and the user stay where ssh already keeps
them, and clawtilla never reimplements ssh's own configuration.

Letters, digits, '.', '_' and '-' only, and never a leading '-'. ssh
reads an argument beginning with '-' as an option, so an alias called
-oProxyCommand=... would be a command rather than a destination.

Run `ssh <alias> true` once by hand first. The host key is accepted
on your terms, never automatically: an unknown or changed key is a
refusal that names this as the remedy. clawtilla does not pass
StrictHostKeyChecking=no, because accepting a key is your decision.

*** =agents.computer.ssh.workspace=

- Type :: path
- Default :: unset
- Since :: 0.2.0

Where the agent works on that machine.

A path as that machine spells it. It is not expanded here: '~' and
$XDG_* would be resolved against this machine's home and produce a
path that exists here and means nothing over there.

There is no kernel mount to make over ssh, so the mount list becomes
the allowlist instead -- the same shape `confine: allowlist` has on
the host backend. Each mount's *target* is the grant, because that is
the path inside the computer and the computer is the other machine;
the source names a directory on this one and is not used.

That check reads the paths in a command and resolves '.' and '..' by
text. It cannot follow a symlink, because the symlink is on the other
machine -- so it is a boundary against mistakes and against paths an
agent constructs, not against a filesystem laid out to defeat it. The
directory must already exist; clawtilla creates nothing on a machine
it does not own, and a mount marked required that is not there makes
the agent a SHADOW with that reason rather than starting it anyway.

*** =agents.computer.ssh.shell=

- Type :: string
- Default :: =/bin/sh=
- Since :: 0.2.0

Which shell runs the command over there.

ssh hands the remote login shell one string whatever we do, so this
is not a way to avoid a shell -- it is a way to name one that behaves
the same everywhere. A login shell that is fish or csh reads the
`cd <dir> && ...` prologue differently, and naming /bin/sh is what
makes an agent behave identically on every host in a fleet.

*** =agents.computer.ssh.allow_sudo=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether sudo and its neighbours may be run there.

Off refuses sudo, pkexec, doas, run0, su, setpriv and machinectl at
the point the command is built, including inside a shell one-liner,
and the agent is told so rather than discovering it a turn later.

It is an argument check, not a kernel boundary: it stops a command
that names one of those, and cannot stop a program that escalates
once it is already running. Nothing on this backend can -- the kernel
doing the enforcing is on the other machine.

*** =agents.computer.ssh.connect_timeout=

- Type :: integer
- Default :: =10=
- Since :: 0.2.0

Seconds to wait for the connection before failing.

Bounds the one failure that otherwise has none. A machine that has
dropped off the network accepts nothing and refuses nothing, and ssh
will sit out the kernel's TCP timeout waiting -- turning a turn that
should have failed in ten seconds into one that hangs. Zero is
treated as one second rather than as no limit.

*** =agents.computer.ssh.control_persist=

- Type :: integer
- Default :: =600=
- Since :: 0.2.0

Seconds an idle multiplexed connection is kept open.

Without multiplexing every single command pays a full TCP connect,
key exchange and authentication, which over a WAN is most of the time
an agent spends running anything. With it the first command opens a
master and every later one is a channel on the connection already
there.

Zero turns it off. It also turns itself off, with a warning, when the
control socket path would exceed the 108 bytes the kernel allows in a
unix address -- an over-long path does not fail at bind time, it just
means the master is never created and every command silently pays a
fresh handshake.

*** =agents.computer.ssh.wake_command=

- Type :: list of strings
- Default :: unset
- Since :: 0.19.0

A program to run when the machine does not answer, to wake it.

For a machine that sleeps: a homelab box that suspends when idle, a
cloud server that is paused. Wake-on-LAN is the usual answer --
[wakeonlan, aa:bb:cc:dd:ee:ff] -- or a provider's own resume command.
It should return once the machine is on its way up; clawtilla then
connects as usual, and ssh's connect_timeout covers the rest of the
boot.

A program and its arguments, as a list. It is never run through a
shell, so a pipe or a redirect would be text; written as one line in
a client it is split into words and refused if it uses one. Nothing
is substituted into it.

Run only when a connection attempt finds nothing answering, never for
a refused key or login. Commands that arrive while it runs wait for
that one run rather than starting their own, and each is told how
long it waited. It gets at most 120 seconds, after which it is killed
along with everything it started, and the time is not taken out of
the command's own timeout. A wake that fails is reported with the
connection failure, saying which.

** =agents.computer.distrobox=

Settings for computer.type: distrobox.

A distrobox is a podman container deliberately wired into the machine
around it: the agent runs as the same user as you, sees your sockets
and displays, and can reach the host itself with distrobox-host-exec.
That makes it a good place to build things and a poor place to put
something that should be contained -- use computer.type: container for
that, which shares none of it.

*** =agents.computer.distrobox.image=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Image the box is created from. Unset uses distrobox's own default,
which is a Fedora toolbox image.

Name the registry, for the reason the container image does: a bare
'fedora:45' is resolved through podman's unqualified-search list,
which is per-machine.

*** =agents.computer.distrobox.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Box name. Defaults to clawt-<agent-id>.

Prefixed on purpose. These machines already have boxes called 'dev'
and 'util', and an agent adopting one of those would be a fleet
operation reaching into somebody's development environment.

*** =agents.computer.distrobox.home=

- Type :: string
- Default :: unset
- Since :: 0.1.0

HOME inside the box.

Unset gives the agent a directory of its own under
$XDG_DATA_HOME/clawtilla/boxes/<agent-id>/home, which is NOT what
distrobox does on its own -- see share_home.

*** =agents.computer.distrobox.share_home=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Give the box your real home directory.

This is distrobox's own default, and clawtilla's is the opposite,
because the two look identical from inside the box and are completely
different in what they touch: an agent sharing your home can read your
ssh keys, your shell configuration and any credential you keep there.

Turn it on when the point is to work in your environment -- an agent
maintaining your dotfiles, say. Leave it off otherwise. It is fixed
when the box is created, so changing it means removing the box.

*** =agents.computer.distrobox.packages=

- Type :: string
- Default :: =gcc make git=
- Since :: 0.1.0

Packages installed when the box is first created, space separated.

Read once, at creation, the way a VM's cloud-init reads its seed --
so adding a name here and restarting the agent does nothing visible.
The agent can install more itself; this is for what it needs before
it can.

*** =agents.computer.distrobox.flags=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Extra flags passed through to podman, space separated.
Quote anything containing a space.

*** =agents.computer.distrobox.init=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Run an init system (systemd) inside the box.
Needed by anything expecting systemctl or a user unit.

*** =agents.computer.distrobox.keep=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Keep the box when the agent stops.

On by default, unlike the plain container: making one pulls an image
and then runs a package install inside it, and a distrobox is the kind
of computer somebody chose so that what the agent installs survives.

** =agents.computer.vm=

Settings for computer.type: vm.

*** =agents.computer.vm.backend=

- Type :: enum
- Values :: libvirt, qemu
- Default :: =libvirt=
- Since :: 0.1.0

libvirt or qemu.

libvirt is the default and brings snapshots, migration and device
hotplug with it. qemu drives qemu-system-* directly over QMP and needs
no libvirtd, at the cost of that surface.

*** =agents.computer.vm.domain=

- Type :: string
- Default :: unset
- Since :: 0.1.0

libvirt domain name. Defaults to clawt-<agent-id>.

*** =agents.computer.vm.uri=

- Type :: string
- Default :: =qemu:///session=
- Since :: 0.1.0

libvirt connection URI. qemu:///system for system-wide VMs.

*** =agents.computer.vm.emulator=

- Type :: path
- Default :: unset
- Since :: 0.1.0

The QEMU binary to run the guest with.

Left unset, clawtilla looks in /usr/bin and then on PATH, and writes
what it finds into the domain.

Naming it matters because libvirt otherwise picks one itself, by
searching the session daemon's PATH -- so a host with another package
manager ahead of /usr/bin gets a domain pointing into a home
directory. SELinux refuses that: svirt_t cannot start a binary
labelled user_home_t, and the guest never boots. Set this only for a
host whose QEMU is somewhere clawtilla does not look.

*** =agents.computer.vm.image=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Base disk image. A qcow2 overlay is created on top, so the base is
never written to and several agents can share one.

clawtilla ships no image and downloads none: point this at a qcow2 you
already have. A distribution's cloud image is the easy answer, because
cloud_init below can give it a login without the image being touched.

*** =agents.computer.vm.cpus=

- Type :: integer
- Default :: =2=
- Since :: 0.1.0

Virtual CPUs.

*** =agents.computer.vm.memory_mb=

- Type :: integer
- Default :: =8192=
- Since :: 0.1.0

Memory in megabytes.

Sized for a guest running a GNOME session, because that is what
computer.desktop.enabled installs into one. A headless VM is happy in
a quarter of it.

*** =agents.computer.vm.disk_gb=

- Type :: integer
- Default :: =128=
- Since :: 0.1.0

Virtual disk size in gigabytes.

A cloud image's own disk is only a few gigabytes, which a desktop and
a toolchain fill immediately. The overlay is created at this size
instead and cloud-init grows the guest's filesystem to match on first
boot.

qcow2 is sparse, so this costs what is written and not what is asked
for. Raising it grows the disk on the next provision; lowering it is
refused, because shrinking a disk destroys whatever was past the new
end.

*** =agents.computer.vm.resolution=

- Type :: string
- Default :: =1280x800=
- Since :: 0.1.0

The size of the VM's screen, as WIDTHxHEIGHT.

1280x800 is the hypervisor's own default, which is why an agent's
screenshots come back that size unless this says otherwise. The
virtual GPU reports it as the preferred mode and GNOME takes it, so
nothing inside the guest has to be configured -- and unlike anything
in the cloud-init seed, changing it applies at the VM's next boot
rather than needing the machine rebuilt.

It costs guest memory: the framebuffer is width x height x 4 bytes.

*** =agents.computer.vm.ssh_user=

- Type :: string
- Default :: =root=
- Since :: 0.1.0

User commands are run as inside the guest, over SSH.

With cloud_init on, this account is created in the guest rather than
having to exist already, and a non-root one gets passwordless sudo.

root, because of how a shared directory is mapped. An unprivileged
libvirt session runs virtiofsd in a user namespace where the *guest's*
root is the host user who started the daemon, and every other guest
id lands in that user's subuid range. So a share of your own files
appears inside the guest as root:root 0755, and an agent running as
any other account can read it and cannot write to it -- including its
own workspace, which arrives as 0700 root and is not even readable.

This was `clawt` for a while, on the reasoning that the guest's first
account is uid 1000 and so lines up with the host user. That is true
of the numbers and false of the mapping, and booting one is the only
way to find out: guest uid 1000 maps to a subuid around 525287, which
owns nothing. Naming an <idmap> on the share does not help either --
virtiofsd's sandbox cannot set one up for a session daemon at all, and
the domain then fails to start rather than starting without it.

The cost is that GDM will not log root in, so a VM with a desktop gets
a second account for the screen -- see computer.vm.desktop.user, which
is created for exactly this. That account is a normal guest user, so
it cannot write to a share either; anything the session produces for
you goes through a path root writes.

*** =agents.computer.vm.ssh_key=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Private key used to reach the guest.

Left unset, an ed25519 key is generated per agent under the VM's state
directory and authorised through cloud-init. It cannot be encrypted:
the daemon uses it with nobody present to type a passphrase.

*** =agents.computer.vm.ssh_host=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Address that reaches the guest.

Leave it unset and clawtilla forwards a port on 127.0.0.1 to the
guest's SSH and fills this in itself -- the port is chosen once and
remembered, so it survives a restart. Set it when the VM is somewhere
clawtilla did not put it: a bridged network, another host, or a VM that
existed before this agent did.

The libvirt backend can only forward a port through passt, because
libvirt has no port forwarding for the SLIRP backend. Without passt
installed the VM still runs, and this key is the way to reach it.

*** =agents.computer.vm.ssh_port=

- Type :: integer
- Default :: =22=
- Since :: 0.1.0

Port SSH is reached on. Ignored when clawtilla is forwarding a port of
its own choosing, which is the default.

*** =agents.computer.vm.packages=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Packages the guest installs at first boot.

  packages: [git, inetutils]

A cloud image is deliberately small, and what is missing differs by
distribution -- Arch's has no `hostname`, which agents reach for
reflexively. This is where to put what yours needs, rather than
having every agent install it again on every fresh machine.

Names are the guest's, not yours: the same tool is `inetutils` on
Arch and `hostname` on Fedora. cloud-init treats a package it cannot
find as a failure of the *whole* install, so one wrong name costs
every other package here -- and on a guest with a desktop, the
desktop with them.

Read once, by cloud-init, from a seed written before the guest ever
ran. Adding one to a VM that already exists needs computer.rebuild,
like everything else in that seed.

*** =agents.computer.vm.cloud_init=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Hand the guest a cloud-init seed on first boot.

A cloud image has no account, no password and no authorised key: it
expects to be given them. Without this it boots perfectly and nothing
can get in, which looks exactly like a VM that failed to boot.

The seed is a small ISO labelled cidata, attached as a CD-ROM, holding
the login and public key. Building it needs xorriso (Fedora: xorriso).
Turn this off for an image that already has a login and a key.

*** =agents.computer.vm.snapshot_on_start=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Take a snapshot each time the VM starts, so a session can be rolled back.
libvirt backend only.

** =agents.computer.vm.desktop=

How the guest's graphical session is built.

None of this happens unless computer.desktop.enabled is also true --
that key is the grant, and these are the details of what it installs.
A cloud image has no desktop at all, so an agent given one on a VM has
to have it put there first.

*** =agents.computer.vm.desktop.user=

- Type :: string
- Default :: unset
- Since :: 0.1.0

The account the graphical session runs as.

Left unset this is computer.vm.ssh_user, unless that is root: GDM
refuses to log root in, so a VM whose ssh_user is root -- the default
-- gets a separate `clawt` account for the session and keeps running
commands as root. Both are created by cloud-init and both authorise
the same key.

cloud-init acts on first boot only, so changing this later means
deleting the overlay rather than restarting.

*** =agents.computer.vm.desktop.autologin=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Log that account straight in at boot, with no password prompt.

There is nobody at the VM's console to type one, and until a session
exists there is no desktop to control: the shell extension the agent
talks to runs inside GNOME Shell. Turn this off and something else has
to start the session.

*** =agents.computer.vm.desktop.flavour=

- Type :: enum
- Values :: auto, fedora, enterprise, debian, ubuntu, arch
- Default :: =auto=
- Since :: 0.2.0

Which family the guest belongs to, for installing things into it.

`auto` reads it off `computer.vm.image` -- a catalog id says outright,
and an image you downloaded yourself keeps the distribution in its
filename. Set it when neither does: clawtilla says which family it
assumed rather than guessing quietly.

`enterprise` covers CentOS Stream, RHEL and the rebuilds; `arch` is
Arch Linux, whose names drop the 3 everyone else puts in their Python
packages and which is upgraded fully before anything is installed --
refreshing pacman's index without upgrading is the partial upgrade it
warns about. Ubuntu is
separate from Debian for one reason: Debian stable has no `firefox`
package, only `firefox-esr`, and Ubuntu has no `firefox-esr` -- so a
single family would be wrong on half of it, and a package that does
not exist fails the whole install rather than merely missing.

It decides more than package names -- the display
manager is gdm on Fedora and gdm3 on Debian, PyGObject is
python3-gobject there and python3-gi here, and a Debian cloud image
has neither the dconf binary nor glib-compile-schemas until asked.

*** =agents.computer.vm.desktop.packages=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

What to install to get a desktop, if not the usual set.

Left unset this is the list for the guest's `flavour`, which is
almost always what you want: the names differ per distribution and
nobody should have to know that to change image. Each family's list
is deliberately small rather than the full workstation group -- the
agent needs a session to drive, not an office suite to download.

A list here replaces that one rather than adding to it, so it is also
how you take something out. It does not reach the packages the MCP
server needs: those are not the desktop, and trimming this list must
not silently switch automation off.

*** =agents.computer.vm.desktop.mcp=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Install gnome-desktop-mcp into the guest and switch it on.

This is the part the agent actually talks to: a GNOME Shell extension
exposing screenshots, window management and input injection over
D-Bus, and a stdio MCP server in front of it. GNOME on Wayland refuses
those to any process outside the compositor, which is why an extension
is involved at all.

Without this the guest has a desktop and the agent has no way to see
it.

*** =agents.computer.vm.desktop.mcp_repo=

- Type :: string
- Default :: =https://git.podbielniak.com/zachpodbielniak/gnome-desktop-mcp.git=
- Since :: 0.1.0

Where the guest clones gnome-desktop-mcp from.

Cloned rather than installed from PyPI because the extension is only
in the repository, and the two halves have to be the same version --
the server calls D-Bus methods the extension has to already export.

** =agents.computer.desktop=

Let the agent see and drive a desktop session.

An add-on rather than a computer type, so it works alongside whichever
one the agent has. An agent with this can read anything on your screen
and click anything on it.

*** =agents.computer.desktop.enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Whether desktop tools are offered to the agent.

*** =agents.computer.desktop.backend=

- Type :: enum
- Values :: auto, gowl, gnome, guest
- Default :: =auto=
- Since :: 0.1.0

auto, gowl, gnome or guest.

guest is the agent's own VM, and auto picks it whenever the agent has
one -- an agent with its own machine should drive that screen rather
than yours. It is also the only backend where a misjudged click lands
somewhere recoverable.

Otherwise auto tries gowl's MCP socket and falls back to
gnome-desktop-mcp on the host. gowl is the better fit where it is
available: same tool vocabulary, native, and no Python or GNOME Shell
extension in the way.

*** =agents.computer.desktop.socket=

- Type :: path
- Default :: =$XDG_RUNTIME_DIR/gowl-mcp.sock=
- Since :: 0.1.0

gowl's MCP socket. Requires gowl built with MCP=1 and modules.mcp
enabled in its config.

*** =agents.computer.desktop.allow_spawn=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.1.0

Whether the agent may launch and signal processes through the
compositor.

Separate from allow_input, and off by default. The compositor's spawn
tool starts a process through the compositor's own socket, so none of
clawtilla's confinement applies to it -- not the path checks, not the
sudo block, and not bwrap. Turning this on gives the agent a way to
run anything, whatever computer.host.confine says.

*** =agents.computer.desktop.allow_input=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Permit key and pointer injection, not just observation.

With this false the agent can take screenshots and query windows but
cannot act, which is a useful amount of access on its own and a much
smaller grant.

*** =agents.computer.desktop.observe_fps=

- Type :: integer
- Default :: =1=
- Since :: 0.2.0

Frames a second while somebody is watching the screen.

A supervision view, not a video call. Grabbing shares the one
channel the agent is using for its own work, so every frame is
latency taken from the task being watched. Nothing is captured at
all unless a client is subscribed.

Clamped to 1-4. A zero means the default rather than never: a
client that subscribed and then received nothing would show an
empty panel with nothing to explain it.

*** =agents.computer.desktop.takeover_lease_seconds=

- Type :: integer
- Default :: =900=
- Since :: 0.2.0

How long a person may hold the screen before the hold lapses.

While it is held the agent's input is refused rather than queued: a
queued click lands after the person has moved on, on whatever
happens to be under it then. The lease expires so that a browser tab
closed mid-takeover cannot lock an agent out for good.

Taking the screen again while you already hold it extends the lease,
which is what a client does while somebody is still working.

*** =agents.computer.desktop.driver_idle_seconds=

- Type :: integer
- Default :: =120=
- Since :: 0.5.0

On a shared computer, how long one agent keeps the screen after its
last input before another may type or click.

A shared machine has one desktop. The first agent to act on it holds
it; another agent's input is refused, naming who is driving, until
the holder has been idle this long. Looking is never refused.

*** =agents.computer.desktop.allow_recording=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.2.0

Whether a demonstration may be recorded on this screen.

Its own setting, and not part of `allow_input`, because capturing
what a person types is categorically different from injecting
keystrokes. An agent allowed to click must not thereby be allowed to
watch you type.

While a recording runs the desktop says so visibly and the
recording stops itself after `skills.teach_max_seconds`.

Capture pauses for a password field only as far as the compositor
can see one, and that is less far than it sounds. In a guest, GNOME
Shell recognises its own password entries -- the lock screen, its
polkit and keyring prompts -- and pauses. On the host, gowl cannot:
under Wayland a client's widget tree is private, so it suppresses
capture while the session is locked and while the focused window's
app-id or title matches its deny list of credential applications,
and a password typed into a form inside any other window IS
recorded. Every trace carries that sentence. Read a recording
before you turn it into a skill.

** =agents.browser=

A real web browser the agent can drive (needs a GSURF=1 build).

*** =agents.browser.mode=

- Type :: enum
- Values :: none, own, shared
- Default :: =none=
- Since :: 0.9.0

Whether this agent can drive a real web browser.

`own` gives it a session of its own, `shared` one declared under
browsers: (agents.browser.use names it), `none` neither -- the agent
still has clawtilla_web_fetch. A session is gsurf on a private X
display, started on the agent's first browser call and stopped after
agents.browser.idle_minutes without one; it runs JavaScript, so it
reads pages clawtilla_web_fetch cannot, and the agent can click and
type. Watch it from the Computer page's Browser view.

Needs clawtilla built with GSURF=1: an agent asking for a browser
from a build without one is disabled with that reason rather than
run without the tools it was told it has.

** =agents.integrations.webhook=

*** =agents.integrations.webhook.port=

- Type :: integer
- Default :: =0=
- Since :: 0.1.0

Port to listen on. 0 asks the kernel for a free one, which is what you
want with several agents: a fixed port means the second agent to start

*** =agents.integrations.webhook.bind_address=

- Type :: string
- Default :: =127.0.0.1=
- Since :: 0.1.0

Which address to listen on.

The loopback by default. An endpoint in shell_command mode runs a
command, and bearer tokens are otherwise the only thing between that

merges that block into the channel it renders rather than refusing

** =agents.tools=

Which orchestration tools this agent may call.

The clawtilla_* tools let an agent message its peers, delegate work,
read its mailbox and drive its computer. A worker usually wants fewer
of them than a chief-of-staff.

*** =agents.tools.allow=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Tool names permitted. Unset means all of them except those needing a
capability this agent does not have.

*** =agents.tools.deny=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Tool names refused. Applied after allow, so a deny always wins.

** =agents.policy=

What this agent may do without asking.

Enforced on clawtilla's own tools, connectors and the desktop relay
for every backend, and on the CLI's own tools (Bash, Write, ...) for
claude-code and claude-tmux through a PreToolUse hook. Other CLIs run
their own tools unchecked; docs/security.org says so in full.

*** =agents.policy.rules=

- Type :: list of strings
- Default :: unset
- Since :: 0.3.0

This agent's action rules, MATCH=MODE, first match wins. Defaults to
defaults.policy.rules.

*** =agents.policy.ask_timeout_seconds=

- Type :: integer
- Default :: unset
- Since :: 0.3.0

How long an `ask` waits for a person. Defaults to
defaults.policy.ask_timeout_seconds.

*** =agents.tools.manage_fleet=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.1.0

Whether this agent may create other agents.

Off by default, and worth thinking about before turning on: an agent
that can create agents can give one a computer, and a container or a
VM is a machine that runs code. It cannot exceed what you could
create yourself -- every agent it makes goes through the same
validation -- but it can do it without being asked twice.

Intended for a chief-of-staff you talk to about what the fleet needs.

*** =agents.tools.schedule=

- Type :: boolean
- Default :: =true=
- Since :: 0.7.1

Whether this agent may schedule its own routines.

With it on, the agent is offered clawtilla_routine_add, _update and
_remove: it can set up a check on something for itself, move one to a
better time, or split a long watchlist into several -- the way you
would ask a colleague to remind themselves rather than doing it for
them. Only ever routines that run on this agent, never another's,
and never one you marked `locked`.

On by default because a routine opens nothing -- unlike a trigger,
which is an address on your network and stays yours to create. What
it can cost is bounded by `tools.schedule_limit` and
`tools.schedule_min_minutes`.

*** =agents.tools.schedule_limit=

- Type :: integer
- Default :: =8=
- Since :: 0.7.1

How many routines may run on this agent before it can add no more
of its own.

Counts every routine whose agent is this one, including those you
wrote: the bound is on how often the agent is woken, not on who
arranged it. Routines you add are never refused for it.

*** =agents.tools.schedule_min_minutes=

- Type :: integer
- Default :: =15=
- Since :: 0.7.1

The shortest gap between two runs of a routine this agent schedules,
in minutes.

An agent that writes `*/1 * * * *` has written itself a turn a
minute, which is a bill rather than a schedule. Checked over the
schedule's next runs, so a cron expression whose runs bunch up --
`0,1,2 9 * * *` -- is refused as well as one that is simply too
frequent. Applies only to what an agent schedules for itself.
