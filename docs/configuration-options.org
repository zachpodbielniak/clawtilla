** =daemon=

The daemon itself: where it listens, where it keeps state, how loud it is.

clawtillad owns every agent process, every credential and every socket.
Clients hold no transports of their own -- they send typed commands and
fold one event stream. That is what lets the CLI, the GTK app, the web
client and an in-process cmacs embed all be the same program.

*** =daemon.socket=

- Type :: path
- Default :: =$XDG_RUNTIME_DIR/clawtilla/daemon.sock=
- Since :: 0.1.0

Unix socket the clients connect to.

Created with mode 0600 inside a 0700 directory, which is the whole of
the access control: the daemon does not check the peer's uid, so
anything that can open the file is trusted completely.

A unix socket is used rather than a loopback HTTP port because the
filesystem can express that at all, and because any web page the user
visits can reach a loopback port through DNS rebinding.

*** =daemon.git=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Make the state directory a git repository on first start.

The workspaces, the org files and this configuration are worth having
a history of. What makes this safe rather than alarming is the
.gitignore written beside it: the same directory holds credentials,
link tokens, mailboxes and memory databases, and the moment to keep
those out of a history is before there is anything in it.

clawtilla never commits. It creates the repository and the ignore
rules; what goes into a commit stays your decision.

Turning this off stops the repository being created. The ignore file
is still written, because a state directory somebody put in git by
hand needs it more, not less.

*** =daemon.state_dir=

- Type :: path
- Default :: =~/.clawtilla=
- Since :: 0.1.0

Where agent workspaces, mailboxes, transcripts and credentials live.

Created 0700. Never mounted into any agent's computer, whatever the
mount configuration says -- an agent that could read this directory
could read every other agent's credentials.

*** =daemon.pod_module_dir=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Where podomation's loadable modules are, if they are not found for you.

The container and vm computers do their work through podomation's
'container' and 'vm_virtmanager' modules, which libreclaw builds. They
are looked for next to the running binary and then in the install
location, so a normal build and a normal install both work without
setting this.

Set it when the modules live somewhere else -- a system podomation, or
a build tree you are testing against. Naming a directory here means
that directory and no other, so a wrong path fails loudly instead of
being papered over by a stale set found elsewhere.

*** =daemon.log_level=

- Type :: enum
- Values :: error, warning, info, debug
- Default :: =info=
- Since :: 0.1.0

How much the daemon says: error, warning, info, debug.

debug logs every frame on every link, which is what you want when an
agent will not connect and noise the rest of the time.

*** =daemon.tcp_enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Also listen on TCP, so clients on other machines can connect.

Off by default. The unix socket is authenticated by the kernel; a TCP
listener is authenticated by whatever you configure below, so turning
this on without TLS and a token puts the whole fleet on the network.

*** =daemon.tailscale=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Also listen on this machine's tailnet address, when there is one.

On by default, and the one network where that is defensible: a peer on
a tailnet is a device you enrolled and WireGuard authenticated, and
nothing outside it can route to a 100.64/10 address at all. It is what
lets the client on a laptop reach the fleet on a workstation with no
tunnel set up by hand.

A token is still required, and generated into <state_dir>/tcp-token if
token_file names nothing -- so the listener is never open, only
reachable. Print it with `clawtilla daemon token`.

Nothing happens when Tailscale is absent, down, or in
userspace-networking mode, since there is then no address to bind.

*** =daemon.event_log_days=

- Type :: integer
- Default :: =30=
- Since :: 0.1.0

How many days of per-room event logs to keep. 0 disables the sweep.

The event log is the file you paste into a bug report. Secrets are
scrubbed as it is written, not as it is displayed -- a transcript gets
replayed into every context rebuild, so a leaked key in one would be
permanent.

*** =daemon.allow_unconfined_host=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.1.0

Permit agents to use computer.host.confine: none.

An unconfined host computer means the agent runs commands as you, with
your files, your keys and your network. That needs to be two deliberate
acts rather than one typo, so it requires this AND confirm_host_control
on the agent itself.

*** =daemon.automation_dir=

- Type :: path
- Default :: =~/.clawtilla/pods=
- Since :: 0.2.0

Where podomation pods that watch the fleet live.

Every `*.pod` in here is loaded at start. clawtilla registers itself
into podomation as a module, so a pod can bind to what the fleet does
and act on it in the same file:

  pod researcher = clawtilla->new("researcher");

  researcher->on_agent_state where event->state == "error" =>
      clawtilla->restart_agent(agent: "researcher");

  researcher->on_agent_state where event->state == "error" =>
      clawtilla->notify(title: "researcher fell over; restarted it");

An event name cannot carry a dot -- podomation's lexer stops at it --
so it is on_agent_state rather than agent.state.

The constructor's arguments are the scope, and it applies both ways:
a pod named for one agent neither hears about the others nor can act
on them. With no arguments, the whole fleet.

A file that does not parse disables that file and warns; the rest are
loaded.

*** =daemon.webhook_enabled=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether to accept inbound trigger deliveries.

Off by default. A fleet nothing calls into needs no listener, and a
port opened because a feature exists rather than because somebody
asked for it is a port nobody is watching.

The receiver is its own server on its own port and serves only
/health and the secret /hooks/... paths -- never the IPC surface --
so putting it behind a tunnel exposes nothing else.

*** =daemon.webhook_port=

- Type :: integer
- Default :: =8788=
- Since :: 0.2.0

Port the trigger receiver listens on.

It binds loopback and the tailnet address when there is one, and
loopback alone when there is not -- the same rule the web client
follows, and for the same reason: a listener is never widened
because an address was missing.

** =defaults.mounts=

Host paths shared into *every* agent's computer.

  defaults:
    mounts:
      - source: "~/source"
        target: "/work/source"
        mode: rw

The directory you want every agent to see -- your projects tree,
your notes -- written once instead of copied into every agent block
and then forgotten on the next agent you create.

Applied to container, distrobox and VM agents. Not to host agents:
there a mount is the confinement allowlist rather than a kernel
mount, and quietly widening what a host agent may reach is not
something a convenience should do.

An agent's own computer.mounts wins on a matching target, so one
agent can point the same path somewhere else without turning the
default off. agents.computer.default_mounts: false declines them all.

*** =defaults.mounts.scope=

- Type :: enum
- Values :: none, selected, all
- Default :: =all=
- Since :: 0.1.0

Who gets this folder: all, selected or none.

`all` includes agents created later, which is the point of a default.
`selected` uses the `agents:` and `teams:` lists below. `none` keeps
the entry without giving it to anybody, which is how you park one
without losing what it said.

Naming agents or teams without saying `scope` means `selected` --
writing a list and having it ignored would be a rule that reads
correctly and does the opposite.

A scope that is written and cannot be read reaches nobody, the same
way an unrecognised integration scope does: handing somebody's home
directory to the whole fleet by typo is far worse than handing it to
nothing and saying so.

** =secrets=

How secret references in this file are resolved.

There is deliberately no way to write a literal secret here. Credentials
are always a reference:

  api_key: {file: ~/.clawtilla/secrets/anthropic}
  api_key: {env: ANTHROPIC_API_KEY}
  api_key: {command: "pass show clawtilla/anthropic"}

Resolved values are written to per-agent credential files at mode 0600
and injected into that agent's environment. They never appear in an IPC
response, a log line or a transcript.

** =orchestration=

How agents talk to each other, and what stops them doing it forever.

Bot-to-bot messaging is the point of clawtilla and also the thing most
able to run away: two agents that each reply politely will do so until
something stops them. Every limit here is that something.

*** =orchestration.max_hops=

- Type :: integer
- Default :: =8=
- Since :: 0.1.0

How far a message may travel agent-to-agent before it is refused.

Every message carries the depth it was sent at. A chief-of-staff
delegating to a worker that asks a specialist is three hops; anything
much beyond that is usually a loop rather than a plan.

*** =orchestration.rate_limit_per_minute=

- Type :: integer
- Default :: =30=
- Since :: 0.1.0

Messages one agent may send per minute. 0 disables the limit.

*** =orchestration.task_budget_usd=

- Type :: number
- Default :: =5.0=
- Since :: 0.1.0

Spend cap for one delegated task and everything it spawns.
0 disables the cap.

*** =orchestration.cycle_window=

- Type :: integer
- Default :: =10=
- Since :: 0.1.0

How many recent messages per room are remembered for loop detection.

A message repeating one already in the window is refused. This catches
the case the hop limit does not: two agents alternating the same two
replies, each one a fresh chain.

This bounds the memory. How far back the check looks in time is
orchestration.cycle_seconds.

*** =orchestration.cycle_seconds=

- Type :: integer
- Default :: =300=
- Since :: 0.1.0

How long a repeated message counts as a loop. 0 disables the check.

Without this the cycle window was a count alone, so how far back it
looked was however long the room's last cycle_window messages had
taken -- ten messages in a quiet room is hours. An agent that hit a
spawn failure and reported the same error string every turn had its
first report delivered and every one after it refused, so a wedged
agent was indistinguishable from an idle one for ten hours.

The default suits the runaway this check exists for -- two agents
alternating the same two replies with nothing pacing them, where a
turn is seconds. Raise it for a fleet whose turns are minutes; a
repeat is only caught if it lands inside the window.

*** =orchestration.chief_of_staff=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Id of the agent that receives work addressed to the fleet.

At most one agent may hold this. Setting it here is equivalent to

*** =orchestration.repeat_thresholds=

- Type :: list of strings
- Default :: =5,10,20=
- Since :: 0.2.0

Repeat counts worth reporting when an agent keeps making the same
call.

A count lands on a threshold exactly once, so the fifth identical
call reports and the sixth does not. Reporting every repeat past a
floor turns a signal into noise, and noise is what gets skipped.

This one observes rather than intervenes. clawtilla does not own the
model's own tool-call loop, so it cannot steer a turn that is already
running: it counts the calls it serves, writes a note into the
thread, and at the highest threshold interrupts the turn.

An empty list turns the counting off.

*** =orchestration.repeat_max_keys=

- Type :: integer
- Default :: =256=
- Since :: 0.2.0

How many distinct calls one turn remembers while watching for
repeats.

Bounded on purpose: an unlimited set of unique arguments lets one
pathological turn grow the daemon for as long as it runs. The least
recently seen call is dropped first, and a dropped one starts
counting again from one.

*** =orchestration.handoff_max_per_turn=

- Type :: integer
- Default :: =4=
- Since :: 0.2.0

How many handoffs one turn may queue.

Not implemented in this build. Handoff is not built yet, so no work is ever queued against this
limit.

Giving up is its own outcome rather than a failure: 'nobody was

Tasks live in memory and do not survive a restart, so the receipt is

Not implemented in this build. Handoff is not built yet, so no work is ever queued against this

** =memories=

What an agent remembers between conversations.

Not agents.memory, which is the MEMORY.md size budget and a different
thing entirely. This is the searchable store.

Each agent gets its own SQLite database beside its mailbox, holding
what it chose to write down: decisions, preferences, things that
turned out to be true. It searches its own with clawtilla_memory_*.

One database per agent rather than one table with an agent column, so
isolation is a property of the filesystem: a query that forgot to
filter still cannot reach another agent's memories, because they are
not in the file being read.

*** =memories.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether agents get a memory store at all.

Off means the clawtilla_memory_* tools are not offered, rather than
offered and failing. An agent that can see a tool will try it.

*** =memories.max_results=

- Type :: integer
- Default :: =20=
- Since :: 0.1.0

How many memories one search or listing returns at most.

This lands in the agent's context on every call, so the limit is a
budget rather than a formality.

*** =memories.readers=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Comma-separated ids of agents allowed to read this agent's memories.

Empty by default, which is the whole point: an agent's memories are
its own unless somebody says otherwise. Reading only -- there is no
setting that lets one agent write into another's memory, because a
memory you did not form is not a memory.

A comma-separated string, not a YAML list: `readers: chief, deputy`.
Written as `readers: [chief]` it reads back as unset and grants
nothing, so the loader warns about that spelling rather than leaving
a permission somebody granted silently denied.

*** =memories.scope=

- Type :: enum
- Values :: agent, team, fleet
- Default :: =agent=
- Since :: 0.2.0

Where this agent's own memories are written: agent, team or fleet.

Reading always fans out across every scope the agent is entitled to;
this says only where a new memory lands. A fact the whole fleet
needs is worth writing once rather than being relearned by each
agent in turn.

Each scope is a separate database, so what an agent may read is
decided by which file is opened rather than by a WHERE clause. A
permission that is structural cannot be lost to a missing
condition.

Not implemented in this build. Team and fleet memories are not built yet: every memory is
written to the agent's own database whatever this says.

*** =memories.recall=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether the agent may search past conversations.

Separate from `memories.enabled`, which is about facts the agent
chose to record. This is about the transcript itself, which it never
chose and which is much larger.

Not implemented in this build. Searching past conversations is not built yet, so there is
nothing for this to permit or refuse.

*** =memories.summarise=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether finished work is summarised into memories automatically.

Off by default because it is a model call nobody asked for, billed
to whoever set it. On, a completed task or a closed routine run is
distilled into memories tagged with the transcript they came from.

Not implemented in this build. Summarising finished work is not built yet, so nothing is
distilled whether this is on or off.

*** =memories.nudge_turns=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

How many turns between reminders to record what was learned. 0 is

The reminder rides the per-agent prompt suffix rather than being a

Not implemented in this build. The reminder is not built yet, so no turn carries it however
this is set.

*** =memories.operator_profile=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether the fleet keeps a profile of the person it works for.

Not implemented in this build. The operator profile is not built yet, so nothing is gathered

** =rooms=

Standing rooms, created at startup if they do not exist.

A room is a conversation with members. Posting into one enqueues to
every member's mailbox. A direct chat is just a room with two members,
so there is one mechanism rather than two.

*** =rooms.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.1.0

Identifier used to address the room.

*** =rooms.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Display name.

*** =rooms.members=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Agent ids in the room. The human is always implicitly a member.

*** =rooms.require_mention=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Only deliver messages that name an agent.

Worth turning on for a busy room: without it every agent takes a turn
on every message, which is expensive and rarely wanted.

*** =rooms.max_hops=

- Type :: integer
- Default :: unset
- Since :: 0.1.0

Overrides orchestration.max_hops for this room.

It may loosen the fleet limit as well as tighten it, which is the
whole reason it exists: in a conversation three agents each reply one
hop deeper, so an ordinary standup reaches the fleet ceiling on its
own, and the only other remedy is raising orchestration.max_hops for
every delegation chain in the fleet to fix one room.

It reaches the hop count and nothing else. The rate limit, the task
budget and the cycle detector are untouched, so a loop that costs
money still has three limits on it.

*** =rooms.turn_timeout_seconds=

- Type :: integer
- Default :: =300=
- Since :: 0.2.0

How long one member may hold a room's turn before it is yielded.

Counted in work, not wall time: the clock holds while the turn is
parked on an open decision and resumes with what is left. Stopping a
turn under a question nobody has answered manufactures a stranded
decision, which the daemon then has to repair.

Different from the runtime's turn timeout: that one catches a wedged
worker, this one catches a wedged conversation.

Anything below 60 is raised to 60, and 0 turns it off.

** =integrations=

Named integrations, each handed to one agent, some agents or all of them.

An integration is a connection to something outside the fleet, kept in
one place and pointed at whichever agents should have it. That is the
difference from the per-agent `integrations:` block inside an agent,
which still works and is still the right thing for a connection only
that one agent will ever use: this one is configured once and scoped.

Which keys below apply depends on `type`. Each names the type it
belongs to; a key belonging to another type is ignored rather than
rejected, so changing a draft's type does not mean deleting fields
first.

*** =integrations.name=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

What this instance is called.

Unique across the file, and used everywhere the instance is referred
to -- the CLI, the UI, and the key it gets in an agent's .mcp.json. Two
instances with the same name is an error rather than a merge, because
the second silently winning is how a credential ends up pointing at the
wrong account.

*** =integrations.type=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

Which kind: matrix, email, webhook, local, cmacs or mcp.

An unknown type disables that instance and nothing else, with the
reason recorded -- the same treatment a shadow agent gets, and for the
same reason: a config written by a newer build must survive an older
one.

*** =integrations.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether this instance is live at all.

Independent of `scope`: this is the switch, scope is the audience.

*** =integrations.scope=

- Type :: enum
- Values :: none, selected, all
- Default :: =selected=
- Since :: 0.2.0

Who gets it: all, selected or none.

`all` includes agents created later, which is the point of it -- a tool
server the fleet shares should not need revisiting every time the fleet
grows. `selected` uses the `agents:` list below. `none` keeps the
instance and its credentials without handing it to anybody.

*** =integrations.teams=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Team ids, when `scope: selected`.

Beside `agents:` rather than instead of it, and either can match.
Naming a team is how an instance covers a group without being
rewritten every time somebody joins it.

Worth thinking about for a *channel*: two agents sharing one Matrix
account answer as the same person, so a team is rarely what you want
there. For a tools integration it is the ordinary case.

*** =integrations.agents=

- Type :: list of strings
- Default :: unset

Agent ids, when `scope: selected`.

*** =integrations.description=

Written into the agent's TOOLS.org beside the integration, so it is

- Since :: 0.2.0

saying would make the notifier the slowest thing in the daemon.

*** =integrations.room=

- Since :: 0.2.0

*** =integrations.events=

- Type :: list of strings

** =connectors=

Connected accounts: how clawtilla obtains credentials and keeps them.

A connector integration gives an agent the tools of a service without
giving it the credential. The daemon runs the authorization, holds the
token, renews it, and injects it into the tool server -- so the value
is never in the agent's .mcp.json, its environment or its transcript.

What that is worth depends on where the agent runs. For a container
or VM agent the boundary is real: the token file and the relay are on
the host and the agent cannot reach either. For an unconfined host
agent it is protection against leaking a credential by accident, not
against one that goes looking -- see docs/security.org.

*** =connectors.dir=

- Type :: path
- Default :: =$XDG_CONFIG_HOME/clawtilla/connectors.d=
- Since :: 0.2.0

Directory of extra connector definitions.

Each `.yaml` file holds a `connectors:` list, and an entry whose id
matches a built-in one replaces it. These are somebody else's URLs:
a provider that moves an endpoint should be fixable here rather than
by waiting for a clawtilla release.

*** =connectors.refresh_margin_seconds=

- Type :: integer
- Default :: =300=
- Since :: 0.2.0

How long before expiry to renew a token.

An access token often lasts an hour, and one that expires while the
request carrying it is in flight fails exactly like a wrong one --
the agent sees only a refusal from a service it was using a minute
ago.

*** =connectors.redirect_port=

- Type :: integer
- Default :: =8765=
- Since :: 0.2.0

Loopback port for the authorization-code flow's redirect.

Only used by providers with no device flow. It has to be a fixed
number rather than whatever the kernel offers, because the redirect
URI is registered with the provider in advance and most match it
exactly: register `http://127.0.0.1:8765/callback`.

Bound on 127.0.0.1 only. A redirect carries an authorization code in
a URL, and a listener on every interface offers that code to whoever
on the network reaches the port first.

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether the open MCP registry is imported into the catalogue.

Off by default because it reaches the network. When on, the fetch

never from a request handler, so a client pressing a button waits on
this machine and not on somebody else's.

Not implemented in this build. Importing the registry is not built yet, so the catalogue is
the built-in table and the overlay directory, as before.

** =routines=

Standing work: a prompt, an agent, and when to run it.

A routine is the thing you would otherwise remember to ask for every
morning. It runs as a delegated task, so it has its own result.

It does not get a session of its own. libreclaw keys a session on
channel, room and sender and deliberately ignores the thread, so a
routine lands in the operator's session and queues behind whatever
the operator is doing -- and inherits that conversation's context.
Point a routine at an agent that is not also somewhere you chat, or
give it `isolate` so it runs in a room of its own.

Routines only fire while the daemon is running. A machine that was
asleep at nine o'clock has missed nine o'clock, and the routine says
so rather than pretending otherwise -- see `catch_up`.

What the agent is asked to do, in full.

Sent as the whole of the prompt, so it should read as an instruction

*** =routines.enabled=

- Type :: boolean

Whether it runs on its schedule. A disabled routine can still be
started by hand, which is how you try one before trusting it.

*** =routines.schedule=

- Type :: enum
- Values :: manual, hourly, daily, weekdays, weekly, custom
- Default :: =daily=
- Since :: 0.2.0

manual, hourly, daily, weekdays, weekly or custom.

All of them become a cron expression, including the presets -- so
there is one answer to "when does this next run" rather than two.

*** =routines.at=

- Type :: string
- Default :: =09:00=
- Since :: 0.2.0

The time of day, for daily, weekdays and weekly.

Local time, because somebody who wrote 09:00 means nine o'clock where
they are. With `hourly` only the minute is used.

*** =routines.weekday=

- Type :: string
- Default :: =monday=
- Since :: 0.2.0

Which day, for `weekly`.

*** =routines.cron=

- Type :: string
- Default :: unset
- Since :: 0.2.0

The expression, for `custom`: minute hour day-of-month month day-of-week.

Ranges, lists and steps all work, and months and weekdays may be
named. Note the oldest oddity in cron: when *both* day fields are
restricted the match is day-of-month OR day-of-week, so `0 0 13 * 5`
is the thirteenth and every Friday, not Friday the thirteenth.

*** =routines.directory=

- Type :: path
- Default :: unset
- Since :: 0.2.0

Where to run, if not the agent's workspace.

A path on the agent's computer, which for a container or a VM is a
path inside it and not on the host.

*** =routines.worktree=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Run in a fresh git worktree of `directory` rather than in it.

For a routine that changes files: it keeps a scheduled run from
landing on top of whatever you had checked out at the time. The
worktree is left behind deliberately -- throwing away work because a
schedule fired is not recoverable.

*** =routines.isolate=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Give this routine a conversation of its own.

A run is sent from `user` to the agent by default, so it lands in the
operator's room from the operator's sender -- and libreclaw keys a
session on channel, room and sender. One session, one queue: Monday's
run is in Tuesday's context, a 09:00 brief starts whenever the agent
next goes idle, and both happen in the operator's transcript.

Set this and the run goes to a room of its own from a sender of its
own, which is a session of its own: no shared context, no waiting
behind a conversation. The cost is that the prompt and the answer are
no longer in the operator's chat -- they are in the task result and on
the Flow tab, which is where a delegated task's output already lives.

Off by default because moving somebody's output is not a thing to do
to them silently. Pointing the routine at an agent nobody talks to
solves the same problem and needs no setting.

*** =routines.catch_up=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Run once at startup when its time passed while the daemon was down.

Off by default, and worth leaving off for anything that talks to
somebody: a laptop opened after a long weekend would otherwise deliver
a stack of good mornings at once. Only ever one run, however many
were missed.

*** =routines.jitter_seconds=

- Type :: integer
- Default :: =0=
- Since :: 0.2.0

Delay each run by up to this many seconds, chosen at random.

Zero here, unlike a hosted scheduler, because there is no shared
server to spread load across: this is your machine, and a routine set
for 09:00 should run at 09:00. Worth setting only when several
routines share one rate-limited service.

Only a scheduled run is delayed. `clawtilla routine run` starts at
once, because somebody waiting at a terminal is not load to spread;
so does a catch-up, because a run that was already missed does not
need to be later still.

** =triggers=

Work started by something happening elsewhere.

A routine is a clock; a trigger is an event. Both end in the same
queued run against the same agent, so a trigger inherits the
routine's ordering behind a busy agent and its durable receipts
rather than growing a second set.

*** =triggers.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

How the trigger is named on the command line and in the clients.

Not the address it is called on: that is a separate unguessable
endpoint, so renaming a trigger does not tell anybody where it
lives.

*** =triggers.description=

- Type :: string
- Default :: unset
- Since :: 0.2.0

What this trigger is for, in a line.

*** =triggers.agent=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

Which agent runs when it fires.

*** =triggers.room=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Where the run reports, if not the agent's own conversation.

*** =triggers.provider=

- Type :: enum
- Values :: generic, forgejo, gitea, github, gitlab
- Default :: =generic=
- Since :: 0.2.0

Who is calling: forgejo, gitea, github, gitlab or generic.

This decides how the delivery is authenticated, and the four forges
genuinely disagree. Forgejo and Gitea sign the body with HMAC-SHA256
and send the hex bare; GitHub sends the same digest behind a
`sha256=` prefix; GitLab sends the secret itself, verbatim, and
signs nothing.

Naming it matters because Forgejo also sends GitHub- and
Gitea-shaped headers for compatibility. Sniffing is a fallback for
when nobody said, and it can never widen what a configured trigger
accepts.

*** =triggers.secret=

- Type :: secret reference
- Default :: unset
- Since :: 0.2.0

The shared secret the caller proves it knows.

Shown once, when it is created or rotated, and never again -- not in
a listing, a log line, an event or a transcript. Rotating it stops
the old one working immediately.

*** =triggers.events=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Which event names are acted on. Empty means all of them.

An event outside the list is answered normally and recorded as
ignored, because a caller that gets an error for a delivery you
simply did not want will keep retrying it.

*** =triggers.repo=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Only act when the delivery names this repository.

*** =triggers.branch=

- Type :: string
- Default :: unset
- Since :: 0.2.0

Only act when the delivery names this branch.

*** =triggers.header=

- Type :: string
- Default :: unset
- Since :: 0.2.0

For `provider: generic`, the header carrying the event name.

*** =triggers.instructions=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.2.0

What the agent is asked to do, with the event fenced beneath it.

Placeholders -- {{event}}, {{repo}}, {{ref}}, {{actor}}, {{title}},
{{url}}, {{number}} -- are expanded by hand rather than by a format
function, because this string comes out of a configuration file and
a stray percent sign must be a percent sign.

The payload arrives marked as untrusted, and the agent is told to
read it as data: a webhook body is somebody else's text.

*** =triggers.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.2.0

Whether it fires.

A new trigger starts unverified: the first authenticated delivery is
captured and shown to you rather than run, so you can see what the
caller actually sends before an agent acts on it.

*** =triggers.directory=

- Type :: path
- Default :: unset
- Since :: 0.2.0

Where the run should work, if somewhere particular.

*** =triggers.worktree=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Ask the agent to work in a git worktree of its own.

*** =triggers.isolate=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Give the run a conversation of its own rather than the agent's.

** =agents=

The fleet.

Each entry is one libreclaw agent: its persona, its model, its
credentials, its integrations and its computer. This file is the source
of truth -- the daemon renders each agent's libreclaw config.yaml into
its workspace from what is here, and regenerates it when this changes.

An agent whose block cannot be understood becomes a shadow: it is
listed, it says why, and it refuses to run. That is what lets a config
written by a newer clawtilla round-trip through an older one without
losing anything.

*** =agents.id=

- Type :: string
- Default :: unset
- Required :: yes
- Since :: 0.1.0

Identifier used everywhere else to address this agent. Must be unique.

*** =agents.name=

- Type :: string

- Since :: 0.1.0

Display name shown in the clients and used as the agent's own name.

*** =agents.description=

- Type :: string
- Default :: unset
- Since :: 0.1.0

One line about what this agent is for.

Other agents see it when they list the fleet, so it is how a
chief-of-staff decides who to delegate to. Worth writing properly.

*** =agents.enabled=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether this agent may run at all.

*** =agents.chief_of_staff=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Marks the agent that receives work addressed to the fleet.
At most one agent may hold this.

*** =agents.color=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Accent colour in the clients, as a hex string.

*** =agents.order=

- Type :: integer
- Default :: =0=
- Since :: 0.1.0

Where this agent sits in the list, lowest first.

Set by dragging a row in the clients rather than written by hand,
though there is nothing wrong with writing it. Agents sharing a
number keep the order they appear in this file, so leaving them all
at 0 changes nothing.

*** =agents.team=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Which team this agent belongs to, by teams.id.

Unset means no team: the agent still messages and is messaged, it is
simply not grouped and no team lead may assign to it.

*** =agents.team_role=

- Type :: enum
- Values :: member, lead
- Default :: =member=
- Since :: 0.1.0

Standing within that team.

A lead may hand work to the members of its own team and to nobody
else. A member may message, ask and share a room with anyone --
handing something over in conversation is not assigning it -- but may
not delegate at all.

At most one lead per team; a second is refused rather than picked
between. The chief of staff outranks every lead and needs no team.

*** =agents.avatar=

- Type :: path
- Default :: unset
- Since :: 0.1.0

The agent's profile picture. Optional, and usually unnecessary.

A file called profile-picture.png, .jpg, .jpeg or .webp in the
agent's own directory is found without being configured, which is
the expected way to set one: drop the file in and it appears. This
key is for pointing somewhere else, and is resolved against the
workspace when it is relative.

A path named here that does not exist warns and falls back to the
initials, rather than falling back silently -- a mistyped path and
no picture at all otherwise look identical.

The picture reaches a client as bytes, never as a path, because a
client may be running on another machine.

*** =agents.skills=

- Type :: list of strings
- Default :: unset
- Since :: 0.2.0

Skills this agent gets, on top of its team's and the fleet's.

Named, not paths: a skill lives once under `skills.dir` and is
linked into the workspace at whatever path this agent's provider
reads. A selector naming a skill that does not exist warns rather
than silently reaching nobody.

Not implemented in this build. The skill library is not built yet, so no skill is scanned,
assigned or linked into a workspace.

*** =agents.workspace=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Workspace directory. Defaults to defaults.workspace_root/<id>.
Scaffolded on first start if it does not exist.

** =agents.persona=

Who the agent is.

*** =agents.persona.system_prompt=

- Type :: string
- Default :: unset
- Since :: 0.1.0

System prompt, inline. Mutually exclusive with identity_files.

*** =agents.persona.identity_files=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Files in the workspace concatenated into the system prompt, in order.

Leave it unset to get the standard set, which is what every workspace
is scaffolded with: SOUL.org for character, IDENTITY.org for role,
USER.org for who you are, AGENTS.org for how to work, TOOLS.org for

PROJECTS.org for the work. Splitting them means one can be edited
without rewriting the rest -- `clawtilla agent edit <id>` opens them.

Set it to take control of the list: to reorder, to drop one, or to add
a file of your own. An inline system_prompt replaces the lot.

*** =agents.prompt_suffix=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Text appended to every turn this agent runs.

For a rule that has to hold on turn 200 as much as turn 1. A resumed
session never re-receives the system prompt, and a long conversation
drifts away from anything said only once at the start.

clawtilla already adds one of its own for an agent with a computer,
naming the container or VM and telling it to run commands there
rather than on the host. Yours is appended to that, not instead of
it.

Costs tokens on every turn, so keep it to rules that genuinely have
to be repeated -- anything else belongs in the agent's org files.

** =agents.memory=

- Type :: integer

- Since :: 0.1.0

Not implemented in this build, for the same reason as memory.enabled:

*** =agents.memory.max_bytes=

- Type :: integer

- Since :: 0.1.0

Byte budget for MEMORY.md, applied alongside max_lines.

** =agents.runtime=

How this agent's libreclaw instance is hosted.

*** =agents.runtime.type=

- Type :: enum
- Values :: process, embedded
- Default :: =process=
- Since :: 0.1.0

process or embedded.

process supervises a real libreclaw child: crashes stay contained, the
environment and credentials are genuinely separate, and the agent can
live inside its own container. embedded runs it inside the daemon,
which is cheaper and is what an in-process host such as cmacs wants, at
the cost of sharing a fate with every other embedded agent.

*** =agents.runtime.autostart=

- Type :: boolean
- Default :: unset
- Since :: 0.1.0

Start with the daemon. Defaults to defaults.autostart.

*** =agents.runtime.restart=

- Type :: enum
- Values :: never, on-failure, always
- Default :: unset
- Since :: 0.1.0

never, on-failure or always. Defaults to defaults.restart.

*** =agents.runtime.backoff_seconds=

- Type :: integer
- Default :: =5=
- Since :: 0.1.0

Base delay before a restart, doubling on each consecutive failure.

*** =agents.runtime.max_restarts=

- Type :: integer
- Default :: =10=
- Since :: 0.1.0

Consecutive failures before the agent is left in error rather than
restarted again. 0 means never give up.

*** =agents.runtime.turn_timeout_seconds=

- Type :: integer
- Default :: =1200=
- Since :: 0.2.0

How long a turn may go without producing anything before it is
cancelled. 0 disables it.

Activity, not duration: a turn may legitimately run for an hour
while events keep arriving, and a turn that has emitted nothing at

Watched in two places, on purpose. The daemon watches activity and
publishes turn.timed_out; the same number is rendered into the
agent's own session.watchdog_timeout_seconds, so a turn wedged
somewhere the daemon cannot see is still unwound from inside.

** =agents.computer=

What the agent can run commands on.

*** =agents.computer.type=

- Type :: enum
- Values :: none, host, container, vm, distrobox, ssh
- Default :: unset
- Since :: 0.1.0

Which kind of computer this agent gets. Defaults to
defaults.computer. The permitted values are listed above, from the
schema itself -- the copy that used to be written out here had
already gone stale by omitting distrobox.

Desktop control is not a type -- it is the desktop block below, and

*** =agents.computer.exchange=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether the shared exchange directory is visible to this agent.

On by default, because otherwise every pair of agents that wants to
hand a file across needs its own hand-wired mount. Turn it off for an

*** =agents.computer.workspace=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Whether the agent's own workspace is mounted into its computer at

On by default. The workspace holds the agent's persona, its notes and

*** =agents.computer.default_mounts=

- Type :: boolean

- Since :: 0.1.0

Whether this agent gets the fleet's shared folders from

On by default -- that is what makes them defaults. Turn it off for an
agent that should see only what it declares itself, which is the
point of giving one a container in the first place.

Declining all of them is different from replacing one: an agent that
declares its own mount at the same target already wins there, with

** =agents.computer.mounts=

Host paths shared into the computer.

  mounts:
    - source: "~/src/projects"
      target: "/work/projects"
      mode: rw
      relabel: shared

For a container these become bind mounts; for a VM, virtiofs shares;
for a host computer they are the confinement allowlist itself.

*** =agents.computer.mounts.source=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Host path to share. Not needed for tmpfs.

*** =agents.computer.mounts.target=

- Type :: path
- Default :: unset
- Required :: yes
- Since :: 0.1.0

Absolute path inside the computer. Must not overlap another mount.

*** =agents.computer.mounts.mode=

- Type :: enum
- Values :: ro, rw
- Default :: =ro=
- Since :: 0.1.0

ro or rw. Read-only is the default: an agent that only needs to read
your notes should not be able to rewrite them.

*** =agents.computer.mounts.type=

- Type :: enum
- Values :: bind, volume, virtiofs, 9p, tmpfs
- Default :: =bind=
- Since :: 0.1.0

bind, volume, virtiofs, 9p or tmpfs.

Usually leave this alone: bind for containers and virtiofs for VMs are
chosen automatically from the computer type.

*** =agents.computer.mounts.relabel=

- Type :: enum
- Values :: none, shared, private
- Default :: =shared=
- Since :: 0.1.0

SELinux relabelling for a container bind mount: none, shared or private.

This matters on Fedora Silverblue and friends, where an unlabelled bind
mount is visible in the container but every access is denied -- which
reads like a permissions bug rather than a labelling one.

shared (:z) is the default because it is what makes a shared folder
work. It used to default to none, which meant every mount anyone
declared failed with permission denied on an SELinux system while
this very text said shared was usually what you wanted. On a machine
without SELinux it does nothing.

private (:Z) rewrites the host directory's labels exclusively for this
container, which will break anything else using that directory. none
leaves the labels alone, which is right when the source is already
labelled for container access.

- Type :: boolean

*** =agents.computer.host.confine=

- Type :: enum
- Values :: none, workspace, allowlist, bwrap
- Default :: =workspace=
- Since :: 0.1.0

How much of the machine the agent may touch.

  workspace  cwd pinned to root; every path in the command line is
             canonicalised and rejected if it escapes
  allowlist  root plus allow_paths, minus deny_paths
  bwrap      a real kernel sandbox via bubblewrap
  none       no restriction at all

workspace and allowlist are enforced by inspecting the command before
running it, which closes '..' and symlink escapes together. They do not
stop a program that opens paths itself once it is running. Only bwrap
does, because only bwrap involves the kernel.

If bwrap is asked for and not installed, the agent becomes a shadow with
that as its reason. It is never silently downgraded.

*** =agents.computer.host.allow_paths=

*** =agents.computer.host.deny_paths=

- Default :: unset
- Since :: 0.1.0

Paths refused even when they fall inside an allowed one.

Checked after allow_paths, so ~/.ssh stays out even when all of ~ is in.

Whether the agent's commands can reach the network.

the next start builds a fresh one from the image.

On by default. It reads as the smaller of the two settings and it is
not -- a bare image has no toolchain, so the first thing an agent does
in a new container is install one, and discarding that on every stop
means paying for it again on every start. The distrobox backend has
defaulted to keeping for exactly this reason since it was written.

Turned off, `computer stop` and `computer restart` refuse without
`--remove`, and both graphical clients ask first: the contents are
gone rather than offline, which is not what the word stop suggests.

** =agents.computer.ssh=

A machine reached over ssh.

The only backend clawtilla does not own. A container, a distrobox and
a VM are things it creates and can destroy; this one was running
before the fleet existed. So clawtilla will not start, stop or take
apart an ssh computer, and both clients leave those buttons out
rather than offering them and failing.

Nothing is mounted into it either -- there is no mount to make across
an ssh connection. That means the agent does NOT get the workspace at
/mnt/clawtilla/workspace or the shared exchange, which every other
backend does get, and fleet-wide shared folders do not apply. What
the mount list does instead is described under workspace below.

*** =agents.computer.ssh.host=

- Type :: string
- Default :: unset
- Since :: 0.2.0

The ssh config alias to connect to.

An alias from ~/.ssh/config, not a hostname -- so the identity file,
the jump host, the port and the user stay where ssh already keeps
them, and clawtilla never reimplements ssh's own configuration.

Letters, digits, '.', '_' and '-' only, and never a leading '-'. ssh
reads an argument beginning with '-' as an option, so an alias called
-oProxyCommand=... would be a command rather than a destination.

Run `ssh <alias> true` once by hand first. The host key is accepted
on your terms, never automatically: an unknown or changed key is a
refusal that names this as the remedy. clawtilla does not pass
StrictHostKeyChecking=no, because accepting a key is your decision.

*** =agents.computer.ssh.workspace=

- Type :: path
- Default :: unset
- Since :: 0.2.0

Where the agent works on that machine.

A path as that machine spells it. It is not expanded here: '~' and
$XDG_* would be resolved against this machine's home and produce a
path that exists here and means nothing over there.

There is no kernel mount to make over ssh, so the mount list becomes
the allowlist instead -- the same shape `confine: allowlist` has on
the host backend. Each mount's *target* is the grant, because that is
the path inside the computer and the computer is the other machine;
the source names a directory on this one and is not used.

That check reads the paths in a command and resolves '.' and '..' by
text. It cannot follow a symlink, because the symlink is on the other
machine -- so it is a boundary against mistakes and against paths an
agent constructs, not against a filesystem laid out to defeat it. The
directory must already exist; clawtilla creates nothing on a machine
it does not own, and a mount marked required that is not there makes
the agent a SHADOW with that reason rather than starting it anyway.

*** =agents.computer.ssh.shell=

- Type :: string
- Default :: =/bin/sh=
- Since :: 0.2.0

Which shell runs the command over there.

ssh hands the remote login shell one string whatever we do, so this
is not a way to avoid a shell -- it is a way to name one that behaves
the same everywhere. A login shell that is fish or csh reads the
`cd <dir> && ...` prologue differently, and naming /bin/sh is what
makes an agent behave identically on every host in a fleet.

*** =agents.computer.ssh.allow_sudo=

- Type :: boolean
- Default :: =false=
- Since :: 0.2.0

Whether sudo and its neighbours may be run there.

Off refuses sudo, pkexec, doas, run0, su, setpriv and machinectl at
the point the command is built, including inside a shell one-liner,
and the agent is told so rather than discovering it a turn later.

It is an argument check, not a kernel boundary: it stops a command
that names one of those, and cannot stop a program that escalates
once it is already running. Nothing on this backend can -- the kernel
doing the enforcing is on the other machine.

*** =agents.computer.ssh.connect_timeout=

- Type :: integer
- Default :: =10=
- Since :: 0.2.0

Seconds to wait for the connection before failing.

Bounds the one failure that otherwise has none. A machine that has
dropped off the network accepts nothing and refuses nothing, and ssh
will sit out the kernel's TCP timeout waiting -- turning a turn that
should have failed in ten seconds into one that hangs. Zero is
treated as one second rather than as no limit.

*** =agents.computer.ssh.control_persist=

- Type :: integer
- Default :: =600=
- Since :: 0.2.0

Seconds an idle multiplexed connection is kept open.

Without multiplexing every single command pays a full TCP connect,
key exchange and authentication, which over a WAN is most of the time
an agent spends running anything. With it the first command opens a
master and every later one is a channel on the connection already
there.

Zero turns it off. It also turns itself off, with a warning, when the
control socket path would exceed the 108 bytes the kernel allows in a
unix address -- an over-long path does not fail at bind time, it just
means the master is never created and every command silently pays a
fresh handshake.

** =agents.computer.distrobox=

Settings for computer.type: distrobox.

A distrobox is a podman container deliberately wired into the machine
around it: the agent runs as the same user as you, sees your sockets
and displays, and can reach the host itself with distrobox-host-exec.
That makes it a good place to build things and a poor place to put
something that should be contained -- use computer.type: container for
that, which shares none of it.

*** =agents.computer.distrobox.image=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Image the box is created from. Unset uses distrobox's own default,
which is a Fedora toolbox image.

Name the registry, for the reason the container image does: a bare
'fedora:44' is resolved through podman's unqualified-search list,
which is per-machine.

*** =agents.computer.distrobox.name=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Box name. Defaults to clawt-<agent-id>.

Prefixed on purpose. These machines already have boxes called 'dev'
and 'util', and an agent adopting one of those would be a fleet
operation reaching into somebody's development environment.

*** =agents.computer.distrobox.home=

- Type :: string
- Default :: unset
- Since :: 0.1.0

HOME inside the box.

Unset gives the agent a directory of its own under
$XDG_DATA_HOME/clawtilla/boxes/<agent-id>/home, which is NOT what
distrobox does on its own -- see share_home.

*** =agents.computer.distrobox.share_home=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Give the box your real home directory.

This is distrobox's own default, and clawtilla's is the opposite,
because the two look identical from inside the box and are completely
different in what they touch: an agent sharing your home can read your
ssh keys, your shell configuration and any credential you keep there.

Turn it on when the point is to work in your environment -- an agent
maintaining your dotfiles, say. Leave it off otherwise. It is fixed
when the box is created, so changing it means removing the box.

*** =agents.computer.distrobox.packages=

- Type :: string
- Default :: =gcc make git=
- Since :: 0.1.0

Packages installed when the box is first created, space separated.

Read once, at creation, the way a VM's cloud-init reads its seed --
so adding a name here and restarting the agent does nothing visible.
The agent can install more itself; this is for what it needs before
it can.

*** =agents.computer.distrobox.flags=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Extra flags passed through to podman, space separated.
Quote anything containing a space.

*** =agents.computer.distrobox.init=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Run an init system (systemd) inside the box.
Needed by anything expecting systemctl or a user unit.

*** =agents.computer.distrobox.keep=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Keep the box when the agent stops.

On by default, unlike the plain container: making one pulls an image
and then runs a package install inside it, and a distrobox is the kind
of computer somebody chose so that what the agent installs survives.

** =agents.computer.vm=

Settings for computer.type: vm.

*** =agents.computer.vm.backend=

- Type :: enum
- Values :: libvirt, qemu
- Default :: =libvirt=
- Since :: 0.1.0

libvirt or qemu.

libvirt is the default and brings snapshots, migration and device
hotplug with it. qemu drives qemu-system-* directly over QMP and needs
no libvirtd, at the cost of that surface.

*** =agents.computer.vm.domain=

- Type :: string
- Default :: unset
- Since :: 0.1.0

libvirt domain name. Defaults to clawt-<agent-id>.

*** =agents.computer.vm.uri=

- Type :: string
- Default :: =qemu:///session=
- Since :: 0.1.0

libvirt connection URI. qemu:///system for system-wide VMs.

*** =agents.computer.vm.emulator=

- Type :: path
- Default :: unset
- Since :: 0.1.0

The QEMU binary to run the guest with.

Left unset, clawtilla looks in /usr/bin and then on PATH, and writes
what it finds into the domain.

Naming it matters because libvirt otherwise picks one itself, by
searching the session daemon's PATH -- so a host with another package
manager ahead of /usr/bin gets a domain pointing into a home
directory. SELinux refuses that: svirt_t cannot start a binary
labelled user_home_t, and the guest never boots. Set this only for a
host whose QEMU is somewhere clawtilla does not look.

*** =agents.computer.vm.image=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Base disk image. A qcow2 overlay is created on top, so the base is
never written to and several agents can share one.

clawtilla ships no image and downloads none: point this at a qcow2 you
already have. A distribution's cloud image is the easy answer, because
cloud_init below can give it a login without the image being touched.

*** =agents.computer.vm.cpus=

- Type :: integer
- Default :: =2=
- Since :: 0.1.0

Virtual CPUs.

*** =agents.computer.vm.memory_mb=

- Type :: integer
- Default :: =8192=
- Since :: 0.1.0

Memory in megabytes.

Sized for a guest running a GNOME session, because that is what
computer.desktop.enabled installs into one. A headless VM is happy in
a quarter of it.

*** =agents.computer.vm.disk_gb=

- Type :: integer
- Default :: =128=
- Since :: 0.1.0

Virtual disk size in gigabytes.

A cloud image's own disk is only a few gigabytes, which a desktop and
a toolchain fill immediately. The overlay is created at this size
instead and cloud-init grows the guest's filesystem to match on first
boot.

qcow2 is sparse, so this costs what is written and not what is asked
for. Raising it grows the disk on the next provision; lowering it is
refused, because shrinking a disk destroys whatever was past the new
end.

*** =agents.computer.vm.resolution=

- Type :: string
- Default :: =1280x800=
- Since :: 0.1.0

The size of the VM's screen, as WIDTHxHEIGHT.

1280x800 is the hypervisor's own default, which is why an agent's
screenshots come back that size unless this says otherwise. The
virtual GPU reports it as the preferred mode and GNOME takes it, so
nothing inside the guest has to be configured -- and unlike anything
in the cloud-init seed, changing it applies at the VM's next boot
rather than needing the machine rebuilt.

It costs guest memory: the framebuffer is width x height x 4 bytes.

*** =agents.computer.vm.ssh_user=

- Type :: string
- Default :: =root=
- Since :: 0.1.0

User commands are run as inside the guest, over SSH.

With cloud_init on, this account is created in the guest rather than
having to exist already, and a non-root one gets passwordless sudo.

root, because of how a shared directory is mapped. An unprivileged
libvirt session runs virtiofsd in a user namespace where the *guest's*
root is the host user who started the daemon, and every other guest
id lands in that user's subuid range. So a share of your own files
appears inside the guest as root:root 0755, and an agent running as
any other account can read it and cannot write to it -- including its
own workspace, which arrives as 0700 root and is not even readable.

This was `clawt` for a while, on the reasoning that the guest's first
account is uid 1000 and so lines up with the host user. That is true
of the numbers and false of the mapping, and booting one is the only
way to find out: guest uid 1000 maps to a subuid around 525287, which
owns nothing. Naming an <idmap> on the share does not help either --
virtiofsd's sandbox cannot set one up for a session daemon at all, and
the domain then fails to start rather than starting without it.

The cost is that GDM will not log root in, so a VM with a desktop gets
a second account for the screen -- see computer.vm.desktop.user, which
is created for exactly this. That account is a normal guest user, so
it cannot write to a share either; anything the session produces for
you goes through a path root writes.

*** =agents.computer.vm.ssh_key=

- Type :: path
- Default :: unset
- Since :: 0.1.0

Private key used to reach the guest.

Left unset, an ed25519 key is generated per agent under the VM's state
directory and authorised through cloud-init. It cannot be encrypted:
the daemon uses it with nobody present to type a passphrase.

*** =agents.computer.vm.ssh_host=

- Type :: string
- Default :: unset
- Since :: 0.1.0

Address that reaches the guest.

Leave it unset and clawtilla forwards a port on 127.0.0.1 to the
guest's SSH and fills this in itself -- the port is chosen once and
remembered, so it survives a restart. Set it when the VM is somewhere
clawtilla did not put it: a bridged network, another host, or a VM that
existed before this agent did.

The libvirt backend can only forward a port through passt, because
libvirt has no port forwarding for the SLIRP backend. Without passt
installed the VM still runs, and this key is the way to reach it.

*** =agents.computer.vm.ssh_port=

- Type :: integer
- Default :: =22=
- Since :: 0.1.0

Port SSH is reached on. Ignored when clawtilla is forwarding a port of
its own choosing, which is the default.

*** =agents.computer.vm.packages=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Packages the guest installs at first boot.

  packages: [git, inetutils]

A cloud image is deliberately small, and what is missing differs by
distribution -- Arch's has no `hostname`, which agents reach for
reflexively. This is where to put what yours needs, rather than
having every agent install it again on every fresh machine.

Names are the guest's, not yours: the same tool is `inetutils` on
Arch and `hostname` on Fedora. cloud-init treats a package it cannot
find as a failure of the *whole* install, so one wrong name costs
every other package here -- and on a guest with a desktop, the
desktop with them.

Read once, by cloud-init, from a seed written before the guest ever
ran. Adding one to a VM that already exists needs computer.rebuild,
like everything else in that seed.

*** =agents.computer.vm.cloud_init=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Hand the guest a cloud-init seed on first boot.

A cloud image has no account, no password and no authorised key: it
expects to be given them. Without this it boots perfectly and nothing
can get in, which looks exactly like a VM that failed to boot.

The seed is a small ISO labelled cidata, attached as a CD-ROM, holding
the login and public key. Building it needs xorriso (Fedora: xorriso).
Turn this off for an image that already has a login and a key.

*** =agents.computer.vm.snapshot_on_start=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Take a snapshot each time the VM starts, so a session can be rolled back.
libvirt backend only.

** =agents.computer.vm.desktop=

How the guest's graphical session is built.

None of this happens unless computer.desktop.enabled is also true --
that key is the grant, and these are the details of what it installs.
A cloud image has no desktop at all, so an agent given one on a VM has
to have it put there first.

*** =agents.computer.vm.desktop.user=

- Type :: string
- Default :: unset
- Since :: 0.1.0

The account the graphical session runs as.

Left unset this is computer.vm.ssh_user, unless that is root: GDM
refuses to log root in, so a VM whose ssh_user is root -- the default
-- gets a separate `clawt` account for the session and keeps running
commands as root. Both are created by cloud-init and both authorise
the same key.

cloud-init acts on first boot only, so changing this later means
deleting the overlay rather than restarting.

*** =agents.computer.vm.desktop.autologin=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Log that account straight in at boot, with no password prompt.

There is nobody at the VM's console to type one, and until a session
exists there is no desktop to control: the shell extension the agent
talks to runs inside GNOME Shell. Turn this off and something else has
to start the session.

*** =agents.computer.vm.desktop.flavour=

- Type :: enum
- Values :: auto, fedora, enterprise, debian, ubuntu, arch
- Default :: =auto=
- Since :: 0.2.0

Which family the guest belongs to, for installing things into it.

`auto` reads it off `computer.vm.image` -- a catalog id says outright,
and an image you downloaded yourself keeps the distribution in its
filename. Set it when neither does: clawtilla says which family it
assumed rather than guessing quietly.

`enterprise` covers CentOS Stream, RHEL and the rebuilds; `arch` is
Arch Linux, whose names drop the 3 everyone else puts in their Python
packages and which is upgraded fully before anything is installed --
refreshing pacman's index without upgrading is the partial upgrade it
warns about. Ubuntu is
separate from Debian for one reason: Debian stable has no `firefox`
package, only `firefox-esr`, and Ubuntu has no `firefox-esr` -- so a
single family would be wrong on half of it, and a package that does
not exist fails the whole install rather than merely missing.

It decides more than package names -- the display
manager is gdm on Fedora and gdm3 on Debian, PyGObject is
python3-gobject there and python3-gi here, and a Debian cloud image
has neither the dconf binary nor glib-compile-schemas until asked.

*** =agents.computer.vm.desktop.packages=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

What to install to get a desktop, if not the usual set.

Left unset this is the list for the guest's `flavour`, which is
almost always what you want: the names differ per distribution and
nobody should have to know that to change image. Each family's list
is deliberately small rather than the full workstation group -- the
agent needs a session to drive, not an office suite to download.

A list here replaces that one rather than adding to it, so it is also
how you take something out. It does not reach the packages the MCP
server needs: those are not the desktop, and trimming this list must
not silently switch automation off.

*** =agents.computer.vm.desktop.mcp=

- Type :: boolean
- Default :: =true=
- Since :: 0.1.0

Install gnome-desktop-mcp into the guest and switch it on.

This is the part the agent actually talks to: a GNOME Shell extension
exposing screenshots, window management and input injection over
D-Bus, and a stdio MCP server in front of it. GNOME on Wayland refuses
those to any process outside the compositor, which is why an extension
is involved at all.

Without this the guest has a desktop and the agent has no way to see
it.

*** =agents.computer.vm.desktop.mcp_repo=

- Type :: string
- Default :: =https://git.podbielniak.com/zachpodbielniak/gnome-desktop-mcp.git=
- Since :: 0.1.0

Where the guest clones gnome-desktop-mcp from.

Cloned rather than installed from PyPI because the extension is only
in the repository, and the two halves have to be the same version --
the server calls D-Bus methods the extension has to already export.

** =agents.computer.desktop=

Let the agent see and drive a desktop session.

An add-on rather than a computer type, so it works alongside whichever
one the agent has. An agent with this can read anything on your screen
and click anything on it.

*** =agents.computer.desktop.enabled=

- Type :: boolean

- Since :: 0.1.0

Whether desktop tools are offered to the agent.

*** =agents.computer.desktop.backend=

- Type :: enum
- Values :: auto, gowl, gnome, guest
- Default :: =auto=
- Since :: 0.1.0

auto, gowl, gnome or guest.

guest is the agent's own VM, and auto picks it whenever the agent has

*** =agents.computer.desktop.allow_spawn=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.1.0

Whether the agent may launch and signal processes through the

Separate from allow_input, and off by default. The compositor's spawn

*** =agents.computer.desktop.allow_input=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

Permit key and pointer injection, not just observation.

With this false the agent can take screenshots and query windows but

*** =agents.computer.desktop.observe_fps=

- Type :: integer
- Default :: =1=
- Since :: 0.2.0

Frames a second while somebody is watching the screen.

A supervision view, not a video call. Grabbing shares the one
channel the agent is using for its own work, so every frame is
latency taken from the task being watched. Nothing is captured at
all unless a client is subscribed.

Not implemented in this build. Watching the screen is not built yet, so no frame is ever

*** =agents.computer.desktop.takeover_lease_seconds=

- Type :: integer
- Default :: =900=
- Since :: 0.2.0

How long a person may hold the screen before the hold lapses.

While it is held the agent's input is refused rather than queued: a

happens to be under it then. The lease expires so that a browser tab
closed mid-takeover cannot lock an agent out for good.

Not implemented in this build. Taking over the screen is not built yet, so no hold is ever
taken and none can lapse.

*** =agents.computer.desktop.allow_recording=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.2.0

Whether a demonstration may be recorded on this screen.

Its own setting, and not part of `allow_input`, because capturing
what a person types is categorically different from injecting

watch you type.

whenever a password field has focus, and the recording stops itself
after `skills.teach_max_seconds`.

Not implemented in this build. Recording a demonstration is not built yet. This grant is
parsed and offered to nobody, and no capture can happen
whatever it says.

- Default :: =127.0.0.1=
- Since :: 0.1.0

Which address to listen on.

The loopback by default. An endpoint in shell_command mode runs a
command, and bearer tokens are otherwise the only thing between that
and whoever can reach the port -- so widening it is something you say
rather than something you get. Set it to 0.0.0.0 for every interface,
or to a private interface's address.

The routing itself is libreclaw's channels.webhook.endpoints, which
goes in the agent's `libreclaw:` block: it is a list of objects with
nested targets and has no sensible spelling as a flat key. clawtilla
merges that block into the channel it renders rather than refusing
it.

*** =agents.integrations.local=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

libreclaw's stdin/stdout channel.

At most one agent may have this, and only with runtime.type: process --
it takes over file descriptors 0 and 1, which an embedded agent would be
taking from the daemon.

*** =agents.integrations.cmacs=

- Type :: boolean
- Default :: =false=
- Since :: 0.1.0

libreclaw's in-process cmacs channel.

** =agents.tools=

Which orchestration tools this agent may call.

The clawtilla_* tools let an agent message its peers, delegate work,
read its mailbox and drive its computer. A worker usually wants fewer
of them than a chief-of-staff.

*** =agents.tools.allow=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Tool names permitted. Unset means all of them except those needing a
capability this agent does not have.

*** =agents.tools.deny=

- Type :: list of strings
- Default :: unset
- Since :: 0.1.0

Tool names refused. Applied after allow, so a deny always wins.

*** =agents.tools.manage_fleet=

- Type :: boolean
- Default :: =false=
- Warning :: hands over real authority; see [[file:security.org][security.org]]
- Since :: 0.1.0

Whether this agent may create other agents.

Off by default, and worth thinking about before turning on: an agent
that can create agents can give one a computer, and a container or a
VM is a machine that runs code. It cannot exceed what you could
create yourself -- every agent it makes goes through the same
validation -- but it can do it without being asked twice.

Intended for a chief-of-staff you talk to about what the fleet needs.

** =agents.mailbox=

Per-agent overrides of orchestration.mailbox.

*** =agents.libreclaw=

- Type :: mapping
- Default :: unset
- Since :: 0.1.0

Merged verbatim into this agent's generated libreclaw config.yaml.

An escape hatch for libreclaw settings clawtilla does not model. What is
here wins over what clawtilla generates, so it can also be used to
override something deliberately.
