* Spending

A fleet of agents is a fleet of paid API calls.  Every agent is a
libreclaw process, and libreclaw records one row per AI turn --  tokens
and cost -- into that agent's own database.  clawtilla reads those rows
and adds them up.

#+begin_src bash
clawtilla cost
#+end_src

#+begin_example
AGENT                   TURNS           IN          OUT         COST  LAST TURN  IDLE
tester                     45          182        15296        $0.23  2h ago     active
chief                       7           28         2834        $0.04  4d ago     idle
fleet                      52          210        18130        $0.27
#+end_example

Agents are listed most expensive first. LAST TURN is the newest recorded turn, and IDLE is =clawt_usage_idle_label()= against =orchestration.idle_hours= -- the same words the Fleet page draws. ~--by-day~ adds the fleet's cost for each of the last 14 days (or ~--days N~) and the strip the Fleet page draws. ~--by model~, ~--by origin~ and ~--by day~ group the same turns another way, ~--csv~ exports them, and turns with no recorded price get a column of their own -- see [[#ledger][the ledger]].

** Where the figure comes from

The cost is *the number the provider itself reported for that turn*, not
an estimate.  Claude Code, the Claude tmux client and the Grok build CLI
all state a =total_cost_usd= per turn; that figure is carried through
ai-glib's =AiResponse= and recorded as it stands.

*=-1= means unknown, not free.*  That is the sentinel all the way through
-- =ai_response_get_cost_micros()=, =lc_session_get_last_cost_micros()=,
and the field's initialiser.  Zero would be indistinguishable from a turn
that genuinely cost nothing, and a fleet summing those would report
spending nothing at all.  Only a cost of =0= or more is taken as the
provider's answer; anything below falls through to the estimate.

This matters more than it sounds.  A CLI backend bills for *cache reads*
and *cache writes*, and neither appears in the token counts it reports.
An agent with a persistent session has a warm context on every turn
after the first, so a cost recomputed from a rate card over the two
reported token counts lands well under the real one -- and the gap grows
with the size of the context, which is exactly the case anybody watching
a bill cares about.

A provider that reports no cost at all gets an estimate from libreclaw's
price table.  That is a floor, and it is used only where there is nothing
better.

*And only if there is a price table.*  It is built from libreclaw's own
config and may be absent, in which case a turn with no reported cost is
written as =0= -- indistinguishable in =token_usage= from a turn that was
genuinely free.  So clawtilla does not believe it: a turn that moved
tokens and recorded =0= is counted as *unpriced*, beside a negative cost,
and kept out of every sum -- see [[#ledger][the ledger]], where those
turns have a column of their own.

*** Why the token columns look too small

=IN= counts *new* input tokens.  Cached context is billed and is not
reported as tokens, so a turn can honestly show eight input tokens
against a bill of two cents.  The cost column is the one to trust; the
token columns describe what was new, not what was charged for.

This is stated in the CLI output, in the GTK page and in the
=clawtilla_fleet_cost= tool for the same reason: somebody reconciling
these numbers against a provider invoice should not have to guess why
they differ.

** The ledger: by model, by origin, by day
:PROPERTIES:
:CUSTOM_ID: ledger
:END:

"Which routine costs me most" had no answer while the only grouping was the agent.  ~--by~ groups the same turns another way:

#+begin_src bash
clawtilla cost --by origin              # what started the work
clawtilla cost --by model --days 30     # which model the month went on
clawtilla cost --by day --today         # one row, today
clawtilla cost --by agent --agent chief # one agent, grouped
#+end_src

#+begin_example
ORIGIN                          TURNS  UNPRICED           IN          OUT         COST
routine:morning-brief              31         0          124         9120        $1.84
operator                           18         0           72         6011        $0.92
agent:chief                         9         2           36         2210        $0.31
untagged                           40         0          160        12008        $0.27
total                              98         2          392        29349        $3.34

2 turns have no recorded price and are not in the total -- unknown, not free.
#+end_example

The groupings are =clawt_usage_group_count()= / =_nth()=, the one table every client's *Group by* selector walks:

| ~agent~  | the agent that ran the turn                                                    |
| ~model~  | the model libreclaw recorded for it, or ~(unknown)~                            |
| ~origin~ | what started the work -- below                                                 |
| ~day~    | the local date, oldest first; every other grouping is most expensive first     |

*** Origins

Every turn is tagged when clawtilla first sees it, from the turn state of the agent that ran it, in the room libreclaw recorded it in -- only that room, never the fold across rooms the other turn getters fall back to, which would hand the turn whichever room's description was written last.  The rule is =clawt_usage_origin_classify()=:

| ~routine:<id>~    | a routine's run, *or work it handed on*: a routine that delegates to three agents is one bill, found by walking the task's parents to the run |
| ~trigger:<id>~    | the same for a trigger                                                                                                                         |
| ~operator~        | you, from any client or the CLI                                                                                                                 |
| ~agent:<id>~      | another agent in the fleet                                                                                                                      |
| ~task:<id>~       | a task whose run the daemon no longer remembers -- a routine that was running across a daemon restart                                          |
| ~channel:<name>~  | the agent's own Matrix, email or other channel, which clawtilla never routed                                                                   |
| ~other:<sender>~  | a sender known by name only, such as a Grok bot                                                                                                 |
| ~untagged~        | a turn recorded before the ledger existed, or before the daemon's baseline when it started, or one no turn state described                     |

A routine wins over the agent that delivered its delegated work on purpose: the agent is still there under ~--by agent~, and "which routine" is the question origin exists to answer.  Which run created a task is held in the daemon's memory, so a run in flight across a daemon restart is charged to its ~task:<id>~ rather than its routine.

*** Unpriced turns

An *unpriced* turn is one whose recorded cost is not a price: negative (=-1= is unknown all the way through), or =0= against tokens -- which is what libreclaw writes for a turn whose provider reported no cost when it has no price table to estimate from (=clawt_usage_turn_is_priced()=).  They are counted in ~TURNS~ and in ~UNPRICED~, and added to no cost.  A group whose every turn is unpriced shows ~unpriced~ where a cost would be, not =$0.00=, and an empty cost cell in the CSV.  The same rule now keeps a negative cost out of the per-agent summary, where a =-1= used to subtract a micro-dollar.

*** CSV

~--csv~ prints the grouped table as CSV (by agent unless ~--by~ says otherwise), and every client's *Export CSV* writes the same document, from =clawt_usage_ledger_csv()=:

#+begin_example
origin,turns,unpriced_turns,input_tokens,output_tokens,cost_usd
routine:morning-brief,31,0,124,9120,1.840000
agent:chief,9,2,36,2210,0.310000
#+end_example

- Commas separate; lines end in CRLF, as RFC 4180 has it.
- Cost is exact dollars with six places, written from the integer micro-dollars rather than through a float.
- There is no total line, so a spreadsheet's own =SUM= is not doubled.
- A cell is quoted when it holds a comma, a quote, a newline or an edge space, with its quotes doubled.
- *Formulas are neutralised.*  A cell beginning with ~=~, ~+~, ~-~, ~@~, a tab or a carriage return gets a leading ~'~.  A model name, a routine id or a channel is text somebody else chose, and a spreadsheet evaluates a cell that opens like a formula -- =HYPERLINK= and =WEBSERVICE= can reach the network from a file that only looks like a report.

*** Where the tags live

=<state_dir>/agents/<id>/sessions/clawtilla-ledger.db=, table =turn_origin=, one row per =token_usage= row id: ~origin_kind~, ~origin_id~, ~sender~, ~task_id~, ~room~, ~provider~ (the agent's ~model.provider~ when it ran -- libreclaw's own ~provider~ column holds the model name) and ~model~ (what the delivery asked for, if anything).  The costs stay in libreclaw's table and are read through =lc_database_*=; only the tags are clawtilla's, joined on the row id when the ledger is read.

Beside libreclaw's database, inside ~sessions/~, on purpose: =/reset= moves that directory aside and the new database numbers its rows from 1 again, so tags keyed on the old ids go with the rows they describe.  The table is created on the first tag and later columns are added one =ALTER TABLE= at a time, so an older file is brought up to date rather than refused.

Tags are written by the same drain that charges a task's budget, once per new row, after the baseline set when the agent's watermark is primed.  A tag that cannot be written is a warning and the turn reads as untagged; it never stops the budget being charged.

** Windows

#+begin_src bash
clawtilla cost --today          # since local midnight
clawtilla cost --days 7         # the last week
clawtilla cost --agent chief    # one agent, with the fleet total for scale
#+end_src

The fleet line is printed even when a single agent was asked for, because
"is this agent most of the bill" is usually why somebody narrowed the
report.

A *nonzero* cost below a cent keeps four decimal places rather than
rounding to =$0.00=.  Per-turn costs here are routinely a fraction of a
cent, and a column of zeroes reads as *nothing is being recorded* --
which is the one thing this report exists to disprove.  An exact zero
still renders =$0.00=, deliberately: there is nothing to reveal in four
places, and =$0.0000= would read as a rounding artefact rather than as an
answer.

** In the clients

All three graphical clients have a *Spending* page under Settings: a period selector, a *Group by* selector (Agent, Model, Origin, Day), one row per group with its cost, turns and unpriced turns, a fleet total, a sentence when any turn in the period has no price, and *Export CSV* -- a save dialog in GTK and libregnum, a download in the web client.  See [[#ledger][the ledger]].

All three graphical clients have a *Fleet* page under Work, which adds what Spending does not: agents ranked by cost with their share, the last fourteen days, how long since each agent's last turn, and Stop for the ones sitting idle. See [[file:clients.org::#fleet-tab][the Fleet tab]].

An agent can ask too.  =clawtilla_fleet_cost= reports the same per-agent
breakdown plus what one delegated task is allowed to spend.  A
chief-of-staff handing out ten subtasks is committing real money, and
until it could see the figure, "delegate this to five agents" and
"delegate this to fifty" felt identical from where it sat.

It is *all-time only*: it takes no window and passes =since = 0=, unlike
the CLI and the GTK page.  So an agent's figure and yours will not match
unless you asked for everything.

** The task budget

=orchestration.task_budget_usd= caps what one delegated task -- and
everything it spawns -- may spend.  It defaults to =$5.00=; =0= disables
it.

When a task reaches its cap -- the test is spend *>=* budget, so it fires
*at* the figure and not past it -- further messages belonging to it are
refused with =CLAWT_ERROR_LOOP_LIMIT=, and the refusal names both the
spend and the cap:

#+begin_example
this task has spent $5.40, which is its budget of $5.00. Stop and report
what you have.
#+end_example

The second sentence is the load-bearing half.  A refusal that only says
no gets retried in a different shape; this one names the thing to do
instead.

The spend is charged when the agent answers.  Each reply drains what that
agent has spent since its previous turn and books it against the task the
reply is about.

*** Charged to the task, not to the agent

A chief-of-staff delegating ten subtasks is bounded as one piece of work
rather than ten.  That is the useful shape: the runaway case is a task
that keeps going, not an agent that is busy.

*** The first turn after a restart charges nothing

A daemon restarted mid-task must not bill that task for every turn the
agent has ever taken.  The first drain on an agent sets a watermark and
charges nothing; an agent with any history at all would otherwise
exhaust its budget on its first reply, over work that finished days ago.

*** Turns are charged exactly once

Rows are filtered by =recorded_at=, which has one-second resolution, so
two turns in the same second are indistinguishable by time.  The row id
settles which have already been charged.  Without it the earlier turn
would be counted again on every drain and a task's budget would drain
itself.

** Where the data lives

=<state_dir>/agents/<id>/sessions/libreclaw.db=, in the =token_usage=
table -- and beside it =clawtilla-ledger.db=, which holds each turn's
origin ([[#ledger][the ledger]]).

Note the =sessions/= component.  Those are libreclaw's settings rather
than clawtilla's: its SQLite backend builds that filename from
~session.persist_dir~ and *never reads* ~database.path~, so the database
is inside the sessions directory rather than beside it.  clawtilla
renders ~database.path~ to the same place so that the line in each
agent's config does not name a file that does not exist.

Everything that needs the path goes through
=clawt_usage_database_path()=.  It is one function because it was once
two spellings: =/reset= tested for =<state_dir>/libreclaw.db=, a file
that has never existed on any machine, so its session-clearing branch was
skipped every time and always reported nothing cleared.  Reset appeared
to work only because moving the sessions directory aside takes the
database with it.

** Reading it yourself

The table belongs to libreclaw, and clawtilla reads it through
libreclaw's own API rather than by opening its schema -- so there is no
copy of that column list here to fall out of step.  If you want to query
it by hand:

Single quotes around ~unixepoch~, double quotes around the whole query:
in SQLite a double-quoted word is an *identifier*, so the obvious spelling
fails with "no such column".

#+begin_src bash
sqlite3 ~/.clawtilla/agents/chief/sessions/libreclaw.db "
  SELECT date(recorded_at, 'unixepoch') AS day,
         count(*) AS turns,
         sum(cost_usd_micros) / 1000000.0 AS usd
  FROM token_usage GROUP BY day ORDER BY day DESC;"
#+end_src

Cost is stored as an integer count of micro-dollars so that =SUM()= is
exact and identical on SQLite and PostgreSQL.  clawtilla carries it the
same way for the same reason: a fleet total built from floats disagrees
with itself depending on the order the agents happened to be visited in.

** An agent that has never run

It has spent nothing, and that is reported as a total rather than as a
failure.  Nothing is created on disk to answer the question either --
opening a SQLite database brings it into existence, and asking what a
stopped agent cost should not leave one behind.

** Troubleshooting

*** Every agent reports zero

Check that the databases exist:

#+begin_src bash
ls ~/.clawtilla/agents/*/sessions/libreclaw.db
#+end_src

An agent that has never completed a turn has no rows.  A turn that
reported no tokens at all is deliberately not recorded -- that is a
tool-only turn, and a zero row would inflate the turn count with no data
behind it.

There is a third cause, and it is quiet: a database that exists and
cannot be *read* -- mid-write, or locked -- is skipped for that agent and
counted as zero, so one bad file does not refuse a report about the other
nine.  It is logged at =g_debug= level only, so run the daemon with
=G_MESSAGES_DEBUG=Clawtilla= if an agent you know has turns reports none.

*** The numbers reset after =/reset=

They do.  =/reset= moves the sessions directory aside, and the history
goes with it.  The old directory is kept as
=sessions.reset-<timestamp>=, so the rows are still there to be read by
hand if you want them.

It also drops the in-memory watermark for that agent, and that half is
not optional.  The replacement database numbers its rows from 1 again, so
a watermark left over from the old one would suppress every row in the
new one for ever -- an agent that reset once and then appeared to cost
nothing, permanently, with a growing =token_usage= table on disk saying
otherwise.

*** The budget never fires

Check it is not zero:

#+begin_src bash
clawtilla config show | grep task_budget_usd
#+end_src

=config show= prints the file as written rather than the effective
configuration, so *no output means the key was never set* and the default
of =$5.00= applies -- which is a working budget, not a disabled one.  A
line reading =task_budget_usd: 0= is the case that disables it.

Then check the work is actually a *task*.  Spend is booked against a task
id, and an ordinary chat has none -- so ordinary conversation is
outside the task budget. The optional daily admission limits below also cover ordinary routed conversation.

* Daily fleet and agent admission limits
:PROPERTIES:
:CUSTOM_ID: daily-limits
:END:

Set =orchestration.daily_fleet_budget_micros= to cap the configured fleet's recorded daily spend, and =orchestration.daily_agent_budget_micros= for the default per-agent cap. Both are nonnegative integer millionths of a US dollar: =1000000= is $1, and =0= disables that cap. An agent's =daily_agent_budget_micros= overrides the default, including =0= to disable its individual cap. The fleet cap still applies.

#+begin_src yaml
orchestration:
  daily_fleet_budget_micros: 20000000
  daily_agent_budget_micros: 5000000
agents:
  - id: researcher
    daily_agent_budget_micros: 8000000
#+end_src

The library mailbox router checks every actual recipient before queueing a message, and checks again before leasing each pending delivery. Chat, delegation, routines, triggers and peer messages using the router share this check. A refused send returns an error without enqueueing any recipient. Previously queued messages remain pending while spending is at or above either cap; the next drain after the cap is raised or the day changes can deliver them. Transcript-only notes require no AI turn and remain available.

Accounting uses persisted libreclaw usage since midnight in the daemon's local timezone, recalculating the calendar boundary for daylight-saving changes. Restarting the daemon does not reset spend. =sessions.reset-*= archives count too, so resetting a conversation does not restore today's allowance. Missing databases mean no recorded usage; unreadable existing databases refuse admission. Fleet totals include agents currently in the configuration; removing an agent or deleting its databases removes that accounting history. Keep usage history for the whole day when relying on these limits.

These are admission limits, not provider-side hard billing ceilings. Admissions run on the router's owning main context; several requests can be delivered while recorded spend is still below the cap. No speculative amount is reserved for queued or in-flight requests, and an already running request can exceed either limit before its usage is recorded. Internal model/tool iterations and provider calls outside mailbox routing are not interrupted by this mechanism. Task budgets remain an additional independent guard.

On the first blocked check per scope and local day, the existing event bus publishes =spending.limit-reached= with subject =fleet= or =agent:<id>= and integer =cost_micros= and =limit_micros= details. Repeated checks do not flood the event stream. Alert deduplication lasts for the router lifetime, so a daemon restart can announce an already exhausted cap again. Alerts are evaluated when new work is attempted or pending work drains; there is no billing poll when no work is waiting. Inspect the existing event stream with =clawtilla event list=.

Since 0.8.0 that event is a *notice* in every client's alerts drawer, and it reaches a notify integration whose =events= include ~budget~ -- the subject says which cap, and the message says that new work waits until midnight or a raised cap. A fleet that has quietly stopped answering because of money reads as a broken fleet to anybody who was not told. The Fleet page draws the fleet cap beside the day's spend.

* Idle agents

An agent that has not taken a turn for days still holds its process, its ports and its computer. =orchestration.idle_hours= says what the clients call idle (a label only), and =agents.runtime.idle_stop_hours= -- 0, off, by default -- has the daemon stop a running agent with no turn for that long, checked once a minute. It is woken by the next message queued for it, and the message waits in its mailbox, which is durable, while the agent comes up; so a sleeping agent loses no conversation. The clock runs from the later of its last recorded turn and its last start, so an agent started an hour ago is not put straight back to sleep for a turn it took last week, and an agent typing anywhere is never stopped. Each stop publishes ~agent.idle_stopped~.
