* Browser sessions

=clawtilla_web_fetch= reads what a server sends.  For a page built by JavaScript that is a script tag and an empty =<div>=, and for anything behind a login it is the login page.  A browser session is a real browser: gsurf (WebKitGTK) on a private X display, which runs the page's scripts, keeps cookies, and takes clicks and typing.  An agent drives it with the =clawtilla_browser_*= tools; a person watches and drives it from the Computer page's Browser view, or with =clawtilla browser=.

Since 0.9.0.

** Building it in

Browser sessions are opt-in at build time, like the libregnum client:

#+begin_src bash
make GSURF=1                      # gsurf from ../gsurf
make GSURF=1 GSURF_DIR=~/src/gsurf
#+end_src

gsurf is *not* a dependency and clawtilla links nothing from it.  The daemon must never link GTK, so a session is two child processes -- Xvfb and gsurf -- and a Unix socket.  =GSURF=1= does three things:

- defines =CLAWT_HAVE_GSURF=, which is what lets an agent have a browser at all;
- records =GSURF_DIR='s build as a place to find the binary;
- runs =tools/clawt-gsurf-check.sh=, which refuses a gsurf older than 0.5.13 (0.5.10 added ~page.click~, ~page.type~, ~page.key~ and the inline screenshot the tools are made of; 0.5.13 added ~page.fill_secret~ and the secret hold the vault fills through) and builds =GSURF_DIR= when its binary is missing.  A gsurf that is already built is never rebuilt: it is somebody's browser, built with their options.

| Needs | Fedora package | For |
|-------+----------------+-----|
| gsurf's build | =webkit2gtk4.1-devel=, =gtk3-devel= | building =GSURF_DIR= |
| =Xvfb= | =xorg-x11-server-Xvfb= | the private display (runtime) |

An agent configured with a browser in a build without =GSURF=1= is disabled, with the reason, rather than run without the tools it was told it has.

*** Which gsurf runs

Beside =clawtillad=, the install location, the =GSURF_DIR= build, then =PATH= -- and each candidate's =--version= is read, so one older than 0.5.13 is passed over.  The build comes before =PATH= on purpose: the first live run found a distribution gsurf 0.4.4 on =PATH= ahead of the 0.5.10 build, and an old gsurf has no ~control.name~, so it starts, opens its window, and the socket clawtilla waits for never appears under the name it asked for.  None found names every place looked at and why each was not used.

** Configuring it

Three ways an agent can be set up, by =agents.browser.mode=:

| Mode | What the agent gets |
|------+---------------------|
| =none= (default) | no browser; =clawtilla_web_fetch= as before |
| =own= | a session of its own, with its own profile |
| =shared= | the session declared under =browsers:= that =agents.browser.use= names |

#+begin_src yaml
browsers:
  - id: accounts
    description: logged in to the vendor portals
    home: https://portal.example.com
agents:
  - id: researcher
    browser:
      mode: own
      idle_minutes: 30
  - id: billing
    browser:
      mode: shared
      use: accounts
  - id: support
    browser:
      mode: shared
      use: accounts
#+end_src

A shared session's keys -- =home=, =allow_scripts=, =idle_minutes=, =width=, =height= -- come from its =browsers:= entry, read through the same getters as an agent's own, exactly as =computers:= work.  =mode= and =use= stay the agent's.  Every key is in [[file:configuration-options.org][configuration-options.org]].

** What a session is

- *Started on first use.*  The agent's first browser call, or a person opening a page from the Browser view or the CLI, starts it.  Watching does not: a frame of a session that is not running answers "not running".
- *A private display.*  Xvfb picks its own display with =-displayfd=, so two sessions never race for =:99=.  TCP is off; the abstract socket is left on, because a daemon with a private =/tmp= (a systemd unit's =PrivateTmp=, a sandbox) cannot share =/tmp/.X11-unix= with the browser it starts -- measured: gsurf then never opens its window.
- *A private profile.*  =<state_dir>/browsers/agent.<id>/= or =shared.<id>/= holds its data, cache, cookies, downloads, generated ~gsurf.yaml~ and the two logs.  An agent and a shared session with the same id never share one.  The profile survives a stop, so a login does; the open page does not.
- *No modules.*  gsurf runs with =--no-modules=: its modal module would take an agent's typed =j= as "scroll down".
- *Its environment is the allowlist*, plus =DISPLAY=, =GDK_BACKEND=x11=, the profile's =XDG_*= directories and a =WAYLAND_DISPLAY= naming a socket that does not exist -- GTK finds =wayland-0= on its own, and a "headless" browser would open on your screen.  Building this exposed a bug in =clawt_build_child_environment()=: a name in both the allowlist and the extras was written twice and =getenv()= returned the allowlisted copy, so an agent's own =env:= could not override =XDG_CONFIG_HOME= either.  Extras now replace.
- *It dies with the daemon* (=PR_SET_PDEATHSIG=), stops after =idle_minutes= without a call (checked on the daemon's one-minute tick), stops when its agent stops if it is the agent's own, and stops with the daemon.
- *One driver at a time on a shared session.*  Two agents clicking in one page undo each other's work and neither can tell, so a call from a second agent is refused, naming the first.  The claim is renewed by every call and lapses after two minutes without one (=CLAWT_BROWSER_DRIVER_LEASE_SECONDS=); =clawtilla_browser_release= gives it up sooner.  A person's click from the Computer page does not take the lease.

** The tools

Offered only to an agent whose =agents.browser.mode= is not =none=, in a daemon that holds sessions.  Every one runs on a worker thread through the deferred tool path: a page can take seconds and a start longer, and nothing that waits may hold the daemon's main context.

| Tool | What it does |
|------+--------------|
| =clawtilla_browser_open= | navigate (=https://= assumed), wait for the load, say where it ended up |
| =clawtilla_browser_read= | the page's text after its scripts ran, and its links |
| =clawtilla_browser_html= | the HTML, of the document or of a selector |
| =clawtilla_browser_click= | a click, by selector (preferred) or at x, y from a screenshot |
| =clawtilla_browser_type= | typing, key by key, into a selector or the focus; optionally Enter |
| =clawtilla_browser_key= | one key, with modifiers |
| =clawtilla_browser_scroll= | by screens; says how far down the page the view is |
| =clawtilla_browser_screenshot= | a picture, as an MCP image |
| =clawtilla_browser_back= | back one page |
| =clawtilla_browser_release= | give up a shared session's wheel |
| =clawtilla_browser_eval= | the agent's own JavaScript -- only with =agents.browser.allow_scripts= |
| =clawtilla_secret_ref= | a one-use reference to a =vault:= entry it was granted, or the list of them -- only with =agents.browser.secrets= (since 0.24.0) |
| =clawtilla_browser_fill_secret= | a granted secret typed into a field by reference; the agent hears only that it was filled (since 0.24.0) |

*A reply means handed over, not done.*  gsurf answers ~page.click~ when the events reach the engine, not when the page has handled them, so every tool that can navigate -- open, click, type with submit, key, back -- waits for ~document.readyState~ to be =complete= and then reports the page it is on.  That last line is what makes a click that navigated visible to the agent without another call.

Click, type, key and fill_secret are =desktop-input= actions to the action rules, secret_ref is =read=, open and back are =external=, and eval is =exec=, so a policy can gate the browser the way it gates a screen.

=clawtilla_browser_eval= is off by default: reading, clicking and typing cover what a person does, and a script can read every field and post anything as the logged-in user without a visible step.  It is refused at the call as well as left out of the listing.

** Secrets the agent never sees

Since 0.24.0.  A login form is where an agent most needs a browser and where it should least hold what it types.  A secret is never handed to the agent: the agent names it, and the daemon has gsurf type it.

#+begin_src yaml
secrets:
  dir: ~/.clawtilla/secrets
vault:
  - name: github
    description: the release bot's login
    secret: {command: "pass show web/github"}
    sites: [github.com]
  - name: github-2fa
    kind: totp
    secret: {file: github-totp}       # a base32 seed or an otpauth://totp/ URI
    sites: [github.com]
agents:
  - id: releaser
    browser:
      mode: own
      secrets: [github, github-2fa]
#+end_src

*** The flow

1. =clawtilla_secret_ref= with ~name~ answers a reference -- ~secret-ref:~ and 32 hex digits from =/dev/urandom= -- and nothing else.  Without a name it lists the entries the agent may ask for, by name, kind and sites.  Nothing is resolved yet.
2. =clawtilla_browser_fill_secret= with that reference as ~secret~, a ~selector~ and optionally ~submit~ spends the reference, checks the grant and the entry again, checks that the page's host is one of the entry's ~sites~, resolves the value through the ordinary secret reference (=secrets.dir=, =secrets.command_timeout_seconds=), turns a TOTP seed into the RFC 6238 code for this second, and sends gsurf ~page.fill_secret~.
3. gsurf focuses the field, selects what is in it and types the secret as key input -- GDK key events on GTK3, ~execCommand('insertText')~ where there is no native input -- never a JavaScript value assignment.  It answers ~{done, secret_hold}~ and nothing else.
4. The agent hears "Filled github into #password. Now on ...".  The event bus gets ~browser.secret_filled~ with the name, kind, host and session.

*** The reference

- *One use.*  The first redemption spends it, whatever the fill then does: a reference that reached a transcript is already worthless.
- *Bound to the agent and the conversation.*  Minted for the room the agent's turn is in (the same ~turn_room~ resolution the other tools use; no room is its own conversation), redeemed only from there and only by that agent.  A redemption from anywhere else is refused *and spends it*, since the attempt is the one sign it travelled.
- *Ten minutes* (=CLAWT_SECRET_REF_TTL_SECONDS=), forgotten when the agent stops, and lost with the daemon.  At most 256 are outstanding.
- =ClawtSecretVault= (=src/browser/clawt-secret-vault.c=) maps references to entry *names*: a dump of it holds no value.

*** Sites

An entry is typed only on a page whose host is one of its ~sites~ or a subdomain of one (~login.example.com~ under ~example.com~; never ~evilexample.com~).  An agent steered by a page it read to a look-alike login cannot be made to fill it there.  A page whose address cannot be read is refused, not assumed.  An entry with no ~sites~ is ignored with a warning, as is one with no secret or a ~kind~ that is neither ~password~ nor ~totp~ -- a seed typed into a password box would be the seed itself.

*** The hold

From the moment a fill is sent -- before the first key, so a fill that fails half-way counts -- the session refuses screenshots and scripts: =clawtilla_browser_screenshot=, =clawtilla_browser_eval=, and =clawtilla_browser_html= and =clawtilla_browser_scroll=, which are scripts underneath.  =clawtilla_browser_read= still works: a page's text carries no field values.  The Browser view gets no picture and says why.

Two walls, one per process.  gsurf keeps its own hold on the view and refuses ~page.eval~ and ~page.screenshot~ with -32003 whoever asks; clawtilla keeps one on the session and lifts it only when gsurf's ~page.secret_hold~ answers that its hold is gone, which happens when a main-frame navigation commits a new document.  A ~page.secret_hold~ that errors, times out or answers anything else keeps the hold on: fail closed.  Stopping the session clears it, since the page is gone.

*** What it cannot do

- A page can still read its own field and send it anywhere; this keeps the value from the *agent*, not from the site.
- gsurf's hold is per document.  Going back to the page may restore it from the page cache with the field filled, and the hold does not come back.
- The value is wiped from clawtilla's copies (the resolved string, the JSON-RPC line) and from gsurf's, but a command backend's pipe and the allocator's past are not under our control.
- Nothing here stops the agent reading a password the page itself prints.

** Watching and driving it yourself

The Computer page has a Browser view in every client ([[file:clients.org][clients.org]]): the vault entries the agent may have filled, one switch each (~vault.list~, saved through ~agent.set~ ~browser.secrets~), the line saying what it is on and when a secret was last filled, a picture refreshed every three seconds while the view is open, an address to open, Stop, and a click on the picture as a click in the page.  An agent with a browser and no computer gets the Browser view on its own.

#+begin_src bash
clawtilla browser                              # every session, running or not
clawtilla browser open researcher example.org
clawtilla browser click researcher 40 20      # the page's CSS pixels
clawtilla browser screenshot researcher page.png
clawtilla browser stop researcher
clawtilla browser secrets researcher          # the vault entries it may fill, [x] granted
clawtilla agent set researcher browser.secrets github,github-2fa
#+end_src

The IPC verbs are in [[file:ipc-protocol.org][ipc-protocol.org]].

** Testing it

=tests/test-browser.c= covers everything above gsurf's control socket with a fake transport (=clawt_browser_manager_set_transport()=): the session keys, the keys a shared session takes from its entry, the shadow reasons, the lease, which agents are offered which tools, and what each tool sends.  It cannot see a real X server or a real page.  Its =/browser/tools/secrets-never-seen= case walks the whole secret path against a fake gsurf that keeps a hold the way 0.5.13 does: the fill sends the value and the agent hears "Filled", the reference works once and only in its conversation, a page on another host is refused, a TOTP fill types the code for now, screenshots and HTML are refused until a navigation, a hold gsurf cannot be asked about stays on -- and the value, the seed and the code are in none of the tool results, the events or the log.  =tests/test-secret-vault.c= has the references on their own, RFC 6238's vectors for SHA1, SHA256 and SHA512, the seed formats, and which vault entries are offered.  gsurf's own =test-control-webkit= types into a real login form.

=tests/test-browser-integration.sh= can, behind =CLAWT_TEST_INTEGRATION=1=: against a =GSURF=1= build it starts a daemon, opens a fixture page whose title only its script sets, takes a screenshot and checks it is a PNG, clicks the button and waits for the page to retitle itself, and stops the session.  It skips, saying why, when Xvfb or a =GSURF=1= daemon is missing.

** Not done

- A person typing into the page from the Browser view.  Clicks are there; text goes through the agent or gsurf's own window.
- =clawtilla_web_fetch= falling back to the browser when it reads an empty page.  The agent is told when to reach for the browser instead, in the tools' descriptions.
